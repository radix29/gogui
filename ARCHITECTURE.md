# gogui architecture

The architecture **as implemented today**: packages, contracts and invariants. The target
design, scope and roadmap are in [`PLAN.md`](PLAN.md). Where this file and the code
disagree, the code wins and this file is fixed in the same change.

## 0. Target architecture overview

Copied from PLAN.md §2 and §2.1. This is the **target** design; section 1 onwards shows
what exists. When the implementation changes the overview (a package is renamed, a layer
is added or dropped, a responsibility moves), change this section and PLAN.md §2 together.

| Layer | Package | Responsibility |
|---|---|---|
| Public API | `gogui` | Widgets, windows, menus, layout, events, colors, fonts. The only package apps import. |
| Driver interfaces | `internal/driver` | "Peer" interfaces (`driver.Button`, `driver.Window` …), one peer per public widget, the same pattern AWT/SWT use. |
| macOS driver | `internal/appkit` | Implements the peers with AppKit objects, called through the Objective-C runtime with `purego/objc` (no `.m` files, no cgo). |
| Native bindings | `internal/ffi` | Shared purego helpers: library loading, a fixed set of callback trampolines, struct/ABI helpers, `objc` class registration (PLAN.md §6.1, §7.2). |
| Aqua driver | `internal/aqua` | Implements the peers as **drawn widgets** that replicate AppKit visuals and behaviour. Shared by Windows and Linux. |
| Theme | `internal/aqua/theme` | Design tokens: colors (light/dark/high-contrast), metrics per control size, fonts, radii, shadows, animation curves. |
| Render | `internal/render` | GPU-backed 2D `Canvas` interface plus a recording backend for tests. |
| Shell | `internal/shell` | OS integration interface for the aqua driver: native windows/popups, event loop, input, IME, text shaping, clipboard, dialogs, system settings, frame clock. |
| Shell: Windows | `internal/shell/win32` | Win32 + DWM + Direct2D + DirectWrite + DirectComposition via `golang.org/x/sys/windows` and hand-written COM vtables (`purego` only for COM calls with float arguments). **No cgo.** |
| Shell: Linux | `internal/shell/gtk4` | GTK 4, GLib and Pango loaded at runtime with `purego.Dlopen` (no cgo, no C shim). Drawing goes through `GtkSnapshot` → GSK render nodes (GPU). Portal settings use pure-Go D-Bus (`godbus/dbus/v5`). |
| Layout | `internal/layout` | Stack / form layout (a grid comes after v0.1) used by **all** drivers, so layouts behave the same on every OS. |

## 1. Layers

```
  examples/*                  app code, imports only gogui
      │
  gogui                       public API, widget tree, layout calls
      │
  internal/driver             peer + handler interfaces, shared types (imports nothing)
      │
      ├── driver/stub         no-op peers, fake metrics, User… sims
      ├── driver/headless     display-less driver on stubs (stub + mainthread)
      ├── appkit              macOS native peers (purego/objc), not yet
      └── aqua                drawn peers for Windows/Linux: tree, paint, hit testing, input routing, focus, windows with title bar, placeholders
          ├── aqua/a11y       accessibility node type
          ├── aqua/anim       animation: bezier curves, closed-form springs, Lerp; Value and Timeline on the frame clock
          ├── aqua/gallery    the gallery scene of the golden-image tests, built on driver.Driver alone
          ├── aqua/gallery/golden  golden PNGs and the perceptual image comparison (pixelmatch-style YIQ)
          ├── aqua/gallery/goldentest  the shared golden-test flow: variants, BGRA readback → NRGBA, compare and report (tests only)
          ├── aqua/scroll     scroll physics: rubber band, momentum decay, release velocity; Axis, one axis's offset on the frame clock
          └── aqua/theme      design tokens (generated from spec/*.json by aqua/theme/gen)

  used by aqua and the shells:
  internal/render             Canvas, text interfaces, value types
      └── render/record       recording Canvas for tests
  internal/shell              Shell, Surface, events, frame clock (interfaces)
      ├── shell/fake          test shell: queue, surfaces, text, clock
      ├── shell/native        per-OS shell selection
      ├── shell/shellkit      OS-independent shell logic: click counts, event times, scroll gestures, points ↔ pixels, regions
      ├── shell/win32         Windows shell (+ w32, com, dxgi, d3d11, dcomp, d2d, dwrite)
      ├── shell/gtk4          Linux shell: the trampolines, the dispatch table, the GGSurface class, the Shell, the frame clock and the surfaces
      └── shell/gtk4/gtk      raw GTK 4 / GObject / GLib / Graphene / Pango bindings
  assets/fonts                embedded font files (Inter, added by hand; used by shell/win32 and shell/gtk4)

  shared infrastructure:
  internal/layout             stack / form layout engine (used by gogui)
  internal/mainthread         UI-thread queue (Do / DoSync / Drain)
  internal/ffi                handle table, callback registry, layout helpers, raw memory (used by shell/win32, shell/gtk4 and shell/gtk4/gtk; appkit later)
```

Dependency rules:

* `gogui` talks to backends **only** through the `internal/driver` interfaces. Apps never
  import `internal/...`.
* `driver` depends on nothing in the module. `stub` depends only on `driver`. `headless`
  depends on `driver`, `stub` and `mainthread`.
* `gogui` depends on `driver`, `driver/stub` (the failed driver), `headless` (selected on
  darwin until the appkit driver exists; the tests use it too), `aqua` and `shell/native`
  (selected elsewhere) and `mainthread`.
* `mainthread` and `ffi` depend on nothing in the module. `layout` depends only on
  `driver` (geometry types); it never calls a peer factory. `render` depends on `driver`
  (geometry, color, font); `render/record` on `render` and `driver`; `shell` on `driver` and
  `render`; `shell/fake` on `shell`, `render`, `render/record`, `mainthread`, `driver` and
  `driver/stub`; `aqua` on `driver`, `driver/stub`, `layout`, `mainthread`, `render`,
  `shell`, `aqua/a11y`, `aqua/anim`, `aqua/scroll` and `aqua/theme`; `aqua/a11y` on `driver`; `aqua/anim` on `aqua/theme` and `driver`; `aqua/scroll` on `aqua/anim`, `aqua/theme` and `shell`; `aqua/gallery` only on `driver` (its tests use `aqua`, `aqua/a11y` and `shell/fake`); `aqua/gallery/golden` only on the standard library; `aqua/gallery/goldentest` (imported only by tests) only on `aqua/gallery/golden` and the standard library; `aqua/theme` only on `driver` (imported
  by `aqua` and by `shell/win32` for the clear color, a leaf package so the layering holds), its generator `aqua/theme/gen` and the `gen/gentokens`
  command only on the standard library; `shell/native` on `shell` and, on Windows, `shell/win32`, on Linux `shell/gtk4`; `shell/shellkit` only on `shell` and `driver` (no build tags; imported by `shell/win32` and `shell/gtk4`); `shell/gtk4/gtk` only on `ffi` (imported by `shell/gtk4`); `shell/gtk4` on `ffi`, `shell/gtk4/gtk`, `shell`, `shell/shellkit`, `shell/fake` (the text system's fixed-width fallback without Pango), `assets/fonts` (the app font, S4.2j), `render/record` (the canvas's debug recorder), `driver`, `render` and `mainthread` (imported by `shell/native` on Linux; `gogui`'s driver test names its type); `assets/fonts` on nothing, imported only by `shell/win32` and (since S4.2j) `shell/gtk4`; `shell/win32` also imports `aqua/theme` (a leaf on `driver` only) for its clear color, never `aqua` itself.
  Drivers use these packages; they never import a driver.
* **Build tags** appear only in the driver-selection files of `gogui` (`driver_darwin.go`
  `//go:build darwin`, `driver_other.go` `//go:build !darwin`), in `internal/ffi`'s per-OS
  files (`callback_windows.go`, `callback_unix.go`, `dl_unix.go`, `cstring_unix.go`,
  `libc_darwin.go`, `libc_linux.go`), in the Windows packages (`//go:build windows`), in
  `shell/gtk4/gtk`'s `load_linux.go` and its test and `shell/gtk4`'s `*_linux.go` files (`//go:build linux`) and in
  `spike/`. Everything builds and tests with `CGO_ENABLED=0`.
* **External dependencies:** `github.com/ebitengine/purego` v0.11.1, imported by
  `internal/ffi`'s darwin/linux files, `spike/appkit` and `internal/shell/win32/com`
  (COM calls with float arguments); `golang.org/x/sys` v0.49.0, imported by the Windows
  packages `w32`, `com`, `dxgi`, `d3d11`, `dcomp`, `d2d`, `dwrite` and `win32` (and by
  godbus); `github.com/godbus/dbus/v5` v5.2.4 (S4.3b, pure Go), imported only by
  `internal/shell/gtk4` (the settings portal client), so it is linked only into Linux builds.

### Tooling

* **`scripts/check.sh`** runs the per-step checks of PLAN.md §11.1 and stops at the first
  failure: `gofmt -l .`; `go vet` and `go build` for the six GOOS/GOARCH targets;
  staticcheck (pinned in the script, `honnef.co/go/tools/cmd/staticcheck@v0.8.2`, not in
  `go.mod`, built once for the host and run per GOOS); `go test -count=1 ./...`; the
  no-cgo guard (`go list` `CgoFiles` is always empty under `CGO_ENABLED=0`, so it also
  greps every `.go` file for `import "C"` and fails on any C/C++/ObjC/assembler/SWIG
  source); the hidden-callback guard (outside `internal/ffi` and `_test.go` files, no call
  to `syscall.NewCallback`, `NewCallbackCDecl`, `windows.NewCallback`,
  `purego.NewCallback`, `objc.NewIMP`, `objc.NewBlock` or `objc.RegisterClass`); and the
  stress run (`-count=20 -cpu=1,2,4,8` on `.`, `internal/mainthread`, `internal/ffi`,
  `internal/driver/headless`, `internal/shell/fake`, `internal/aqua`,
  `internal/shell/win32`; skips `TestCallbackBudget`). `-quick` skips the stress run. It
  exports `CGO_ENABLED=0`, clears `GOOS`/`GOARCH` and uses only bash built-ins, `grep`,
  `go` and `gofmt`.
* **`scripts/native.sh`** runs on the target OS what needs it, with `CGO_ENABLED=0`:
  `go vet`, `go test -count=1 ./...`, `go build ./examples/...`, the verbose callback
  measurements of `internal/ffi`. On darwin it adds `go run ./spike/appkit -selftest`. On
  linux (since S4.1l) it runs `go test -count=1 -v ./internal/shell/gtk4/...` and
  every example (`hello`, `controls`, `form`, `notes`, `converter`; only `hello` until
  S4.2k) for 5 s each (`examples_on`/`example_for`: built once, `GOGUI_DEBUG=1`, passing
  only if `timeout` still had to stop it) under xvfb (`GDK_BACKEND=x11`) and under headless weston
  (`weston_run`: a private socket and `XDG_RUNTIME_DIR`, `GDK_BACKEND=wayland`, weston's
  log after the run), the gtk4 tests there inside `dbus-run-session` when it is installed
  (since S4.3d: a private session bus for the portal tests; logged either way), and again on the desktop session when `WAYLAND_DISPLAY` or
  `DISPLAY` is set. On windows (since S3.6d) the gallery goldens run verbosely (`TestGalleryGolden`, the reports in the log; on a failure the images go to `native-logs/golden/`). Every step runs even after a failure; output
  goes to `native-logs/<goos>-<goarch>.log` (not committed). Bash 3.2 compatible.
* **`.gitattributes`** forces LF; a CRLF checkout breaks bash and `gofmt -l`.
* **No CI.** There is no `.github` directory (PLAN.md §8.4).
* **`README.md`** is a short stub pointing to this file, PLAN.md and the examples.

### Spikes

Throw-away, never imported, `//go:build` on every file; results and open runs are in
[`docs/spikes.md`](docs/spikes.md).

* **`spike/appkit`** (`darwin`; deleted when the appkit driver lands). AppKit through
  `purego/objc`. It builds ObjC classes itself with `objc_allocateClassPair` and
  `class_addIvar` bound through `ffi.Dlopen`/`Bind` (`objc.RegisterClass` would create a
  hidden callback per method). Each class has a `goHandle` ivar holding an `ffi.Handle`,

### 1.1 `gogui`: the public package

The whole v0.1 API the five examples use; the conventions are in PLAN.md §4.2.

* **`init`** calls `runtime.LockOSThread()`, so `main` and `Run` stay on the main OS thread.
* **`Run(cfg AppConfig, ready func(*App)) error`** may be called once per process (an atomic flag; a second or nested call returns an error without creating a driver). It creates the driver through the `newDriver` hook in `driver.go`, which calls `newPlatformDriver` from `driver_darwin.go` (headless until the appkit driver exists) or `driver_other.go` (`aqua.New(sh)` over `native.New()`; when that fails, as on Linux, `failedDriver("aqua", err)`: a `driver/stub` driver whose `Run` returns the error without calling the handler and whose `Queue` is nil). The driver must implement the unexported `uiDriver` (`driver.Driver` plus `Queue() *mainthread.Queue`). `Run` stores the `App` in an atomic pointer, runs the driver, then destroys leftover widgets and clears the current app. `AppConfig` aliases `driver.AppConfig`.
* **`App`** implements `driver.AppHandler` through the unexported `appHandler`: `Ready` sets the queue's UI-thread checks from `debugChecks` (`GOGUI_DEBUG=1`; tests turn them on), records the effective appearance and calls the ready callback (nil allowed); `QuitRequested` asks the `OnQuitRequested` handlers; `MenuItemSelected` runs the menu action; `AppearanceChanged` fires `OnAppearanceChange`. `App.Quit` forwards to the driver.
* **`Do` / `DoSync`** forward to the current app's queue (mainthread semantics). Without a current app `Do` drops fn and `DoSync` returns false, also on the goroutine that ran `Run`.
* **`checkUI(what)`** is the UI-thread check every public method calls (widgets use `widget.check`, which builds the "Kind.Method" name only on failure). It panics off the UI thread when checks are on and does nothing outside `Run`.
* **Value types are aliases** of the `internal/driver` types, so no conversion happens at the peer boundary: `Point`, `Size`, `Rect`, `Insets`, `Color`, `Font`, `FontWeight`, `Modifiers`, `Key`, `KeyShortcut` (= `driver.Shortcut`), `ControlSize`, `TextAlignment`, `WindowStyle`, `CheckState`, `AlertStyle`. Public constants and variables: `Titled` … `Resizable`, `StateOff/On/Mixed`, `AlertInformational/Warning/Critical`, `ControlSize…`, `Align…`, `FontWeight…`, the modifiers `KeyPrimary`, `KeyShift`, `KeyOption`, `KeyControl`, `KeyCommand`, the special keys `KeyReturn` … `KeyF12`, all 39 semantic colors (`ColorLabel` = `driver.Semantic(driver.ColorLabel)` …) and the standard shortcuts `ShortcutUndo` … `ShortcutClose` (from `ItemRole.DefaultShortcut`, using `KeyPrimary`). Helpers: `RGBA`, `RGB8`, `UniformInsets`, `SystemFont(size)`, `BoldSystemFont(size)` (a size that isn't positive, or NaN, becomes 0 = the control size's default) and `Shortcut(mods, key)` (upper-cases letter keys).
* **`Appearance`** is `gogui`'s own `uint8` type (`AppearanceSystem`, `AppearanceLight`, `AppearanceDark`) with `Toggled` (swaps Light and Dark, anything else unchanged) and `String`. `mode()` maps it to `driver.AppearanceMode` (unknown → system); `effectiveAppearance` gives Light or Dark, never System.
* **Widgets (`widget.go`).** `Widget` is a sealed interface (unexported `base()`, `node() layout.Node`, `peerWidget() driver.Widget`, nil for peer-less widgets such as `Spacer`). Every widget embeds the shared `widget` struct: `kind` (names it in check messages and selects the default expansion), the peer, the layout node (a `layout.Leaf` around the peer unless the widget builds its own), the parent link, a `layoutHost` link on a window's root, the destroyed and disabled flags, and the axis flags (`vertical` for sliders and separators, `scrolls` for scroll views).
  * *Construction.* Constructors get the driver through `driverFor("NewX")`, which panics outside `Run` and runs the UI-thread check, and create the peer at once. `common[T].init` sets kind, peer and node and applies the default expansion.
  * *Shared setters.* `common[T]` (embedded as `common[*Label]` …) has `SetEnabled`, `SetHidden`, `SetTooltip`, `SetControlSize` and `Focus`; each returns `T`, so chains keep the concrete type. Every public method starts with the UI-thread check.
  * *Re-layout.* Setters that can change a widget's size call `invalidate()`, which walks the parent links to the window's `layoutHost`; it does nothing outside a window or on a destroyed widget.
  * *Lifetime.* `destroy()` is idempotent and destroys only the widget's own peer (the window destroys its tree bottom-up with `destroyTree`). After it, setters only record their value and getters return the last one. `common[T].init` registers every public widget in the app's `live` map; when `Run` returns, `destroyLeftovers` runs `destroyTree` on every live widget without a parent. Private radios and the peer-less `Spacer` are not registered.
  * *Default expansion* (by kind): text fields and progress bars horizontally, text views on both axes, sliders and separators along their length, scroll views on each axis with a scroller; labels, buttons, checkboxes, radios, radio groups, pop-up buttons and spinners not at all; boxes, stacks and forms only through their children.
  * *Events.* `On*` methods return `Unsubscribe` (`func()`). `subscribers[F]` keeps handlers in subscription order; unsubscribing is idempotent and copies the list, so a dispatch in progress keeps its snapshot and skips handlers removed during it, and handlers added during a dispatch run from the next one.
* **`Label`**: `NewLabel(text)`, `SetText`, `Text`, `SetFont`, `Font`, `SetTextColor`, `SetAlignment`, `SetSelectable`, `SetWraps`. `SetText`/`SetFont`/`SetWraps` invalidate.
* **Buttons, toggles, separators.** `NewButton(title)` (`SetTitle`, `SetDefault`, `SetCancel`, `OnClick(func())`); `NewCheckbox(title)` (`SetTitle`, `SetChecked`, `Checked`, `SetState`, `State`, `OnChange(func(on bool))`); `NewRadioGroup(items...)` (`SetSelected`, `Selected`, `OnChange(func(i int))`); `NewSeparator()` (`SetVertical`).
  * Each control implements its driver handler through an unexported type (`buttonEvents`, `checkboxEvents`, `radioEvents{group, index}`), which drops events on a disabled or destroyed widget. Setters never fire events.
  * The checkbox keeps its state; mixed counts as on in `Checked` and `OnChange`; `SetState` maps unknown values to `StateOn`.
  * A radio group is a `common[*RadioGroup]` around a 6 pt `layout.Stack` with a `Container` peer holding one private `radio` widget per item. The group implements `parentWidget`, so `destroyTree` destroys the radios before the container. It enforces exclusivity: the first radio is selected initially (none without items), `SetSelected(i)` selects none for an index out of range (-1), and a user click fires `OnChange` only when the selection changed. `SetEnabled`, `SetControlSize`, `SetTooltip` and `Focus` (the selected radio, else the first) are overridden to reach the radios.
  * `SetVertical` sets the `vertical` flag, re-applies the default expansion and invalidates. Only title setters and `SetVertical` invalidate (plus the shared `SetHidden`/`SetControlSize`).
* **Input and value controls.** `NewTextField()` / `NewSecureField()` return `*TextField` (`SetText`, `Text`, `SetPlaceholder`, `SetFont`, `Font`, `SetAlignment`, `SetEditable`, `OnChange(func(string))`, `OnSubmit(func(string))`, `Secure()`). `NewSlider()` (`SetRange`, `SetValue`, `Value`, `SetTickMarks`, `SetVertical`, `OnChange(func(float64))`). `NewProgressBar()` / `NewSpinner()` (a generic `progress[T]` around one `driver.Progress` peer; `SetRange`, `SetValue`, `Value`, `SetIndeterminate`, `Indeterminate`). `NewPopUpButton(items...)` (`SetItems`, `Items` (a copy), `Item(i)` ("" out of range), `SetSelected`, `Selected`, `OnChange(func(int))`).
  * The text field keeps its text (user edits update it) and font. Sliders and progress indicators keep a `valueRange`: AppKit's defaults (slider 0…1, progress 0…100); `SetRange` ignores a NaN bound and raises a max below min to min; values are clamped (NaN → min), also values the native slider reports.
  * Pop-up: the first item is selected initially (none without items); `SetItems` keeps the selection if still in range, else resets it to 0 (-1 without items); `SetSelected` out of range selects none. `OnChange` fires only on user changes; out-of-range native indices are dropped.
  * Invalidating setters: `TextField.SetText/SetPlaceholder/SetFont`, `Slider.SetTickMarks/SetVertical` (flips the expansion), `PopUpButton.SetItems`. Progress setters don't.
* **Stacks and forms.** `VStack(spacing, children...)` / `HStack(...)` return `*Stack` (a `common[*Stack]` around a `layout.Stack` with a `Container` peer; `Add`, `Padding(v)`, `PaddingInsets(in)`, which invalidate). `Spacer()` is a peer-less widget around a `layout.Spacer`. `Row(label, control)` returns a `FormRow` (a non-empty label creates a `Label` at once, `""` none). `Form(rows...)` returns `*FormView` (a `common[*FormView]` around a `layout.Form` with a `Container` peer).
  * Every stack and form owns a container peer whose `SetChildren` gets the peers of its direct children in order (a form: each row's label, then its control); peer-less widgets are skipped. The layout node gets the children's nodes. Each change re-syncs both and invalidates.
  * `adopt` sets the parent link and first removes the widget from its old parent (re-adding to the same stack moves it to the end). A nil child, the same widget twice in one call and a cycle panic. A control moved out of a form takes its row with it and the row's label is destroyed; passing the same `FormRow` to a second form moves the label too.
  * `SetHidden` on a form's control also hides the row's label peer.
* **Boxes, scroll views, text views.** `NewBox(title)` (`SetTitle`, `Title`, `SetContent`, `Content`). `NewScrollView(doc)` (`SetDocument`, `Document`, `SetHasVerticalScroller`, `SetHasHorizontalScroller`, `SetMinWidth`, `SetMinHeight`, `Offset`, `SetOffset`, `OnScroll(func(Point))`). `NewTextView()` (`SetText`, `Text`, `SetFont`, `Font`, `SetTextColor`, `SetEditable`, `Selection`, `SetSelection`, `OnChange(func(string))`).
  * `Box` and `ScrollView` wrap `layout.Box` / `layout.ScrollView` nodes around their peers and implement `parentWidget` with one child, so `adopt`/`detach` and `destroyTree` work as for stacks. Replacing the child or setting nil detaches the old one without destroying it; moving the child elsewhere empties the host. Each change invalidates.
  * The scroller setters keep three things in sync: the peer's scroller, the node's `SetScrolls` and the `scrolls` axis flags (which re-apply the default expansion).
  * `scrollEvents`: `Scrolled` updates the remembered offset and fires `OnScroll` (also while disabled, as in AppKit; not when destroyed); `ViewportResized` marks the window dirty. `SetOffset` doesn't fire; `Offset` reads the clamped peer offset.
  * Text view: `SetText` puts the caret at the end; the selection is read back from the peer after every change (clamped, character-aligned UTF-8 byte offsets). The peer's `TextChanged` carries no text, so `textViewEvents` reads `Text()` once per edit and passes it to every handler. No text-view setter invalidates.
* **Menus, alerts, app-level events.** `MenuBar(menus...) MenuBarSpec`, `Menu(title, items...)`, `AppMenu()`, `EditMenu()`, `WindowMenu()` (Minimize, Zoom, a separator, Close) return `MenuSpec`; `MenuItem(title, shortcut, action)` and `MenuSeparator()` return `MenuItemSpec`; the three are opaque value types built by these functions. `App.SetMenuBar(bar)`. `Alert{Style, Message, Detail, Buttons}.Show(win, done)`. `App.SetAppearance`, `Appearance`, `OnAppearanceChange(func(Appearance))`, `OnQuitRequested(func() bool)`.

  * `SetMenuBar` builds a fresh `driver.MenuBarSpec` and gives every item with an action a new ID from a per-app counter that never repeats, so IDs of a replaced bar do nothing. Role items and separators get ID 0; an item without an action gets ID 0 and is disabled. Unknown IDs do nothing.
  * `Show` panics outside `Run`. The spec gets `["OK"]` when `Buttons` is empty and `Cancel` = the index of the first button titled exactly "Cancel" (else -1). A nil or closed window makes the alert app-modal.
  * `AppearanceChanged` fires handlers only when Light/Dark actually switches. `Appearance()` reads the driver each time.
  * `QuitRequested` asks the handlers in order; the first `false` vetoes and later ones aren't asked. `App.Quit` doesn't ask.
* **Windows.** `WindowConfig` aliases `driver.WindowConfig` (`Title`, `Size`, `MinSize`, `MaxSize`, `Style`, `Center`). `App.NewWindow(cfg) *Window` creates the hidden peer (a driver error panics). `Window`: `SetTitle`, `Title`, `SetContent`, `ContentSize`, `SetContentSize`, `Show`, `Close`, `OnClose(func())`, `OnShouldClose(func() bool)`; it implements `driver.WindowHandler` through the unexported `windowEvents`.
  * *Content.* `SetContent(c)` sets the root's `host` link to the window, wraps its node in a `layout.Root` and passes its peer to the window peer; nil removes it. The old content is detached but not destroyed. Content has one place: `detach` takes a widget out of its stack, form or window.
  * *Deferred, coalesced layout.* `invalidate` sets a `pending` flag and posts one pass to the UI queue; further calls before it runs add nothing. `ContentResized` (user resize, `SetContentSize`) lays out at once; `Show` lays out first if a pass is pending.
  * *Minimum size.* After each pass the window computes `max(cfg.MinSize, root.MinSize())` and calls the peer's `SetMinSize` only on change. The window is not grown on the spot.
  * *Closing.* `OnShouldClose` handlers run in order on a user close request; the first `false` vetoes. `Close` and `App.Quit` don't ask. On the peer's `Closed` the window runs the `OnClose` handlers (widgets still alive), then destroys the content tree bottom-up. Afterwards setters only record, `ContentSize` returns the last size, and `Show`, `Close` and `SetContent` do nothing. `KeyChanged` is ignored for now.
* **Test hook.** Tests (`package gogui`) replace `newDriver` with a silent headless driver, reset the once-only flag and run `Run` on the test goroutine. `runApp(t, body)` runs body in `ready`, drains the queue and quits.

## 2. `internal/driver`: the peer boundary

AWT/SWT-style peers: one interface per public widget, created by a `Driver` factory, with a handler interface through which the backend reports user and OS events. PLAN.md §4.3 has an excerpt; the package docs hold the full contracts.

### 2.1 Interfaces

* **`Driver`**: `Name`, `Run(cfg, AppHandler) error`, `Quit`, `Post(fn)`, `Appearance`, `SetAppearance(AppearanceMode)`, `SetMenuBar(*MenuBarSpec)`, `RunAlert(parent, AlertSpec, done func(int))`, `NewWindow(cfg, WindowHandler)`, and one factory per peer: `NewContainer`, `NewLabel`, `NewButton`, `NewCheckbox`, `NewRadio`, `NewTextField(secure, h)`, `NewSlider`, `NewProgress`, `NewPopUpButton`, `NewSeparator`, `NewBox`, `NewScrollView`, `NewTextView`.
* **`AppHandler`**: `Ready`, `AppearanceChanged`, `QuitRequested() bool`, `MenuItemSelected(id)`. Menu items carry integer IDs, not funcs.
* **`Widget`** (every peer): `SetFrame(Rect)`, `FittingSize(max) Size`, `SetEnabled`, `SetHidden`, `SetControlSize`, `SetTooltip`, `Focus`, `Destroy`.
* **`Container`**: `Widget` + `SetChildren([]Widget)`. List order is paint and focus order. Children dropped from the list are removed, not destroyed.
* **Controls** (peer + handler): `Label`; `Button`/`ButtonHandler.Clicked`; `Checkbox` and `Radio`/`ToggleHandler.StateChanged`; `TextField`/`TextFieldHandler` (`TextChanged`, `Submitted`); `Slider`/`SliderHandler`; `Progress` (bar or spinner, indeterminate); `PopUpButton`/`PopUpHandler`; `Separator`; `Box` (`ContentInsets`); `ScrollView`/`ScrollHandler` (`Scrolled`, `ViewportResized`); `TextView`/`TextViewHandler.TextChanged()` (no argument, documents can be large).
* **`Window`**/`WindowHandler` (`ContentResized`, `ShouldClose`, `Closed`, `KeyChanged`). A window is not a `Widget`; it holds one content widget.

`RadioGroup` exclusivity lives in the public layer; the driver only reports clicks.

### 2.2 Shared value types

* **Geometry**: `Point`, `Size` (`Unbounded()` = +Inf in both components, the `FittingSize` maximum when unconstrained), `Rect` (top-left origin, half-open `Contains`, `Inset` collapses to the centre when over-inset), `Insets`.
* **`Color`**: straight-alpha RGBA, or one of 39 `SemanticColor`s named after NSColor. The zero `Color` means "default" where a setter says so.
* **`Font`**: family, size, weight, italic, monospaced. Size 0 means the system size for the control size (`EffectiveSize`: 13/11/9/13 pt for regular/small/mini/large).
* **`Appearance`** (dark, accent, increase contrast, reduce motion/transparency, legacy scrollers), `AppearanceMode`, `ControlSize`, `TextAlignment`.
* **Keys**: `Modifiers` with `Primary` (⌘ on macOS, Ctrl elsewhere), `Key` as a rune with AppKit values for special keys, `Shortcut` with `Display(mac)` (`⇧⌘D` / `Ctrl+Shift+D`).
* **Menus**: `MenuBarSpec` → `MenuSpec` → `MenuItemSpec` with `MenuRole` and `ItemRole` (standard App/Edit/Window items with default titles and shortcuts), `DefaultMenuBar`, deep `Clone`, `FindItem`. A role item with a non-zero ID is reported through `MenuItemSelected` instead of running its standard action.
* **`AlertSpec`** (style, message, detail, buttons; first button is the default, `Cancel` index for Escape), **`WindowConfig`**/`WindowStyle`, **`AppConfig`**.

Enum values that mirror AppKit match it bit for bit and are tested: `ControlSize` (NSControlSize), `WindowStyle` (NSWindowStyleMask), `CheckState` (NSControlStateValue, mixed = -1). `AlertStyle` deliberately does not match NSAlertStyle; drivers map it.

### 2.3 Contracts every backend follows

* **Units** are logical points, top-left origin. A frame is relative to the content area of the parent (container, box, scroll-view document or window).
* **Threading**: every peer method and handler call happens on the UI thread; the only exception is `Driver.Post`, safe from any goroutine and order-keeping. `Run` is called on the locked main OS thread; factories are used only after `Ready`.
* **Setters never call handlers.** Handlers report user and OS changes, plus the consequences documented on a method: `Window.Close` → `Closed`, `SetContentSize` → `ContentResized`, `SetAppearance` → `AppearanceChanged`; `Quit` closes all windows without asking `QuitRequested`.
* **Getters exist only for user-changeable state** (`Text`, `Value`, `State`, `Selected`, `ContentSize`, `Offset` …). The public layer remembers everything else.
* **Layout is done in Go** for every driver: peers report `FittingSize` and receive `SetFrame`. Stretchable controls report their minimum comfortable size; the layout engine decides about stretching.
* **Scroll viewport**: `ScrollView.ViewportSize` depends only on the frame, the enabled scrollers and the appearance (scrollers never auto-hide), so `SetDocumentSize` never changes it. When the viewport changes without a `SetFrame`, the driver reports `ViewportResized` and the public layer re-runs the layout.
* **Parenting**: a widget has at most one parent; adding it elsewhere first removes it. `Destroy` removes the widget from its parent and frees it but does not destroy children (the public layer destroys bottom-up). Nothing may be called after `Destroy`.
* **Text offsets** (`TextView` selection) are UTF-8 byte offsets; drivers convert to UTF-16 where the OS needs it. `SetSelection` clamps and moves back to a rune boundary.
* Peers never store Go pointers in native memory (§5).

## 3. `internal/driver/stub`: fallback and test peers

Every peer interface has a stub (compile-time checked in `assert.go`). Stubs are the building blocks of the headless driver, fallbacks in the appkit and aqua drivers while incomplete, and test doubles for the public layer.

* **State is recorded** in exported fields (`Frame`, `Disabled`, `Title`, `Value` …). Setters only record (sliders and progress clamp to their range).
* **`User…` methods** simulate input and call the handler like the real control: `Button.UserClick`, `Checkbox.UserClick` (mixed/off → on, on → off), `Radio.UserClick` (always reports on), `TextField.UserType/UserSubmit`, `Slider.UserDrag`, `PopUpButton.UserSelect`, `ScrollView.UserScroll`, `ScrollView.UserResizeViewport(in)` (sets `ViewportInset`, clamps the offset, reports `ViewportResized`), `TextView.UserType`, `Window.UserClose/UserResize/UserSetKey`, `Driver.UserSelectMenuItem/UserQuit/SetSystemAppearance`, `Alert.Dismiss`. Control `User…` methods do nothing while the control is disabled (`ScrollView.UserScroll` excepted).
* **`Base`** implements `Widget` and tracks the parent (`adopt`/`release`), so moving between parents and `Destroy` behave like the real drivers.
* **Fake metrics** (`metrics.go`) make layout tests independent of fonts. They are stable on purpose; layout and public-layer tests depend on the exact numbers:

  | Item | Fake size |
  |---|---|
  | Text | 7 pt per rune, 16 pt line height at 13 pt, scaled by font size |
  | Control height | 22 regular, 19 small, 16 mini, 28 large |
  | Button | text + 28 × control height |
  | Checkbox, radio | 18 + text × 18 |
  | Text field, slider, progress bar | 96 × control height (vertical slider swapped) |
  | Spinner | 32 × 32 |
  | Pop-up button | widest item + 32 × control height |
  | Separator | 1 × 1 |
  | Box | its content insets: 8, plus 16 on top when titled |
  | Container, scroll view, text view | 0 × 0 (sized by the layout) |
  | Scroll viewport | the frame size minus `ScrollView.ViewportInset` (zero by default) |

  Labels wrap only when `SetWraps(true)`. A non-zero `Base.Fixed` overrides the metrics. `FittingSize` always clamps to `max`.
* **`stub.Driver`** (`Name() == "stub"`) runs `Ready` and then a loop over its own small mutex queue until `Quit`. It does not use `mainthread`; the headless driver does.

Known simplifications (fine for tests, not for real drivers): the stub window doesn't move key status on `Close` and doesn't re-clamp on `SetMin/MaxSize`; the scroll view's viewport changes only through `ViewportInset`; there is no Return/Escape simulation for default/cancel buttons; menu role actions are not run.

### 3.1 `internal/driver/headless`: the display-less driver

`headless.New(notice io.Writer) *Driver` (`Name() == "headless"`) is the driver `gogui` uses where a platform has no native one, and the one the `gogui` tests run on. It embeds `*stub.Driver` (factories, appearance, menu bar, alerts, recorded state, `User…` simulations) and replaces the stub's queue with a `mainthread.Queue`:

* **`Run`** may be called once (`ErrRunTwice`). It creates the queue, `Bind`s the calling goroutine, installs a channel wake, writes `headless.Notice` ("gogui: headless driver, no windows are shown") to `notice` (nil writes nothing), calls `Ready`, then `Drain`s on every wake until `Quit`. While waiting it keeps a far-future timer pending, so a `Run` nothing quits blocks forever (as a native loop does) instead of tripping the runtime's deadlock check. After `Quit` it drains once more (work queued before `Quit` runs once), closes any window that work opened and returns nil.
* **`Quit`** closes the open windows (each gets `Closed`), closes the queue and wakes the loop. **`UserQuit`** is overridden to reach it.
* **`Post`** forwards to `Queue().Do`; before `Run` and after `Quit` it drops fn.
* **`Queue()`** returns the queue (nil before `Run`, closed after), for `gogui.Do`/`DoSync`.
* **Panics** in `Ready` or queued work propagate out of `Run` unrecovered; the queue is closed on the way out, releasing goroutines blocked in `DoSync` with false.

The driver is single-threaded except `Post` and `Queue`.

## 4. `internal/mainthread`: the UI-thread queue

`Queue` is created with `New()` (the zero value is not usable; there is no package-level queue). The driver owns one; `gogui.Do`/`DoSync` forward to it.

| Method | Meaning |
|---|---|
| `Bind()` / `Bound()` | Marks the calling goroutine as the UI goroutine. |
| `SetWake(fn)` | The "wake the native loop" hook (`PostMessage`, `g_idle_add`, `performSelectorOnMainThread:`). Called on the producer's goroutine, at most once until the next `Drain`, and immediately if work is already pending. Must not block or drain. |
| `Do(fn) bool` | Queues fn (FIFO), even from the UI goroutine. `false` after `Close`. |
| `DoSync(fn) bool` | On the UI goroutine: runs fn inline (no deadlock). Elsewhere: queues and blocks; a panic in fn is re-raised in the caller as `*PanicError` (with the UI stack). `false` if the queue closes before fn starts. |
| `Drain() int` | Called by the driver on the UI thread when woken. Runs a **snapshot**: work queued during the drain waits for the next one, so self-requeuing work can't starve the native loop. Re-entrant (nested modal loops). |
| `Close()` | Rejects new work and releases waiting `DoSync` callers. Already-queued `Do` work still runs on the next `Drain`. |
| `OnUIThread()`, `Check(what)`, `SetChecks(on)` | Debug guard. A goroutine-ID comparison costs a few µs, so `Check` is off by default and then costs one atomic load. |

Implementation: a lock-free multi-producer single-consumer queue (Vyukov, non-intrusive), an atomic `wakePending` flag for coalescing, and a drain sequence number to detect nested drains.

Gotchas for driver authors:

* A panic in a `Do` function propagates out of `Drain`; the remaining work stays queued and a wake is re-requested. The driver loop decides whether to recover.
* `DoSync` on the UI goroutine **before `Bind`** queues and blocks: always `Bind` before any user code runs.
* `DoSync` always pays for one goroutine-ID lookup.

## 5. `internal/ffi`: FFI helpers

The rule (PLAN.md §7.2): **Go pointers are never stored in native memory.** Native objects (ObjC ivars, GObject `user_data`, `GWLP_USERDATA`) store an integer `ffi.Handle` instead.

**Handle table.** `Handles[T]` is a generic table, one per driver, typed to its peer interface. The zero value is ready; don't copy it after first use. API: `New(v) Handle`, `Get(h) (T, bool)`, `Valid(h)`, `Free(h) bool`, `Len()` (leak checks in tests).

* `Handle` is a `uintptr`: low 24 bits slot index (about 16.7 M live handles), the rest a generation (40 bits on 64-bit, 8 on 32-bit). `Free` bumps the generation, so a stale handle from a late native event no longer resolves; a slot whose generation runs out is retired.
* The zero `Handle` is never valid, so a NULL `user_data` or zeroed ivar never resolves. `Free` clears the value so it can be collected.
* Stale, foreign and double-freed handles make `Get` return `false` and `Free` do nothing. Handles carry no table ID, so a handle from one table can match a live slot in another; never mix tables.
* `New` panics when the table is full (only a leak can cause that on 64-bit).
* A mutex makes the table safe if a stray native callback arrives on another thread (about 15 ns per `Get`, no allocations); drivers use it on the UI thread.
* Never convert a `Handle` to `unsafe.Pointer`; pass it to native code as a `uintptr`.

**Callback registry** (`callback.go`, `callback_windows.go`, `callback_unix.go`, `bind.go`). Native callbacks can't be freed and have a fixed maximum, so drivers create a fixed set of trampolines at start-up and dispatch through a `Handle`.

* `RegisterCallback(name, fn) uintptr` is the only way drivers create native callbacks. It returns the C function pointer, valid for the life of the process. It panics, **before creating anything**, on an empty name, a name registered twice (this catches per-widget callbacks), a bad signature or a used-up budget. A name is recorded only after the native create succeeded.
* Signature rules (the intersection of `syscall.NewCallback` and purego, `checkCallbackSignature(fn, goos)`): a non-nil, non-variadic func with ≤ 12 arguments; arguments are bool, integers, uintptr, pointers or `unsafe.Pointer` no wider than a uintptr, plus float32/float64 except on Windows; at most one result of those kinds, and on Windows exactly one, uintptr-sized and not a float. No structs. `CheckCallback(fn, goos) error` applies them for any OS without creating a callback (since S4.1c; the gtk4 shell checks its linux set on the Windows host with it).
* `Callbacks()` counts created callbacks. `MaxCallbacks` is the budget, one constant: **1024 on every OS** (Windows' guarantee; on darwin/linux it leaves about 975 of purego's 2000 slots for callbacks the registry never sees: purego/objc's block dispose callback, blocks, `objc.RegisterClass` methods and ivar accessors). `TestCallbackBudget` checks that every target has at least `MaxCallbacks` + 64 free slots.
* *No hidden callbacks.* purego's `RegisterFunc` turns every Go func passed as an argument into a new, invisible callback on every call. So `Bind` and `BindAddr` reject a func type with a func-typed argument at any position (`checkBindFunc` in the portable `bind.go`, before the symbol lookup), naming the argument and pointing to `RegisterCallback` (pass the trampoline's pointer as `uintptr`). Func-typed results stay allowed. `check.sh`'s hidden-callback guard keeps every other way to create callbacks inside `internal/ffi`.
* Windows uses `syscall.NewCallback`; darwin/linux `purego.NewCallback`. Safe for concurrent use (a mutex), though drivers register on the UI thread at start-up. A callback runs on whatever thread native code calls it from.
* *Measurements* (tests only: `budget_test.go`, `thread_*_test.go`): `TestCallbackBudget` re-runs the test binary as a child (`GOGUI_FFI_BUDGET_CHILD`) that creates callbacks until failure. Windows: 1998 free (the runtime takes 2 of `cb_max = 2000`), ended by the unrecoverable `fatal error: too many callback functions`; the same top-level func twice gives the same pointer. Linux: 2000 free; darwin: 1999 (the test binary imports `purego/objc`), both ended by purego's recoverable panic with no deduplication. `TestCallbackForeignThread` runs a registered start routine on threads Go didn't create; `TestCallbackNested` has two callbacks calling each other through native code 17 deep; `BenchmarkCallbackCall` measures one call.

**Struct-layout helpers** (`layout.go`, exported for the driver packages' tests). Without cgo, a mirrored C struct is checked against constants from the headers, chosen per GOARCH by the test.

* `CheckLayout(t TB, v, Layout{Size, Align, Fields: []Field{{Name, Offset, Size}}}) bool` reports every difference in one `Errorf`, one line each: size, alignment, field offset, field size (if given), missing, unlisted, duplicate and out-of-order fields. Blank `_` padding fields are not listed.
* `CheckNoGoPointers(t TB, v) bool` reports every field path (through nested structs and arrays) that holds a pointer, `unsafe.Pointer`, string, slice, map, chan, func or interface. Native addresses in mirrors are `uintptr`.
* `ffi.TB` is just `Helper` + `Errorf`, so the package doesn't import `testing`.

**Shared libraries** (`dl_unix.go`, darwin and linux, through purego).

* `Dlopen(path) (*Lib, error)` opens with `RTLD_NOW|RTLD_GLOBAL`; errors name the library and wrap dlerror's message; an empty path is an error.
* `Lib.Sym(name)` (a missing or NULL symbol is an error naming symbol and library), `MustSym` (panics; for start-up lookups), `Bind(fptr, name)` (a `purego.RegisterFunc` wrapper; a bad `fptr`, a missing symbol or a func type purego rejects come back as errors, never panics), `Path()` and `Close()` (a second Close does nothing; `Sym` on a closed `Lib` fails). Nothing checks that the Go signature matches the C one.
* `BindAddr(fptr, addr)` is `Bind` for a bare function pointer with no symbol: a vfunc slot read from a GObject class struct, or a parent implementation to chain up to. An `addr` of 0, a bad `fptr` and a func type purego rejects are errors naming the address; `*fptr` is left unset. A wrong non-zero `addr` crashes on the call.

**C strings** (`cstring_unix.go`, `libc_*.go`).

* `CString(s) uintptr` copies into libc `malloc` memory, NUL-terminated; the caller frees it with `Free(p)` (`Free(0)` is a no-op). A string containing NUL panics instead of being truncated. libc is loaded on first use.
* `GoString(p)` copies up to the first NUL, `GoStringN(p, n)` exactly n bytes; both return "" for NULL and never free.

**Raw memory** (`mem.go`, every OS).

* `ReadUintptr(addr, off)` / `WriteUintptr(addr, off, v)` read and write the uintptr-sized word at `addr+off` in native memory (a `Handle` in an ObjC ivar, a vfunc slot in a GObject class struct). The address must never be Go memory and `v` never a Go pointer. A NULL `addr` or an `addr+off` not aligned to a uintptr panics; any other bad address crashes.
* `ReadInt32` / `WriteInt32` do the same for a 32-bit C `int` with 4-byte alignment (int fields and out-parameters, where a word-sized write would clobber the neighbour). They share the NULL and alignment checks (`checkAligned`).
* `At[T any](p uintptr) *T` returns the address of a native struct as a `*T` (a Win32 `lParam` pointing at a `MINMAXINFO`, `NCCALCSIZE_PARAMS`, `WINDOWPOS`, `CREATESTRUCTW` or `RECT`, read and written in place). It panics on 0 and on a misaligned `p`, so `w32` and `shell/win32` need no `//nolint` conversion of their own. `p` must be native memory valid for the call, and the `*T` must not outlive it.
* `CopyBytes(p uintptr, n int) []byte` copies `n` bytes of native memory into a new Go slice (a mapped D3D11 staging texture, copied before `Unmap`). Any alignment; `n` 0 returns an empty slice without touching `p`; NULL with `n > 0` and a negative `n` panic.
* `cptr(p uintptr) unsafe.Pointer` is the package's single uintptr→unsafe.Pointer conversion, for native (never Go) memory only, written `*(*unsafe.Pointer)(unsafe.Pointer(&p))` so vet's unsafeptr check passes (§7.2 of PLAN.md).

## 6. `internal/layout`: the layout engine

One engine lays out every driver's widgets in Go; the policies are in PLAN.md §11.1 (S0.4). It is complete for v0.1.

* **`Node`**: `Props() *Props`, `Expands(Axis) bool`, `Measure(p *Pass, max) Size`, `Arrange(p *Pass, frame Rect)`. `Measure` returns the natural size shrunk towards the minimum when `max` is smaller, **never below the minimum**, so the result may exceed `max`. Measuring with the main axis unbounded gives the natural size, at 0 the minimum; there is no separate `MinSize`. The frame passed to `Arrange` is final: the parent has already aligned it in its slot.
* **`Pass`** (`pass.go`): per-pass state. Nodes measure children only through `p.Measure(child, max)`, which normalizes `max` and returns zero for hidden nodes without measuring them. It caches every result by node and normalized max: a map from the node's `*Props` to a short list of (max, size) pairs scanned linearly. Without the cache every nesting level measures its subtree about 3 times (9,840 `FittingSize` calls on the deepest leaf at depth 8); with it at most 9 at any depth. The cache lives only in the `Pass`; `Root` starts a fresh `Pass` for every `Layout` and `MinSize`. **Invariant:** a tree must not change while a `Pass` that measured it is in use. The zero value caches; a nil `*Pass` works but never caches.
* **`Props`** (zero value = defaults, chained setters per `Axis`): `SetMin`/`Min`, `SetMax`/`Max`, `SetFixed`, `SetAlign`/`Align`, `SetExpand`/`Expand`, `SetHidden`/`Hidden`. Normalization: negative and NaN → 0, a min or max of +Inf means unset, unset max = +Inf, max 0 is real, min wins over max.
* **`Align`**: `AlignDefault` (the parent decides), `Leading`, `Center`, `Trailing`, `Fill`. **`LayoutDirection`**: `LeftToRight` (default), `RightToLeft` (reserved, laid out as LTR). **`Axis`**: `Horizontal`, `Vertical`, `Cross()`.
* **`Item`** = `FittingSize(max) Size` + `SetFrame(Rect)`. Every `driver.Widget` satisfies it, and aqua can use it for internal parts without a peer.
* **`Leaf`/`NewLeaf(Item)`**: the default min is `FittingSize(Unbounded)`, so a control never shrinks unless the app sets a smaller min (a max below the fitting size only works together with such a min). The width is resolved first; if it differs from the fitting width, the height (natural and default min) is `FittingSize` at that width, which handles wrapping labels. NaN, negative and +Inf sizes from an item count as 0. Hidden leaves call neither `FittingSize` nor `SetFrame`.
* **`place(slot, size, h, v)`**: `Leading`/`AlignDefault` at the origin, `Center` and `Trailing` in the free space, `Fill` stretches to the slot. A node larger than its slot starts at the slot's origin and overflows at the trailing edge. Nothing is rounded; drivers snap edges, not sizes.
* **`distribute(items []span, space) []float64`** (internal, for stacks and forms): one size per child along the main axis; callers subtract spacing and padding first. A `span` is natural, min, max, expand; inputs are normalized like `Props` and each natural is clamped into [min, max]. +Inf space gives the naturals. Extra space is shared equally among the expanders, a max caps a share and the rest is shared again; with no free expander the rest stays at the trailing end. Short space shrinks every child in proportion to (natural − min); below the sum of the minima every child gets its min and the content overflows. The float leftover goes to the last child that got a share, so the in-order sum equals the space exactly or (in a rounding gap, about 2 % of random inputs) is the float just below it, never above. Deterministic; the input is not modified.
* **`Stack`** (`NewVStack(spacing, children...)`, `NewHStack(...)`): chained `SetSpacing`, `SetPadding`, `SetPeer`, `SetDirection`, `SetChildren` with getters. Bad spacing and padding count as 0; a nil child panics. `Peer` is a one-method interface (`SetFrame`) that every `driver.Container` satisfies. With a peer, the stack frames it and lays children out from (0, 0); without one, it is a transparent group and offsets children by its own origin.
  * *Measure*: the inner cross extent is the cross max, clamped by the stack's own cross min/max, minus the padding. Each visible child is measured at it with the main axis unbounded (natural) and at 0 (min); these become `span`s. The main size is the stack's own `resolve` of the sums plus padding and spacing. `distribute` gives the shares, and the cross size is the largest child's cross size measured at its share, plus padding (height-for-width in an HStack).
  * *Arrange*: the same order. A child's slot is exactly its main-axis share, so its own main-axis alignment is ignored. Across, the child is placed with `place` using its explicit alignment, else `Fill` if it expands on the cross axis, else `Leading` (VStack) or `Center` (HStack). A cross max still caps `Fill`.
  * *Expands*: the own flag, or any visible child's. A `Spacer` counts on the main axis.
  * *FirstLine*: padding.Top plus the first visible child's first line, recursively; with no visible child the stack's own height; a hidden stack reports 0.
* **`Spacer`** (`NewSpacer`): never expands by itself; a parent stack treats it as expanding on its main axis. It measures 0 (or its Props min) and frames nothing. `spacer.go` also holds `firstLine(p, node, max)` (calls the optional `FirstLine` method or falls back to the measured height, 0 when hidden) and the per-axis helpers `get`/`mk`/`getPt`/`mkPt`.
* **`Form`** (`NewForm(rows...)`): `Row{Label Item; Control Node}`. Chained `SetRows`, `SetPeer`, `SetDirection`; a nil `Control` panics. Each label is wrapped in an internal `Leaf` and measured unbounded, so labels never shrink or wrap. A nil label is an empty label. A row is hidden when its control is; its label then doesn't count and isn't framed.
  * *Columns*: the label column is the widest visible label; controls start at column + `FormLabelGap` (8 pt), or at 0 when no visible row has a label. Labels are right-aligned in the column. A form has no padding.
  * *Measure*: width = the form's own `resolve` of column + gap + widest control (natural; minimum for the min), so only the controls shrink. Each row's height is max(label, control measured at its width), rows are `FormRowSpacing` (8 pt) apart, and `distribute` shares the height; a row expands when its control expands vertically, and its max is the control's max but never below the label.
  * *Arrange*: in the control column a control uses its explicit horizontal alignment, else `Fill` (capped by its max) when it expands horizontally, else `Leading` at its natural width; vertically the same rule in its row. The label is centered on the control's first line, never above the row's top.
  * *Expands*: the own flag or any visible control's. *FirstLine*: the taller of the first visible row's label and its control's first line.
  * Both spacing constants are from memory of the HIG and still to be checked.
* **`Root`** (`NewRoot(node)`): chained `SetNode`, `Node`, and `Layout(contentSize)`, which runs one pass in a fresh `Pass` and arranges the node at (0, 0, contentSize) whatever its expansion flags and min/max. Negative, NaN and +Inf components count as 0, a hidden root frames nothing, a nil node panics. `MinSize()` is the smallest content size the tree fits in: w = the root measured at (0, +Inf), then h = its natural height measured at (w, +Inf), each in a fresh pass. The height is the natural one, not the one measured at 0, so a window never cuts off content (wrapping labels are tallest at the minimum width). A hidden root gives 0 × 0.
* **`Box`** (`NewBox(peer, content)`): a group box with one content node (nil for none). It owns a `BoxPeer` (`SetFrame` + `ContentInsets`, satisfied by every `driver.Box`) and starts a new coordinate space; a nil peer panics. Chained `SetContent`, getters `Content` and `Peer`.
  * The insets are read again on every `Measure` and `Arrange` (they depend on title and control size); negative, NaN and +Inf edges count as 0.
  * *Measure*: the width first (content natural and minimum width plus insets, through the box's own `resolve`), then the content measured at that inner width plus the insets. The peer's `FittingSize` is never used. A nil or hidden content counts as 0 × 0.
  * *Arrange*: frames the peer and the visible content at (0, 0, frame.Inset(insets).Size()).
  * *Expands*: the own flag or the visible content's.
* **`ScrollView`** (`NewScrollView(peer, doc)`): shows one document node (nil for none). It owns a `ScrollPeer` (`SetFrame`, `ViewportSize`, `SetDocumentSize`, satisfied by every `driver.ScrollView`) and starts a new coordinate space; a nil peer panics. Chained `SetDocument` and `SetScrolls(axis, on)` (the public layer keeps these in sync with the peer's scrollers), getters `Document`, `Scrolls`, `Peer`.
  * *Measure*: only its `Props` (for example a min width of 180); 0 without a min. The document is never measured here.
  * *Arrange*: (1) frames the peer, (2) reads `ViewportSize` (bad components count as 0), (3) measures the visible document unbounded on each scrolling axis and at the viewport size on the others, (4) calls `SetDocumentSize` with max(measured, viewport) on scrolling axes and the viewport on the others, (5) arranges the document at (0, 0, documentSize).
  * *Expands*: only the own flag, never the document's (the public layer's default expansion handles scroller axes).

Invariants: nodes are used on the UI thread only, live as long as their widgets, and call only `FittingSize` and `SetFrame` on leaves, plus `ContentInsets`, `ViewportSize` and `SetDocumentSize` on Box and ScrollView peers. The public layer mirrors hidden state and the scroll axes into the nodes.

## 7. `internal/render`: drawing vocabulary and the recorder

The vocabulary the aqua elements hand to a canvas (PLAN.md §5.3): value types, the `Canvas`, `TextSystem` and `TextLayout` interfaces, and the recording backend `render/record`. Depends only on `internal/driver`; no build tags.

* **Geometry and colors** are aliases: `Point`, `Size`, `Rect` and `Color` are the `driver` types (float64 logical points, top-left origin, Y down; straight-alpha colors). Backends narrow to float32 only at the native call. Angles are radians, positive turning clockwise on screen.
* **`Radii`**: one radius per corner (`TopLeft`, `TopRight`, `BottomRight`, `BottomLeft`), `UniformRadii`, `IsZero`, `IsUniform` (for D2D's single-radius call).
* **`Paint`**: `PaintSolid` (`Color`) or `PaintLinear` (`Start`, `End` in user space, `Stops` of `GradientStop{Offset, Color}`, pad extend mode); `Solid`, `LinearGradient` (copies the stops). The zero value is solid transparent black.
* **`StrokeStyle`**: `LineCap` (butt/round/square), `LineJoin` (miter/round/bevel), `MiterLimit` (default 10), `Dash` (dash/gap lengths starting with a dash) and `DashOffset`. The zero value is a solid butt/miter line.
* **`Shadow`**: `Offset`, `Blur` (σ = Blur/2), `Spread` (may be negative), `Color`, `Inset`, with CSS box-shadow semantics (outer shadows only outside the shape, inset ones only inside).
* **`Path`** (zero value ready): `MoveTo`, `LineTo`, `QuadTo`, `CubicTo`, `ArcTo` (tangent arc as in HTML canvas, stored as at most two cubics; a line to p1 when the radius is not a positive finite number or the points are collinear), `Close`, `Reset`, `Len`, `Empty`, `Current`. HTML canvas subpath rules: a drawing call without a current point first moves to its first point, and after `Close` the next drawing call starts a new subpath at the closed start, so every subpath a backend sees starts with `OpMoveTo`. `Segments()` is an `iter.Seq[Segment]` of `{Op, Pts [3]Point}` (M, L, Q, C, Z). `Bounds()` is tight: on-path points and curve extrema, no control points, no stroke width.
* **`Transform`**: 2×3 affine in the SVG/D2D layout (`A B C D E F`). The zero value is not the identity; `Identity`, `Translation`, `Scaling`, `Rotation`. `t.Then(u)` applies t first, `t.Pre(u)` applies u first (what a canvas's `Translate`/`Scale` use), `Det`, `Invert` (false for singular or non-finite results), `IsIdentity`, `IsTranslation`, `Apply`, `ApplyVector`, `ApplyRect` (bounding box).
* **`Image`**: an interface with only `Size()`.
* **Validation (`validate.go`)** is applied by backends and the recorder before drawing, never by constructors: `Radii.Clamped(r)` (negative/NaN → 0, at most half the shorter side, zero for an empty rect), `StrokeWidth` (negative/NaN → 0), `Paint.Normalized` (stops clamped to [0, 1] and stably sorted into a new slice, non-finite end points → 0, solid paints drop `Stops`, unknown kinds become solid), `StrokeStyle.Normalized` (unknown cap/join → default, miter limit < 1, NaN or +Inf → 10, negative/NaN/Inf dash entries → 0, all zeros → solid, odd lengths repeated, a fresh dash slice), `Shadow.Normalized` (negative/NaN/Inf blur → 0, non-finite offset and spread → 0), `Opacity` (clamped to [0, 1], NaN → 0) and `BlurRadius` (negative/NaN/Inf → 0).
* **Semantic colors** must not reach a canvas: `Paint.IsSemantic` (gradient stops included) and `Shadow.IsSemantic` let the recorder fail the test.

### 7.1 `Canvas` (`canvas.go`)

Used on the UI thread during one paint call, not safe for concurrent use.

* **State:** transform, clip and opacity. At the start of a paint: identity in logical points (the backend applies the surface scale underneath), the whole surface as clip, opacity 1. `Save`/`Restore` push and pop it; `PushOpacity` and `PushBackdropBlur` also push it and `Pop` restores it, so a transform or clip set inside a layer ends with it. `Translate`, `Scale` and `Concat(Transform)` act in user space (`Transform.Pre`); `ClipRoundedRect` intersects the clip.
* **Balance:** `Save`/`Restore` and `Push*`/`Pop` nest strictly with each other (`Restore` closes a `Save`, `Pop` a `Push*`), and everything is closed before the paint returns. A violation is a bug: the recorder reports it, backends ignore the call.
* **Values:** the canvas applies the validation rules itself, so callers pass values as built. A semantic color or a non-finite `Translate`/`Scale`/`Concat` argument is a bug (recorder error; backends skip the call).
* **Drawing:** `FillRoundedRect`, `StrokeRoundedRect` (centered on the outline), `FillPath` (nonzero winding, open subpaths closed; nil is empty), `StrokePath`, `DrawShadow` (only the shadow), `DrawText(l, origin, color)` (origin is the layout's top-left; the first baseline is at `origin.Y + l.Baseline()`), `DrawImage(img, dst)`. `PushOpacity(alpha)` composes the layer and draws it with group opacity; `PushBackdropBlur(r, radii, radius)` blurs what is behind the shape (σ = radius/2) and clips the layer to it.

### 7.2 `TextSystem` and `TextLayout` (`text.go`)

* `Font` aliases `driver.Font`; a zero size means 13 pt.
* `TextSystem.NewLayout(text, font, maxWidth)`: lines break at `'\n'` and wrap at word boundaries when `maxWidth` is positive and finite (0, negative, NaN, +Inf: no wrapping). The shell provides it (`Shell.TextSystem()`); the fixed-width one is `shell/fake.TextSystem`.
* `TextLayout` is immutable, geometry relative to its top-left: `Text`, `Font`, `Size` (widest line × sum of line heights; empty text is one line high), `Baseline` (first line), `LineCount` (≥ 1), `HitTest(p)` (nearest cluster start and whether p is in its trailing half; points outside snap to the first/last line and the line's first/last cluster; past a line's end the index is that end with trailing false), `CaretRect` (zero width, line height), `SelectionRects(start, end)` (either order, one rect per line, empty when equal).
* Indices are UTF-8 byte offsets into `Text()`; an index inside a cluster moves back to its start; one outside `[0, len]` is clamped.

### 7.3 `render/record`: the recording canvas

`record.New(size)` returns a `*Canvas` implementing `render.Canvas` for a surface of `size` logical points. Standard library, `render` and `driver` only.

* **Ops:** every drawing and layer call becomes an `Op` (`Kind`: `FillRoundedRect`, `StrokeRoundedRect`, `FillPath`, `StrokePath`, `DrawShadow`, `DrawText`, `DrawImage`, `PushOpacity`, `PushBackdropBlur`, `Pop`) with normalized values, a copy of the path's segments, and the resolved state: `Transform`, `Clip` (device-space bounding box; rounded corners are not tracked) and `Opacity` (product of enclosing opacity layers). Push ops carry the state outside the new layer, `Pop` the state it restores. `Save`, `Restore`, transforms and clips record nothing themselves. `Op.Bounds()` is the device-space box of the geometry. `Ops()` returns a copy; recorded values never alias the caller's slices.
* **Contract checks:** calls are numbered from 1 and violations are collected as errors `record: call N (Name): …` instead of panicking: `Restore`/`Pop` with nothing open or with the other kind innermost, semantic colors, nil layouts and images, non-finite transform arguments, calls after `End`. The offending call is ignored. `End()` adds one error per pair still open (innermost first) and returns all errors joined; a second `End` is an error. `Errors()` and `Depth()` inspect the state.
* **Dump:** `Dump()` (lines joined by `\n`, no trailing newline) and `Lines()`, e.g. `fillRRect (0,0,80,22) r=5 solid #007aff`. Numbers rounded to 3 decimals (no trailing zeros, -0 as 0); a pure-translation transform is folded into the printed geometry, any other prints as `xf=(a,b,c,d,e,f)`; radii `r=5` or `r=tl/tr/br/bl` (omitted when zero); colors `#rrggbb[aa]`; paints `solid #…` or `linear (x0,y0)->(x1,y1) [off:#… …]`; stroke cap/join/miter/dash, shadow spread/inset, font family, weight, italic and mono only when not the default; `clip=(…)` when the clip is not the whole surface, `alpha=` when the effective opacity is not 1. `Op.String()` formats one op without its clip. The full format is in `dump.go`.

## 8. `internal/shell`: the OS boundary of the aqua driver

Interfaces and value types only (`doc.go shell.go surface.go event.go clock.go`), no behaviour and no tests of its own; compile-time checks pin every event type to `Event`. Depends only on `internal/driver` and `internal/render`; no build tags. Implementations: `shell/fake` (§8.1), `shell/win32` (§8.2–8.3) and `shell/gtk4` (§8.5; no surfaces yet). The per-OS selection is `internal/shell/native`: `native.New() (shell.Shell, error)` returns `win32.New()` on Windows, `gtk4.New()` on Linux (S4.1d) and `ErrNotImplemented` elsewhere (a platform package, so build tags are allowed; the error is declared untagged). `gogui`'s `driver_other.go` selects the aqua driver over it.

* **Shared contracts:** every value is in logical points with a top-left origin, relative to the surface's drawable area (the whole client area, including the title bar aqua draws); the surface reports its `Scale` and backends apply it. Every method and handler call is on the UI thread except `Shell.Post`. Modifiers in events are physical (`ModPrimary` never appears; `ModOption` = Alt, `ModCommand` = Win/Super). Event times and frame times share the `FrameClock.Now` timeline. The shell never calls Go per `WM_NCHITTEST` (chrome regions) and paints at most once per frame.
* **`Shell`:** `Run(Handler)` on the locked main thread (`Ready` once; returns nil after `Quit` or an error such as "GTK missing"; only once), `Quit` (closes open surfaces with `Closed`, no `CloseRequested`), `Post` (any goroutine, FIFO, coalesced wake, the `driver.Driver.Post` contract), `NewSurface(cfg, h)` (hidden), `TextSystem()`, `Appearance()` (the OS setting only; forcing light/dark is the aqua driver's job), `Clock()`. `Handler`: `Ready`, `AppearanceChanged(a)`.
* **`SurfaceConfig`:** `Title` (native title for taskbar/Alt-Tab; aqua draws the visible one), `Size` (drawable area, title bar included, unlike `driver.WindowConfig.Size`), `MinSize`/`MaxSize` (zero = no limit), `Style` (`driver.WindowStyle`; without `StyleResizable` no resize, maximize or Snap), `Center`.
* **`Surface`:** `SetTitle`, `Size`/`SetSize` (clamped, `Resized` before returning), `SetMinSize`/`SetMaxSize` (resize if violated), `Scale` (valid from `NewSurface`), `Center`, `Show` (front and key), `Minimize`, `Zoom`/`Zoomed` (the green button), `Close` (no `CloseRequested`, then `Closed`; idempotent; the last surface closing does not quit), `Invalidate` (whole surface, requests a frame, one `Paint` per frame), `SetCursor(Cursor)`, `SetChromeRegions([]ChromeRegion)`. Dead after `Closed`: every method does nothing.
* **Chrome regions:** `{Rect, Kind}` with `RegionClient`, `RegionCaption` (HTCAPTION: a primary press moves the window, a double-click maximizes; these presses are not delivered) and `RegionClose`/`RegionMinimize`/`RegionMaximize` (the traffic lights; their pointer events are delivered normally and aqua calls `Close`/`Minimize`/`Zoom` itself; `RegionMaximize` gives Windows 11 Snap Layouts). Tested last to first, first hit wins, no hit is client; so the title bar goes first, then the menu titles as client (PLAN.md §5.4.1), then the buttons. Copied; nil = all client; the shell's resize borders win.
* **`SurfaceHandler`:** `Paint(render.Canvas)` (logical points, `Size()` large, balanced, draw only; `Invalidate` allowed), `Resized(size, scale)` (not for the initial values; the shell invalidates and, in a live resize, paints before returning to the OS), `CloseRequested() bool` (Alt+F4, taskbar, logout; aqua's own close button calls `Close`), `Closed` (once), `KeyChanged(bool)`, `Event(Event) bool`.
* **Events** (a closed set: `EventTime()` plus an unexported marker):

  * `ScrollEvent{Pos, Delta, Precise, Phase, Momentum, Mods, Time}`: natural-scrolling direction applied, positive Y moves the content down; points when precise, lines otherwise; gesture phases began/changed/ended, OS momentum phases after them on GTK, none on Windows (aqua runs its own); wheel notches have no phase.

### 8.1 `shell/fake`: the test shell

`fake.New()` returns a `*Shell` implementing `shell.Shell` without an OS; the aqua tests run on it. No build tags.

* **Loop:** `Post` goes to a `mainthread.Queue` (`Queue()` exposes it); work posted before the start waits, after `Quit` it is dropped. `Run(h)` binds the calling goroutine, calls `Ready` and drains until `Quit` (work queued before `Quit` runs once, open surfaces are closed; a panic propagates and closes the queue). `Start(h)` binds and calls `Ready`, then returns: the test drives the shell with `Step()` (one non-blocking `Drain`), `Flush()` (run the requested frame now) and `FakeClock().Advance(d)`. A second `Run`/`Start` returns `ErrRunTwice`. Neither runs frames by itself.
* **Checks:** every method except `Post` panics off the UI goroutine; `NewSurface`/`TextSystem`/`Appearance`/`Clock` panic before `Ready`; resizing, showing, closing or creating surfaces, input and `Quit` panic during `Paint`; `ModPrimary` in an event, key input to a surface that is not key, and bad buttons panic.
* **Clock** (`Clock`, also standalone via `NewClock`): time starts at 0 and moves only with `Advance(d)`, which runs each requested frame at the next multiple of `FrameInterval` (1/60 s) up to `Now+d` (an animation that re-requests gets one frame per interval) and returns the count; `Flush()` runs one requested frame at `Now`. A frame is the frame function, then one `Paint` of each invalidated, visible, not minimized surface in creation order. `Requested()`, `Frames()`; `Advance`/`Flush` from inside a frame panic.
* **Surfaces:** start hidden and invalidated, sized by the config clamped to the limits (zero = none, min over max), at the screen scale. They record `Title`, `Size`, `MinSize`/`MaxSize`, `Style`, `Scale`, `Centered()` (a count), `Visible`, `Minimized`, `Zoomed`, `IsKey`, `Cursor`, `ChromeRegions` (copied) and `Closed`. `HitTest(p)` answers like the real shells (last to first, else client; no resize borders). `Show` makes key (and restores), `Minimize` drops key, `Activate`/`Shell.Deactivate` simulate focus changes, `Zoom` toggles between `SetScreen`'s size (default 1440 × 900) and the old size, `SetScale` simulates a monitor move, `UserResize` (needs `StyleResizable`) paints before returning, `UserClose` asks `CloseRequested`. `Resized` comes before the setter returns and only on a change. Each paint gets a fresh `record.Canvas` of the current size: `Paints()`, `LastPaint()`, `Dump()`, `PaintErr()`. Closed surfaces keep their state readable and ignore every call.
* **Input helpers** (dropped for hidden, minimized or closed surfaces; times from the clock): `Move`, `Press`, `Release`, `Click`, `ClickButton`, `DoubleClick`, `Drag` produce enter (plus a move) before the first move inside, leave on exit, implicit capture while a button is held (leave after the last release outside), and click counts (same button within `DoubleClickTime` 500 ms and `DoubleClickDistance` 4 pt; advance the clock to separate clicks). A primary press on `RegionCaption` is not delivered (a double-click there zooms). `CancelCapture` sends up for each held button. `SetModifiers` sets pointer/scroll modifiers. `Wheel` (lines, no phase), `Swipe` (precise, began/changed…/ended with a zero delta, as on Windows), `Momentum` (OS momentum phases, as on GTK), `TimedSwipe(p, interval, deltas…)` (S3.5c: the clock advances by interval between the deltas, running the frames due, and the zero-delta `PhaseEnded` comes `SwipeEndDelay`, 100 ms as Win32's gesture timeout, after the last; it stops early when a frame closes, hides or minimizes the surface; panics for a negative interval). `KeyDown`, `KeyRepeat`, `KeyUp`, `Key` (normalized keys, return `handled`); `Type(text)` per rune: key-down (upper case holds Shift, `\n`/`\t`/`\b` are Return/Tab/Backspace without text), `TextEvent` unless handled, key-up, stopping when a handler closes the surface or moves the focus; `Commit` (one `TextEvent`, no keys); `Send(ev)` for raw events (zero time filled in).
* **Text** (`TextSystem`, stateless): every rune is one cluster `RuneWidth(f)` wide (7 pt at 13 pt) and every line `LineHeight(f)` high (16 pt), both from `driver/stub`, so unwrapped text measures as the stub's labels; baseline at 3/4 of the line. Wrapping is greedy: break after the last space run starting within the fitting runes (spaces hang and do not count), else between runes (at least one per line); lines have their real widths. Carets at a break go to the next line's start; hit-testing right of a wrapped line returns the index before its hanging space; a selected `\n` shows as one rune width.

### 8.1a `shell/shellkit`: shared shell logic

Pure Go, no build tags, no OS calls (S4.1a): the parts of a native shell that only compute, moved out of `shell/win32` so `shell/gtk4` reuses them and their tests run on every host. Depends only on `internal/driver` and `internal/shell`.

* **Event times:** `EventTimeAt(now, tick, evTime)` maps an OS event time (uint32 ms, wrapping) onto the clock: `now` minus the age `tick - evTime`; an age beyond `MaxEventAge` (5000 ms, also a time "from the future") gives `now`; never negative. `Monotonic.Next(t)` keeps the times a shell hands out from going backwards.
* **Click counts:** `ClickCounter.Press(b, p, t, rules, atLeast2)`: the next click when the button is the same, `t` is within `ClickRules.Time` of the previous press (uint32 difference, so across the wrap) and `p` (`Point`, device pixels) within half of `ClickRules.W` × `H` on each axis; otherwise 1. `atLeast2` (a Windows `DBLCLK`) makes it at least 2. `Reset` starts over (a caption press).
* **Scroll gestures:** `Gesture.Next(precise)` returns whether an event is precise and its phase: inside a gesture every event is precise and `PhaseChanged`; a precise one outside begins it (`PhaseBegan`); else `PhaseNone`. `End` ends it and reports whether one was active (the shell then sends `PhaseEnded`).
* **Sizes:** `ToPx(v, scale)` rounds half away from zero, clamped to [0, `MaxPx` = 2²⁰], NaN 0. `FromPx(w, h, scale, hint)` returns `hint` per axis when it converts to the same pixels, so fractional sizes round-trip. `ClampSize(size, min, max)`: zero = no limit, min wins over max, NaN and negatives to 0.
* **Placement:** `CenterIn(work Rect, w, h)` centers a `w × h` rectangle in `work` (device pixels; a larger one starts at its corner). `Rect` and `Point` convert directly from `w32.Rect`/`w32.Point`.
* **Regions:** `HitRegion(regions, pos)` tests the chrome regions from last to first and returns the first kind containing `pos` (`driver.Rect.Contains`: right and bottom edges outside, NaN nowhere); `ok` false means client. The shell maps the kind to its own code and checks its resize borders first.

### 8.2 `shell/win32/w32`: raw Win32 bindings

`//go:build windows`. The bindings the Windows shell calls, so `shell/win32` makes no raw syscalls of its own. Only the shell imports it.

* **Procs** (`procs.go`): user32 (window class and lifecycle, message loop, `PostMessageW`, `Get/SetWindowLongPtrW`, placement and monitors, DPI and metrics, `SystemParametersInfoW`, capture, cursor, keyboard layout, `BeginPaint`/`EndPaint`, `InvalidateRect`, `UpdateWindow`, timers, `MsgWaitForMultipleObjectsEx`, `PrintWindow`, `FindWindowExW`), gdi32, dwmapi (`DwmExtendFrameIntoClientArea`, `DwmGetColorizationColor`, `DwmGetCompositionTimingInfo`), shcore (`GetDpiForMonitor`), kernel32 (module handle, `SetLastError`, `GetTickCount`, waitable timers, `QueryPerformanceCounter`/`Frequency`) on `windows.NewLazySystemDLL` (System32 only). Every proc is declared through `newProc`, which records it in `allProcs`. `x/sys/windows` supplies `HWND`, `Handle`, `GetCurrentThreadId`, `DwmSetWindowAttribute` and the `registry` package. Every proc exists on Windows 10 1809 (D7).
* **Constants** (`consts.go`): SDK names for window and class styles, messages, hit-test codes, `MK_*`, `TME_*`, `PM_*`, `SW_*`, `SWP_*`, monitor and DPI values (`DPI_AWARENESS_CONTEXT_*` as pseudo-handles, `HWND_MESSAGE`), `SM_*`, `SPI_*`, `IDC_*`, `MAPVK_*`, the virtual keys the shell needs, the two DWM attributes, wait and timer constants.
* **Structs** (`types.go`): `Point`, `Size`, `Rect`, `Msg`, `WndClassEx`, `MinMaxInfo`, `WindowPos`, `NCCalcSizeParams`, `TrackMouseEventInfo`, `MonitorInfo`, `Margins`, `CreateStruct`, `PaintStruct`, `HighContrast`, `WindowPlacement`, `BITMAPINFOHEADER`. Native pointers are `uintptr`, handles `windows.HWND`/`windows.Handle`. Every layout is pinned by `ffi.CheckLayout` and `CheckNoGoPointers` with one table for amd64 and arm64 (both LLP64). Structs that arrive as an `lParam` are read with `ffi.At[T]`.
* **Wrappers** (`w32.go`): typed functions that set `cbSize`-style fields, convert strings to UTF-16 and return an error wrapping the `windows.Errno` (from `GetLastError`, or the HRESULT for dwmapi and shcore). `RegisterClassEx` pins the class-name buffer for the call and clears `LpszClassName` afterwards, so no Go pointer stays in the struct. `RegDWORD` (`reg.go`) reads an HKCU DWORD; a missing key or value wraps `ERROR_FILE_NOT_FOUND`. Special cases:
  * `GetWindowLongPtr`/`SetWindowLongPtr` call `SetLastError(0)` first and fail only for a 0 result with a non-zero last error (0 is a valid value). The Go runtime clears and reads the last error inside its syscall stub, so the value belongs to the call.
  * `GetMessage` returns `(true, nil)` for a message, `(false, nil)` for `WM_QUIT` and `(false, err)` for -1.
  * `DwmSetWindowAttributeInt` fails with `E_INVALIDARG` for an attribute Windows doesn't know (`DWMWA_WINDOW_CORNER_PREFERENCE` on Windows 10); the caller ignores it.
  * `MonitorFromPoint` and `WindowFromPoint` pass the `POINT` by value packed into one register.
  * `MsgWaitForMultipleObjectsEx` keeps its handle slice alive over the call; `WAIT_FAILED` is an error. `CreateWaitableTimer` (`CreateWaitableTimerExW`, high-resolution or standard, auto-reset), `SetWaitableTimer` (relative, 100 ns units), `CancelWaitableTimer`.
  * `DwmGetCompositionTimingInfo` (desktop timing, hwnd NULL) returns `CompositionTiming` (refresh period and vblank in QPC ticks). `DWM_TIMING_INFO` is `#pragma pack(1)` with unaligned 64-bit fields, so it is read from a 292-byte buffer at fixed offsets (12, 28) instead of being mirrored.
* The calls that take an `HWND` must run on the window's thread; the package doesn't check.

### 8.2a `shell/win32/com`: the COM core

The base of the D3D11, DXGI, DComp, D2D and DirectWrite bindings. `guid.go`, `hresult.go` and `vtable.go` are untagged (pure, tested on every OS); the rest is `//go:build windows`.

* **`Ptr`** is an interface pointer (a `uintptr`, the address of a native object whose first word is its vtable). A non-zero `Ptr` held by Go code owns one reference. `Slot(i)` reads the code address of vtable slot `i` through `ffi.ReadUintptr` (panics on a nil `Ptr`). `AddRef`, `Release` (takes `*Ptr`, clears it; a nil `Ptr` is a no-op, so it can be deferred) and `QueryInterface` (returns a new reference; a missing interface wraps `E_NOINTERFACE`). `RefCount` (an `AddRef`/`Release` pair) is for tests. No finalizers.
* **Integer call path:** `Call(i, args...)` and `CallHR(op, i, args...)` call slot `i` with `p` as `this` through `syscall.SyscallN` (`//go:uintptrescapes`, so a Go pointer converted in the call expression stays alive and in place).
* **Float call path:** `Bind(fptr, p, i)` sets a Go func variable to a `purego.RegisterFunc` wrapper of slot `i`; `BindFunc(fptr, addr)` does the same for a flat export. purego places floats by the C ABI: positionally on windows/amd64 (it calls `syscall.SyscallN`, which loads XMM0–3 there), and through its own trampoline with the float registers and HFAs (`D2D1_POINT_2F`) on windows/arm64, where `syscall.SyscallN` loads only integer registers. Bound funcs are cached by func type and code address, so objects of one class share an entry. `Method[F]` is a binding's per-method cache of the last bound func per code address (an atomic pointer), so a hot call skips `Bind`'s lock and map. Rejected as errors (func variable unchanged): nil `this`, a negative slot, a first parameter that isn't uintptr-kind, a Go func parameter, a variadic or func result (purego would create a native callback, which `check.sh`'s guard and §7.2 forbid), and a struct result (MSVC returns those through a hidden pointer after `this`, which purego doesn't know; bindings declare that out pointer instead).
* **`Vtable`/`CheckSlots`** (`vtable.go`): the slot-table check of the binding packages (`Extend` builds a table from the parent interface; `CheckSlots` reports a wrong index, missing method or duplicate name).
* **`GUID`** mirrors the SDK struct (16 bytes, 4-aligned). `ParseGUID` reads the SDK string form (braces optional, either case), `MustGUID` panics for package-level IIDs, `String` prints the braced upper-case form. `IID_IUnknown` is predeclared.
* **`HRESULT`** (`int32`) implements `error`: `Failed`, `Succeeded`, `Facility`, `Code`, and `Error` as `NAME (0x…)` for the named codes (common `E_*`, `E_NOT_SUFFICIENT_BUFFER`, `RPC_E_CHANGED_MODE`, `CO_E_NOTINITIALIZED`, `REGDB_E_CLASSNOTREG`, DXGI's device-loss and call errors, `D2DERR_RECREATE_TARGET`, `DWRITE_E_FILEFORMAT`), otherwise with facility and code. `hr.Err(op)` returns nil or an `*Error{Op, HR}` that unwraps to the `HRESULT`, so `errors.Is(err, com.E_…)` works.
* **Apartment:** `InitUIThread` calls `CoInitializeEx(COINIT_APARTMENTTHREADED | COINIT_DISABLE_OLE1DDE)` and returns the matching `CoUninitialize` (also for `S_FALSE`); an MTA thread fails with `RPC_E_CHANGED_MODE`. `win32.Shell.Run` calls it right after `LockOSThread`. `CreateInstance(clsid, iid)` is `CoCreateInstance` with `CLSCTX_INPROC_SERVER`.

### 8.2d `shell/win32/dwrite`: the DirectWrite bindings

A `//go:build windows` package on `com` with d2d's rules. Text crosses as UTF-16 (`[]uint16`); the UTF-8 conversion and index map are the shell's. Files: `dwrite.go`, `fonts.go`, `types.go`.

* **Factory:** `CreateFactory()` calls `DWriteCreateFactory(SHARED, IDWriteFactory)` and queries `IDWriteFactory5`; without it the error wraps `ErrNoFactory5`, naming Windows 10 1703 (D7). The shared factory is one object per process: every call adds a reference. `Factory` holds the `IDWriteFactory5` pointer and binds `IDWriteFactory`'s `GetSystemFontCollection` (slot 3), `CreateTextFormat` (15) and `CreateTextLayout` (18).
* **`TextFormat`:** `SetWordWrapping`, `SetTextAlignment`, `SetParagraphAlignment` and their getters (out-of-range values fail with `E_INVALIDARG` and change nothing), `FontWeight`, `FontStyle`, `FontStretch`, `FontFamilyName`, `FontSize`. A family the collection lacks is no error at format time.
* **`TextLayout`** embeds `TextFormat`: `MaxWidth`, `MaxHeight`, `Metrics` (`DWRITE_TEXT_METRICS`, slot 60), `LineMetrics` (slot 59; asked first with an empty buffer whose `E_NOT_SUFFICIENT_BUFFER` carries the count), `SetMaxWidth` (slot 28; negative or NaN refused), `ClusterMetrics` (62), `HitTestPoint` (64, returns `PointHit`: `Trailing`, `Inside`, the cluster's `HitTestMetrics`), `HitTestTextPosition` (65), `HitTestTextRange` (66, one box per line the range touches, offset by an origin). `LineMetrics`, `ClusterMetrics` and `HitTestTextRange` share `fetchArray`, the "buffer too small" retry. `CreateTextLayout` passes a terminated copy, so empty text has a valid address; DirectWrite copies the text. * **Measured behaviour the shell relies on:** `\r\n` is two clusters (only the `\n` has `IsNewline`; the line's `NewlineLength` is 2); a base letter with a combining mark and a surrogate pair are one cluster of 2 units; the text's last cluster always has `CanWrapLineAfter`; points outside the text give the nearest position with `Inside` false; empty text has no clusters, the caret at (0, 0) and one empty range box. "Hello" in Segoe UI at 13 DIPs is 29.94 × 17.29 (1.33 × size), baseline 14.03.
* **In-memory fonts (`fonts.go`):** `Factory` binds `RegisterFontFileLoader`/`UnregisterFontFileLoader` (13/14), `CreateFontCollectionFromFontSet` (37), `CreateFontSetBuilder` (`IDWriteFactory5`'s `IDWriteFontSetBuilder1` overload, 43) and `CreateInMemoryFontFileLoader` (44). `InMemoryFontFileLoader.CreateFontFileReference` passes no owner object, so DirectWrite copies the bytes and no Go memory is held natively (empty data is a Go error). `FontFile.Analyze` (unsupported data is `Supported` false, no error), `FontSetBuilder.AddFontFile` (bytes that are no font: `DWRITE_E_FILEFORMAT`) and `CreateFontSet`, `FontSet.FontCount`, `FontCollection.FindFamilyName` (case-insensitive; index and whether it exists). `Factory.CreateMemoryFonts(files)` builds one collection from several files and returns a `*MemoryFonts` (`Collection`, plus the registered loader and a factory reference); an unusable file or no font (`ErrNoFonts`) is an error with everything released. `MemoryFonts.Release` releases the collection, unregisters and releases the loader and drops the factory reference; it is idempotent and nil-safe. **Invariant:** the loader stays registered while any collection, format or layout from its files lives; a layout after `UnregisterFontFileLoader` kills the process (measured). The first in-memory layout in a process leaves three factory references in DirectWrite's caches.
* **Float path:** `CreateTextFormat` (the FLOAT size between integer arguments), `CreateTextLayout` (two FLOATs), `SetMaxWidth`, `HitTestPoint` (two FLOATs before pointers), `HitTestTextRange` (two FLOATs between integers and pointers) and the FLOAT results of `GetFontSize`, `GetMaxWidth`, `GetMaxHeight`, each through a `com.Method`.
* **Structs:** `TextMetrics` (36 bytes), `LineMetrics` (24, `IsTrimmed` a BOOL), `HitTestMetrics` (36, `IsText`/`IsTrimmed` BOOLs), `ClusterMetrics` (8: `Width`, `Length` and five UINT16 bit fields as `Flags`, LSB first in declaration order, read by mask), with layout tests.
* **Vtables:** `IDWriteFactory` (24 entries) to `IDWriteFactory5` (48, from `dwrite_1.h`–`dwrite_3.h`, overloads in MSVC's reverse order), `IDWriteFontCollection` (7), `IDWriteTextFormat` (28), `IDWriteTextLayout` (67), `IDWriteInMemoryFontFileLoader` (6), `IDWriteFontFile` (6), `IDWriteFontSetBuilder1` (8), `IDWriteFontSet` (13).

### 8.3 `shell/win32`: the Windows shell

`win32.New()` returns a `*Shell` implementing `shell.Shell`; `shell/native` selects it, so `gogui` apps on Windows run on it. Every file except `doc.go` is `//go:build windows`.

* **Run:** locks the goroutine to its OS thread, makes the thread a COM STA (`com.InitUIThread`; `CoUninitialize` on the way out), binds the `mainthread.Queue`, sets Per-Monitor-V2 DPI awareness (`ERROR_ACCESS_DENIED` from an earlier call or a manifest is accepted only if the thread's context then equals Per-Monitor-V2), registers the one window class `gogui.win32` once per process (`CS_DBLCLKS`), creates the **listener**, reads the appearance, installs the wake, creates the clock's hold timer, calls `Ready` and runs the loop until `Quit`: each round is the clock's `wait` (a due frame, or `MsgWaitForMultipleObjectsEx` on the clock's handles and the queue), then one `PeekMessageW(PM_REMOVE)`/`TranslateMessage`/`DispatchMessageW`. On the way out the queue is drained once (work posted before `Quit`), closed, and the listener destroyed, also when Run ends in a panic. A second `Run` returns `ErrRunTwice`; a foreign `WM_QUIT` acts as `Quit`.
* **Listener:** a hidden `WS_POPUP` tool window (`WS_EX_TOOLWINDOW|WS_EX_NOACTIVATE`), not a message-only window, because message-only windows get no broadcasts and the appearance needs `WM_SETTINGCHANGE`, `WM_THEMECHANGED` and `WM_DWMCOLORIZATIONCOLORCHANGED` with no surface open. It handles the private `msgWake` (drain) and `msgFrame` messages and the modal frame timer.
* **Post and wake:** `Post` is `Queue.Do`; the queue's wake is one `PostMessageW(msgWake)` per drain, so wakes stay coalesced however many goroutines post. `Queue()` exposes the queue; its `SetChecks` also turns on the shell's UI-thread checks.
* **Window procedure** (`wndproc.go`): one `ffi.RegisterCallback("win32.wndproc", …)`, created with the class. `WM_NCCREATE` copies `CREATESTRUCTW.lpCreateParams` (an `ffi.Handle`) into `GWLP_USERDATA`; every message looks the handle up in the package's `ffi.Handles[target]` and calls `target.handle`, or `DefWindowProcW` for 0, stale or unhandled. `WM_NCDESTROY` frees the handle. A panic in a target is recovered at the trampoline (it must not unwind through native frames; the message returns 0) and kept as a `*PanicError` (value, message, stack); the loop re-raises it after `DispatchMessageW`, and Go code that sends messages calls `rethrow`.
* **Appearance** (`appearance.go`): `Dark` from `Personalize\AppsUseLightTheme` = 0; `Accent` from `DWM\AccentColor` (ABGR), else `DwmGetColorizationColor` (ARGB), else `driver.DefaultAccent`, always opaque; `IncreaseContrast` from `HCF_HIGHCONTRASTON`; `ReduceMotion` from `SPI_GETCLIENTAREAANIMATION` off; `ReduceTransparency` from `Personalize\EnableTransparency` = 0; `LegacyScrollers` from `Accessibility\DynamicScrollbars` = 0. Missing values give defaults. Readings go through a `sysReader` the tests replace. The broadcasts re-read it and call `AppearanceChanged` only on a change.

#### Text system (`text.go`, `textindex.go`, `textgeom.go`)

`Shell.TextSystem()` is a `*textSystem` made with the shell and used on the UI thread (`NewLayout` checks it). The DirectWrite factory and the system collection are created with the first layout and released in `shutdown`; a failure there, or a layout after release, falls back to `shell/fake`'s fixed-width layouts, logged once, so text never takes the application down.

* **Fonts:** `resolve` maps a `render.Font` to a `fontKey` (family, collection, size, weight, italic). Empty family: Inter from the embedded collection, else `Segoe UI Variable Text` (Windows 11) or `Segoe UI`; `Monospaced`: Consolas (Courier New if missing). A named family is looked up in the embedded, then the system collection (case-insensitive), else it falls back as for empty; `Family` wins over `Monospaced`. Size 0 is 13; sizes clamp to 0.1…2048, weights to 1…999. `TextFormat`s are cached per key (at most 128, then emptied) and live until shutdown; the wrap mode is set on each layout, never on the shared format.
* **Embedded fonts:** `init` builds one in-memory collection, once, from every file of `assets/fonts` (`fonts.Files`) through `dwrite.CreateMemoryFonts`. With no files, or when any file fails (corrupt, truncated, empty, not a font), there is no embedded collection: the UI font is the system's, and the reason (file names and error) is logged once through `debugf` (`log.Printf` only with `GOGUI_DEBUG=1`). `release` frees the `MemoryFonts` after the formats, because DirectWrite reads the files through the loader while anything from the collection lives. Test hooks: `fontFiles` (the file source) and `embeddedUI` (the family the empty family resolves to, `Inter`).
* **Layouts** are measured once in `NewLayout`, in DIPs with natural measuring, and kept as Go data (`layout`: text, font, `indexMap`, size, first baseline and line height, line count). The native `IDWriteTextLayout` is released at once, because `TextLayout` has no `Release` and nothing relies on finalizers (§7.2 of PLAN.md); drawing rebuilds one from text, font and width (`textSystem.native`). A positive finite `maxWidth` wraps (`WORD_WRAPPING_WRAP`); zero, negative, NaN, ±Inf do not (`NO_WRAP`). `Size` is DirectWrite's `Width` (trailing whitespace left out) by `Height`; empty text is one line high.
* **Index map** (`utf16Of`): UTF-8 → UTF-16 with invalid bytes as U+FFFD, one unit per byte; `indexMap.unit` / `byteOffset` move an index inside a rune or surrogate pair back to the rune's start and clamp to the text; ASCII text has the identity map and no tables.
* **Hit-testing, carets and selection** (`textgeom.go`): `NewLayout` also reads line and cluster metrics into a `geometry` (lines with content and break ranges, top and height; clusters with start, left, width and direction), so `HitTest`, `CaretRect` and `SelectionRects` make no native calls. Indices go UTF-8 → UTF-16, are clamped and moved to their cluster's start (combining marks, surrogate pairs and invalid bytes are never split); a line break (`\n`, `\r\n`) counts as one cluster, so an index between `\r` and `\n` is the line's end. Rules beyond DirectWrite's own answers, as in `shell/fake`: right of a line's last cluster `HitTest` gives the line's end with trailing false (before its break; on a line wrapped at whitespace the start of its last whitespace cluster, so the caret stays on that line; on a line broken between clusters the next line's start); the caret at a wrap point is at the next line's start; a selected break shows half an em past the line's end (`newlineWidth`). Points above/below snap to the first/last line, NaN to the first line's start. Left-aligned LTR text places clusters by summing widths; with mixed directions (`MaxBidiReorderingDepth > 1`) each cluster's box and each line's end come from `HitTestTextPosition`, carets sit at a cluster's leading edge in its own direction, and a selection is one rect per line spanning its selected clusters.
* **Drawing** (`canvas.go`): the surface's canvas gets the shell's text system (`canvas.text`); `DrawText` accepts only a `*layout` of that system that is not released and not empty, a concrete non-transparent color and a finite origin, and ignores everything else (nil, `shell/fake` layouts, another system's, semantic colors). The first `DrawText` of a layout in a frame rebuilds its `IDWriteTextLayout` (same text, font and width, so the same lines), cached per layout in `canvas.texts` and released with the frame's other resources; it is drawn with `DrawTextLayout` in the frame's solid brush at the origin under the current transform, clips and layers, with `DRAW_TEXT_OPTIONS_ENABLE_COLOR_FONT`. `newCanvas` sets `TEXT_ANTIALIAS_MODE_GRAYSCALE` (no ClearType fringes). Crispness at every scale comes from the context's DPI; nothing is snapped by hand.

#### Surfaces (`surface.go`)

`NewSurface` (`ErrQuit` after `Quit`; panics during a `Paint`) creates a hidden top-level window of the one class (`WS_OVERLAPPEDWINDOW`, minus `WS_THICKFRAME|WS_MAXIMIZEBOX` without `StyleResizable` and `WS_MINIMIZEBOX` without `StyleMiniaturizable`; `WS_EX_APPWINDOW`, `WS_EX_NOREDIRECTIONBMP`) at `CW_USEDEFAULT`, with the surface's `ffi.Handle` in `lpCreateParams`. It is first sized at the primary monitor's effective DPI (`GetDpiForMonitor`), then again at the window's own (`GetDpiForWindow`), so the initial size gets no `Resized`; `SurfaceConfig.Center` centers it. NUL characters are dropped from titles. The drawable area is the client area, which the custom chrome extends to the top edge of the window.

* **Sizes:** points ↔ pixels through the window's DPI / 96 with `shellkit.ToPx`/`FromPx` (§8.1a: round half away from zero, clamped to [0, 2²⁰]; the size asked for last is returned when it converts to the same pixels, so fractional sizes round-trip). `SetSize` restores a maximized or minimized window, clamps (min wins over max, `shellkit.ClampSize`, as in `shell/fake`), resizes with `SetWindowPos` and reports `Resized` before it returns (also for a sub-pixel change, which sends no `WM_SIZE`). `SetMinSize`/`SetMaxSize` resize only when the current size violates the new limit. `WM_GETMINMAXINFO` always sets the minimum track size (so Windows' own minimum does not apply) and the maximum only for a limit.
* **Resized:** `WM_SIZE` (not while minimized) re-reads the client size and calls `Resized` on a change of size or scale, then invalidates and, when the surface is on screen, paints and presents at once (`UpdateWindow`), so buffers, content and window change in the same message. `WM_DPICHANGED` sets the new DPI, applies the suggested rectangle (with its `WM_SIZE` held back) and makes one `Resized` with the new scale, keeping the logical size when the rectangle has its pixels.
* **Lifecycle:** `Show` (`SW_SHOW`, or `SW_RESTORE` when minimized, then `SetForegroundWindow`, which Windows may refuse), `Minimize` (only when visible), `Zoom`/`Zoomed` (`SW_MAXIMIZE`/`SW_RESTORE`, `IsZoomed`; nothing without `StyleResizable` or while hidden), `Center` (the monitor's work area; not while maximized or minimized). `WM_CLOSE` asks `CloseRequested` and destroys the window on true; `Close` destroys it directly. `WM_DESTROY` marks the surface dead, removes it from the shell and calls `Closed` once; `WM_NCDESTROY` frees the handle. `Quit` sets the quit flag, closes every surface (newest first, with `Closed`, no `CloseRequested`, so a `Closed` handler's `NewSurface` gets `ErrQuit`) and closes the queue. Surfaces a panic left open are destroyed by `Run`'s teardown with no handler calls. A dead surface ignores every method.
* **Key, cursor, regions:** `WM_ACTIVATE` calls `KeyChanged` once per change (and still goes to `DefWindowProcW` for the focus). `WM_SETCURSOR` over `HTCLIENT` sets the cursor of `SetCursor` (`IDC_*`, loaded once; `CursorHidden` is no cursor) and starts `TrackMouseEvent(TME_LEAVE)`; `SetCursor` applies at once while the pointer is over the client area. `SetChromeRegions` keeps a copy for the hit-test.
* **Paint:** `Invalidate` marks the surface and requests a frame; the clock's paint pass (after the frame function) paints every invalidated surface that is visible and not minimized through `InvalidateRect` + `UpdateWindow`, so `WM_PAINT` renders the frame with `Paint` on the D2D canvas. Hidden and minimized surfaces stay invalid and get a frame when shown or restored. `WM_ERASEBKGND` is swallowed. During `Paint`, `NewSurface`, `Quit` and the size-, show- and close-changing methods panic; `Invalidate` is allowed and schedules the next frame.

#### Custom chrome (`chrome.go`, `ncinput.go`)

The windows keep `WS_OVERLAPPEDWINDOW` (taskbar entry, system menu, Snap, minimize/maximize animations), but the native caption is gone.

* **Frame:** `WM_NCCALCSIZE` (both lParam forms) turns the window rectangle into the client rectangle minus the side and bottom resize frame (`SM_CXSIZEFRAME`/`SM_CYSIZEFRAME` + `SM_CXPADDEDBORDER` at the window's DPI, invisible on Windows 10 and 11); the client area reaches the top edge. A maximized window loses the frame on every side and is clipped to the monitor's work area, so its drawable area is exactly the work area. Without `StyleResizable` there is no frame at all. Sizes, limits and `WM_GETDPISCALEDSIZE` (the same logical size plus the frame at the new DPI, so the rectangle `WM_DPICHANGED` suggests keeps the logical size) all use this frame.
* **DWM:** `DwmExtendFrameIntoClientArea` with a 1 px top margin keeps the shadow and border, `DWMWA_USE_IMMERSIVE_DARK_MODE` follows `Appearance.Dark`, and `DWMWA_WINDOW_CORNER_PREFERENCE` asks for rounded corners (default corners in high contrast). Set on creation, on `WM_DWMCOMPOSITIONCHANGED` and for every surface on an appearance change; failures are ignored (Windows 10 has no corner attribute, D7).
* **Hit-test:** `WM_NCHITTEST` is answered in the shell by `hitTest`, a pure function over screen pixels: outside the window `HTNOWHERE`; with resize borders (resizable and not maximized) the side and bottom frame and a top band of the bottom frame's height inside the client area, corners reaching twice that along both edges; then the chrome regions from last to first (`HTCAPTION`, `HTCLOSE`, `HTMINBUTTON`, `HTMAXBUTTON`, `HTCLIENT`), the pixel converted to points like a pointer position; else `HTCLIENT`. Without resize borders the frame left over is `HTNOWHERE`.
* **Pointer over the chrome:** the title bar and lights report the pointer with non-client messages, which become `PointerEvent`s in surface coordinates. `WM_NCMOUSEMOVE` over a region is a `PointerMove` (after `PointerEnter`; it still goes to `DefWindowProcW`, which keeps the Windows 11 Snap Layouts flyout on `HTMAXBUTTON`; `TrackMouseEvent(TME_NONCLIENT)` asks for the leave). `WM_NCLBUTTONDOWN`/`DBLCLK` on a light is a `PointerDown` with `Clicks` 1 or 2 that captures the mouse; the native button action is suppressed, so the aqua driver's light calls `Close`/`Minimize`/`Zoom`. During the press the captured `WM_MOUSEMOVE`/`WM_LBUTTONUP` become `PointerMove`/`PointerUp`, and `WM_CAPTURECHANGED` ends it with a `PointerUp`. The light's `WM_NCLBUTTONUP` is swallowed. Caption presses are not delivered (`DefWindowProcW` moves the window or maximizes on a double click, and the click count resets). `PointerLeave` comes when the pointer is no longer over the window's client area or regions (`WindowFromPoint` + the hit-test), checked on `WM_NCMOUSELEAVE`, `WM_MOUSELEAVE`, a move onto a resize border and the end of a press.

#### Input (`input.go`, `wheel.go`, `keyboard.go`)

Modifiers come from `GetKeyState` (`VK_SHIFT`, `VK_CONTROL`, `VK_MENU`, either Windows key; AltGr is Control+Option). Event times are `GetMessageTime` mapped onto the clock: now minus the message's age against `GetTickCount` (a wrapping `uint32` difference; an age over 5 s gives now), never going backwards. Both sources are fields of the shell, so tests replace them.

* **Mouse:** `WM_MOUSEMOVE` is a `PointerMove` (after `PointerEnter`; a repeat of the same position is dropped) and starts `TrackMouseEvent(TME_LEAVE)`; the client and non-client leave requests replace each other. The five buttons' `DOWN`/`DBLCLK` messages are a `PointerDown`, `UP` a `PointerUp`; the first held button `SetCapture`s, the last release frees it, then `PointerLeave` if the pointer is outside. A press of a held button or a release of one not held is dropped. `WM_CAPTURECHANGED` to another window with buttons held sends a `PointerUp` for each (lowest bit first), then the leave check. Clicks are counted by the shell (`shellkit.ClickCounter`): same button, within `GetDoubleClickTime` of the previous press (message times) and within the `SM_CXDOUBLECLK` × `SM_CYDOUBLECLK` rectangle at the window's DPI, so triple clicks work; a `DBLCLK` counts at least 2; the `PointerUp` carries its press's count. Handling the right and X buttons means no `WM_CONTEXTMENU`/`WM_APPCOMMAND` from `DefWindowProcW`.
* **Wheel:** `WM_MOUSEWHEEL`/`WM_MOUSEHWHEEL` deltas that are multiples of 120 are notches in lines (× `SPI_GETWHEELSCROLLLINES`, or × `SPI_GETWHEELSCROLLCHARS` horizontally; `WHEEL_PAGESCROLL` counts 20 lines; 0 turns scrolling off), with no phases. Other deltas are precise, in points (the same lines × 100/3 pt), and form a gesture: `PhaseBegan`, `PhaseChanged` (also for a whole notch inside the gesture), and `PhaseEnded` with a zero delta from a 100 ms surface timer after the last one (the phases are `shellkit.Gesture`). `Momentum` is never set (the aqua driver's job). Positive vertical deltas move the content down, positive horizontal ones (tilt right) left.
* **Keyboard:** `WM_KEYDOWN/UP` and `WM_SYSKEYDOWN/UP` are `KeyEvent`s. `keyFor`: a VK table for the named keys and keypad operators, F1–F12, keypad digits, `KeyNone` for modifiers, F13–F24, Insert and the like, else the active layout's unshifted character (`MapVirtualKeyExW(MAPVK_VK_TO_CHAR)`, dead-key bit masked, control characters and surrogates rejected), normalized. `Repeat` is lParam bit 30. `VK_PROCESSKEY` (the IME) is not delivered. A handled key-down removes the pending `WM_CHAR`/`WM_DEADCHAR` and `WM_SYSCHAR`/`WM_SYSDEADCHAR` (`PeekMessageW`, `PM_REMOVE`) and does not reach `DefWindowProcW`, nor does its key-up (per-VK flag, cleared when the surface stops being key); unhandled ones go on, so Alt+F4 and Alt+Space keep working. `WM_CHAR` is a `TextEvent` (`textUnit`: surrogate pairs joined, lone surrogates and C0, DEL and C1 control characters dropped). `WM_SYSCHAR` is not text: Alt+Space goes on to `DefWindowProcW` (the system menu), the others are swallowed. Windows sends no key-ups for keys held when the focus leaves, and neither does the shell.

#### Rendering pipeline (`gpu.go`, `present.go`)

Everything on the UI thread.

* **Shell devices** (`gpu`): one D3D11 device (hardware with BGRA support, else WARP; `newGPU(warp)` with `warp` set, which only tests set through `Shell.warp`, always takes WARP: the golden renders, S3.6c) with its immediate context, its `IDXGIDevice` and `IDXGIFactory2` (the adapter is released at once; the device keeps it), a single-threaded `ID2D1Factory1`, the `ID2D1Device`, one `ID2D1DeviceContext`, a second one for shadow masks (`gpu.mask`; bitmaps are shared within the device, so the main context never changes target while clips or layers are pushed), and one `IDCompositionDevice`. `NewSurface` creates them for the first surface (`Shell.device`); `removeSurface` releases them after the last one (dependants first, then `ClearState` + `Flush` so D3D11's deferred destruction runs, then the device). Every release that should be the last checks the count and records any rest in `Shell.leaks` (logged with `GOGUI_DEBUG=1`); the tests require it to stay empty.
* **Per surface:** the windows are `WS_EX_NOREDIRECTIONBMP` (the window shows only its composition). `createChain` makes a composition swap chain (`B8G8R8A8_UNORM`, premultiplied alpha, 2 buffers, flip-sequential, stretch, `FRAME_LATENCY_WAITABLE_OBJECT`) of the client area's pixel size (at least 1×1), a DComp target for the HWND (not topmost) whose root visual shows the chain (committed), and a D2D target bitmap over buffer 0 (`TARGET | CANNOT_DRAW`) at the window's DPI. A `NewSurface` whose chain fails destroys its window (no `Closed`) and returns the error. `releaseChain` empties the tree (`SetContent(0)`, `SetRoot(nil)`, `Commit`) and releases bitmap, visual, target and chain.
* **Resize and DPI:** `sync` calls `fitChain` before `Resized`, so the handler already sees buffers of the new size: the bitmap is released (it holds the back buffer), then `ResizeBuffers(0, w, h, UNKNOWN, flags)` if the pixel size changed (an empty client area, minimized, keeps the old size), then a new bitmap at the window's DPI.
* **Frame:** `WM_PAINT` validates with `BeginPaint`/`EndPaint`, then `render`: creates a missing chain, fits it, sets the bitmap as the context's target, `SetDpi(dpi, dpi)`, `BeginDraw`, `Clear` to the theme's `ColorWindowBackground` (`clearColor`, from `theme.Sequoia`: 236 grey light, 50 dark, opaque), runs `SurfaceHandler.Paint` on a fresh D2D `canvas` in the same draw, `finish`, `EndDraw`, `SetTarget(0)` (the context keeps no back-buffer reference between frames), releases the canvas's resources (so a device-loss recovery after a failed `EndDraw` finds none), then `Present(1, 0)` and `Commit`. A panicking `Paint` still ends the draw and releases the frame before the panic goes on. `paintErr` holds the recorder's contract errors, only with `Shell.debug` (`GOGUI_DEBUG=1`; tests set it); `renderErr` the last rendering error, including canvas resource creation failures; both are logged with `GOGUI_DEBUG=1`. An appearance change invalidates every surface.
* **Device loss:** `DXGI_ERROR_DEVICE_REMOVED`, `_RESET` or `_HUNG` from `Present` or `ResizeBuffers`, or `D2DERR_RECREATE_TARGET` from `EndDraw` (`isDeviceLost`), calls `deviceLost`: every chain, image bitmap and the devices are released, new devices and chains are created for every open surface, every surface is invalidated and a frame is requested. A chain that can't be recreated keeps the error and is retried at the surface's next paint. Test hooks: `Shell.fault` makes the next `EndDraw`, `Present` or `ResizeBuffers` fail with a chosen `HRESULT`; `Shell.onDrawn` runs between `EndDraw` and `Present` (tests read the back buffer there through a staging texture).

#### Frame clock (`clock.go`)

Everything on the UI thread.

* **Time:** `Now` is the performance counter (QPC) since `New`, the timeline of DWM's timing, so a vblank from `DwmGetCompositionTimingInfo` converts onto it exactly. Without DWM timing the grid is 60 Hz from 0.
* **Frame times:** a frame starting at `t` targets the first vblank after `t`, but a whole period after the previous target if that would be less than half a period after it. Its **hold**, the earliest start of the next frame, is the target, or `t` + half a period if later. So no two frames start within half a period, and frame-function-only frames still run once per refresh on the vblank grid.
* **Pacing:** `Run`'s loop calls `wait` before every message. With a request and the hold not passed, it waits on a high-resolution waitable timer (`CreateWaitableTimerExW`; standard timer or a plain timeout as fallbacks) set for the hold. After the hold it waits on the frame-latency waitables (latency 1, opened with the chain, closed by `releaseChain`) of the **pacing surfaces**: the visible, not minimized surfaces with a waitable, only the invalid ones if any are. A surface with a ticket, or no pacing surface at all, runs the frame at once: a `msgFrame` sent to the listener (so a panic is recovered and re-raised like any window-procedure panic). Every wait is `MsgWaitForMultipleObjectsEx(QS_ALLINPUT, MWMO_INPUTAVAILABLE)`, so messages end it; then one message is dispatched. Idle (no request) waits on the queue alone, with no timer set.
* **Tickets and debts:** the waitable is a semaphore that starts at 1 and gains one signal per `Present`, uncapped; `ResizeBuffers` leaves it alone. A signal the loop takes is the surface's ticket, spent by its next `Present`; a `Present` without a ticket (a resize paint, a `WM_PAINT` from Windows) is a debt, and the waitable's next signals pay debts before one counts as a ticket again. So the semaphore and the bookkeeping stay equal.
* **Stalls:** if the pacing waitables stay unsignaled for 100 ms (`stallTimeout`) from the start of the wait (a deadline: messages meanwhile don't extend it), every waited surface gets a ticket and its debt is cleared.
* **Modal loops:** between `WM_ENTERSIZEMOVE`/`WM_EXITSIZEMOVE` and `WM_ENTERMENULOOP`/`WM_EXITMENULOOP` Windows runs its own loop, so `wait` doesn't run: a request posts `msgFrame` with `frameModal` once the hold has passed, else starts the listener's `WM_TIMER` for the rest of the hold; `modalFrame` runs the frame if still modal and held long enough. Leaving the loop kills the timer and drops the posted frame. The paints that matter in the size loop come from `WM_SIZE` itself.
* **Counters for tests:** `frames`, `waits`, `chainWaits`, `stalls`, `modalFrames`, and per surface `presents`, `ticket` and `debt`. `timing` can be replaced.

#### D2D canvas (`canvas.go`, `shadow.go`, `blur.go`, `image.go`)

`canvas` implements `render.Canvas` on the shell's device context for one frame: `newCanvas(gpu, size, dpi, debug)` after `BeginDraw` (identity transform), `finish` before `EndDraw` (pops every open D2D push, resets the transform, ends the canvas so later calls do nothing, returns the recorder's `End` errors), `release(leak)` after `EndDraw` (every frame resource at its last reference, the rest reported to `leak`); `failures` returns resource creation errors.

* **State:** the transform lives in Go and is mirrored with `SetTransform` (user space is logical points; the surface scale stays in `SetDpi`). Each `Save`/`PushOpacity`/`PushBackdropBlur` frame keeps the transform and the count of open D2D pushes; `Restore`/`Pop` close only a frame of their own kind and pop the pushes made since, innermost first. `ClipRoundedRect`: a sharp rect under a transform with `B = C = 0` is `PushAxisAlignedClip`; anything else (radii, rotation, skew) a `PushLayer` with a geometry mask (`ID2D1RoundedRectangleGeometry` for uniform radii, a path built with `ArcTo` per corner otherwise); a negative or NaN size clips everything away. Every D2D push is recorded as a `canvasPush` (kind, the transform at the push, the clip rect or layer parameters), so it can be pushed again.
* **Drawing:** radii `Clamped`, paints `Normalized`, widths `StrokeWidth`. Sharp fills are `FillRectangle`, uniform ones `FillRoundedRectangle`, per-corner ones `FillGeometry`; strokes `DrawRoundedRectangle` or `DrawGeometry`. Paths become `ID2D1PathGeometry`s (winding fill; each `OpMoveTo` begins a filled figure, `OpClose` ends it closed, open figures end open). Stroke styles map caps (Butt→FLAT, Round→ROUND, Square→SQUARE, for start, end and dash caps), joins (Miter→MITER_OR_BEVEL, Round, Bevel) and the miter limit; dashes and their offset are divided by the width (D2D's units). `DrawText` and `DrawImage` are described under **Text system** and **Images**.
* **Group opacity:** `PushOpacity` pushes a state frame and a `PushLayer` with `render.Opacity(alpha)` (NaN is 0) and infinite bounds on the same push stack, so `Pop` and `finish` close it; nested layers multiply. An opacity of 1 pushes no layer.
* **Shadows (`shadow.go`):** `Shadow.Normalized`; a semantic or transparent color, a shape without area, an outer shape shrunk away by its spread, or a value that doesn't narrow draws nothing. The mask is drawn on `gpu.mask` at the surface DPI into a `TARGET` bitmap, opaque white in the shape's own coordinates: outer, the shape grown by `Spread` (rounded corners grow with it, sharp ones stay sharp) padded by 3σ + 1; inset, a ring (a rect grown by 3σ, the offset and any negative spread, with the shape shrunk by `Spread` cut out, even-odd). A `CLSID_D2D1Shadow` effect gets the mask, σ = `Blur/2` and the color; its output is drawn with `DrawImage` at the shape's origin plus `Offset` plus the mask's origin under the current transform (so shadows follow scales and rotations), inside a geometry layer: the outside of the shape (a rect around everything the shadow reaches with the shape cut out) for outer shadows, the shape itself for inset ones. Masks are cached for the frame by size, radii, spread, blur, inset and ring margin (`maskHits` counts reuses), effects by mask and color (each effect's input and properties are set once, so batched draws never see a mutated effect). `release` frees effects (and their outputs) first, then masks and the mask brush.
* **Backdrop blur (`blur.go`):** `PushBackdropBlur` pushes a blur frame. An empty or invalid shape pushes an empty clip; a zero (or NaN, negative, infinite) radius pushes only the shape's clip. Otherwise σ = `BlurRadius/2` × √|det| of the transform (DIPs); the region is the device-pixel bounds of the transformed shape padded by 3σ and intersected with the target. **Finding:** inside an open D2D layer `CopyFromBitmap` from the target reads the layer's own content, not the composed target, so the open layers (and the clips above the lowest one) are popped, the context flushed, the region copied into the target's scratch bitmap at its origin, and the pushes reopened under their own transforms (an opacity group's content before the blur is thus composed as a group of its own). A crop effect (hard borders) limits the scratch bitmap to the copied region, a Gaussian blur (hard borders) blurs it; both are made once per frame and changed only right after the `Flush`. Then the shape's clip is pushed and stays open until `Pop`, and the blurred copy is drawn into it under the identity transform at the region's DIP origin. The scratch bitmap (`surface.backdrop`, handed to the canvas as `blurTarget` with the target bitmap and its pixel size) persists across frames, grows when a copy needs more (the old one is retired to the frame's resources, since flushed draws may still use it), is recreated for another DPI and released by `releaseChain` (so also on device loss). Without a `blurTarget` blurs only clip. `release` frees the blur effects before the geometries.
* **Images (`image.go`):** `shellImage` implements `render.Image`: premultiplied BGRA pixels copied onto the CPU, a pixel size and a scale (pixels per point; `Size` is pixels / scale). There is no public API yet (decoding and icons come later); the shell makes them with `Shell.newImage`, tests with `imageSet.newImage`, which rejects empty or oversized sizes, a non-positive or non-finite scale and a pixel buffer of the wrong length. Each image belongs to one `imageSet` (`Shell.images`, handed to the canvas as `canvas.images`). Its D2D bitmap (`BITMAP_OPTIONS_NONE`, DPI 96 × scale, so its DIP size is `Size`) is made on the first draw for the current `gpu` and kept across frames; the set tracks the images holding one, and `releaseGPU` releases them all before the device objects (so on device loss and after the last surface's `Close` too); the next draw makes a new one. No finalizers: a dropped image keeps its bitmap until then. A failed `CreateBitmap` is a frame resource failure and isn't retried on the same devices. `DrawImage` draws it with `DrawBitmap` into `dst` (linear interpolation, opacity 1) under the current transform, clips and opacity layers. Images of another set, other `render.Image`s, nil (also a typed nil), an empty or invalid `dst`, and a canvas without an image set draw nothing.
* **Caches (one frame):** solid brushes by clamped color (alpha 0 draws nothing), stop collections by stops (gamma 2.2, clamp), gradient brushes by stops and end points (no stops: nothing; one stop: a solid brush), stroke styles by their mapped properties; geometries are made per call and kept until `release`.
* **Misuse** is ignored before it reaches D2D: semantic colors, non-finite values (also those that overflow float32, such as `Translate(1e300, 0)`), negative sizes, nil layouts and paths, mismatched `Restore`/`Pop`, leftover saves (closed by `finish`). With `debug` every call also goes to a `record.Canvas`, which reports them.

### 8.5 `shell/gtk4`: the Linux shell

Built in S4.1c–S4.1k, S4.2a–S4.2j and (so far) S4.3a–S4.3d (S4.1l deleted `spike/gtk` and put the linux tests into `native.sh` on both backends; S4.2k added every example to it): its native callbacks and its widget class (S4.1c), its `Shell` (S4.1d), its frame clock (S4.1e), its surfaces (S4.1f), the canvas (S4.1g; gradient strokes S4.2b, paths S4.2c, shadows S4.2d, images S4.2e, backdrop blur S4.2f, text S4.2i), the text system (S4.2g; hit-testing, carets and selection S4.2h; drawing S4.2i), the appearance mapping (S4.3a), the portal client (S4.3b), the shell's appearance cache (S4.3c), the live GtkSettings (S4.3d), the chrome regions (S4.1h), pointer input (S4.1i), scroll input (S4.1j) and keyboard input (S4.1k). Depends on `internal/ffi`, `shell/gtk4/gtk`, `shell`, `shell/shellkit`, `shell/fake` (the fixed-width layouts when Pango is missing or fails) and `render/record` (the debug recorder), `driver`, `render`, `mainthread` and `godbus/dbus/v5` (the portal client, S4.3b). **Built and host-tested only; the linux parts have not run yet** (no Linux machine). The dispatch table, the panic capture, the trampolines' Go side, the class constants and the `Shell` are untagged, so their tests run on every host; `trampolines_linux.go`, `class_linux.go`, `loop_linux.go`, `window_linux.go`, `canvas_linux.go` and `gtksettings_linux.go` call GTK.

* **`Shell`** (`shell.go`, `wake.go`; S4.1d): drives the native side through the unexported `loop` interface (`init`, `run`, `quit`, `idle`, `remove`, `release`, `newWindow` (S4.1f), plus the clock's `clockLoop`: `monotonic`, `timeout`, `addTick`, `removeTick`, `frameInfo`); `New()` (linux, `loop_linux.go`) uses the GTK one, the host tests a fake that dispatches through the real `sourceFunc`. `Run` (once, else `ErrRunTwice`) locks the OS thread, binds the queue, then `init`: `gtk.Load` (an `ErrMissing` error is shown with `gtk.Report` and returned), `gtk_init_check` (failure: an error naming `DISPLAY`/`WAYLAND_DISPLAY`), `registerSurfaceClass` (and the trampolines), `g_main_loop_new` on the default context. No `GtkApplication`. It then sets `onPanic` to the loop's quit, installs the wake, sets ready, calls `Ready` (and `rethrow`), runs the loop unless `Quit` came in `Ready` (`g_main_loop_quit` before `g_main_loop_run` would be lost), re-raises a trapped panic, and drains the queue once. **Wake:** `mainthread.Queue` coalesces, and each wake adds one idle source (`g_idle_add`, any goroutine) with its own `kindWake` handle to a `*wakeSource`, kept in a mutex-guarded pending set; the source drains once and goes (`sourceFunc` frees its handle). **`Quit`** (idempotent): sets quit first (so `NewSurface` in a `Closed` handler gets `ErrQuit`), closes the surfaces last to first with `Closed` (a pending panic re-raised after each), closes the queue and quits a running loop. **Teardown** (deferred, every exit after `init`, panics included): surfaces left open closed silently, queue closed, wake removed, pending wake sources removed (`g_source_remove`) with their handles freed, the loop unreffed, `onPanic` and `pendingPanic` cleared. An `init` error returns before any of it. `NewSurface` is the surface's (below); `Quit` has the Paint guard and is posted while a `Resized` handler runs inside GTK's layout; `Appearance` returns the cached appearance (S4.3c, below); `TextSystem` is the Pango text system below (S4.2g), released in `shutdown`; `Clock` is the frame clock below. `Run` starts the clock after `init` (`begin`), and the teardown closes it right after the surfaces. `Queue()` exposes the queue for its checks.

* **Frame clock** (`clock.go`; S4.1e): `Shell.Clock()`, one per shell. `Now` is `g_get_monotonic_time` (GDK's frame times are on that timeline, so they convert exactly), with its 0 back-dated to `Run`'s call (`begin(since)`). A requested frame runs either (a) from a **tick callback** (`gtk_widget_add_tick_callback`, kind `kindTick`) on the **pacing widget** — `Shell.pacingWidget`, the first open surface in creation order whose `openSurface.tickWidget()` is nonzero (S4.1f: a shown surface) — in the UPDATE phase of GDK's frame, so the paint pass's `queue_draw` calls are drawn in the same frame; the target time is GDK's predicted presentation (`gdk_frame_clock_get_refresh_info`), and its refresh interval becomes the period only when GDK has presentation feedback (otherwise it reports a default 16667 µs). The first tick without a request returns `G_SOURCE_REMOVE`, so an idle clock has no tick callback. While frames are requested a lazy **watchdog** timeout runs one if no tick came for `stallTimeout` = 100 ms (a compositor sends no frame callbacks to a minimized or hidden window); it is armed once and re-arms itself while ticks come, so an animation costs no GLib source per frame. Or (b) without a pacing widget, from a one-shot **fallback** `g_timeout_add` (kind `kindFrameTimeout`) at the frame's hold, on a 60 Hz grid. Targets come from the pure `frameTimes(t, predicted, prev, period)`: the first vblank strictly after `t` (GDK's prediction moved on by whole periods, else the grid through the previous target); at least half a period after the previous target; never more than two periods after `t` (a wrong period cannot make targets run ahead); always increasing. The hold is `max(target, t+period/2)`. A frame runs the frame function, then the paint pass (`clock.paint`, S4.1f), both with the target; requests are coalesced and one from inside a frame is scheduled after it. Handles: a timeout's is freed by `sourceFunc` when it goes or by `cancelTimeout` (after `g_source_remove`); a tick callback's by `destroyNotify`, which first tells the clock (`tickGone`), so a widget destroyed without `detach` leaves no stale id; a tick whose handle is not the clock's current one returns `G_SOURCE_REMOVE`. A surface calls `clock.surfacesChanged` when it starts or stops pacing and `clock.detach(widget)` before destroying its widget; `close` (teardown) removes the tick and the timeout. A panic in the frame leaves the clock consistent (no stale ids) and ends `Run` as any callback panic.
* **Surfaces** (`surface.go`, untagged; `window_linux.go`; S4.1f): `shell.Surface` over the unexported `window` interface (one native window: `widget`, `setTitle`, `setDefaultSize`, `setSizeRequest`, `queueResize`, `present`, `minimize`, `setMaximized`/`maximized`, `active`, `minimized`, `scale`, `queueDraw`, `snapshotter` (S4.1g), `setCursor`, `eventTime`, `pastDragThreshold`, `beginMove` (S4.1h), `eventState`, `currentButton`, `clickRules` (S4.1i), `scrollUnit` (S4.1j), `keyBase`, `keyvalToUnicode`, `imFilter`, `imReset`, `imFocus`, `commitString` (S4.1k), `destroy`), created by `loop.newWindow(windowConfig, windowPeer)`; the `*surface` is the `windowPeer` (the GGSurface vfuncs plus `boolSignalPeer`, `pointerSignalPeer`, and since S4.1h `intDoubleDoublePeer` and `doubleDoublePeer` for the caption gestures, since S4.1i `voidSignalPeer` for the pointer controllers, since S4.1j `boolDoubleDoublePeer` for the scroll controller, and since S4.1k `boolUintUintUintPeer` and `uintUintUintPeer` for the key controller). **Native window** (`gtkWindow`): `gtk_window_new` (GTK's toplevel list owns it), a hidden, empty GGSurface as the title bar (`gtk_window_set_titlebar` turns CSD on, so GTK keeps its shadow and resize borders; an invisible title bar takes no space), `gtk_window_set_resizable`, the GGSurface child with the surface as its peer, its size request (the minimum; a non-resizable surface requests its size), `gtk_window_set_default_size`, then `gtk_widget_realize` for the `GdkSurface`. Signals (`connect`, kept and disconnected in `destroy` if still connected): `close-request` (`sigBool`, `kindCloseRequest`), `notify::is-active` (`kindActive`), `notify::scale` of the `GdkSurface` (`kindScale`), `notify::state` of the `GdkSurface` (`kindState`). It holds its own references to the window, the GGSurface and the `GdkSurface` until `destroy` (disconnect, `gtk_window_destroy`, release the GGSurface, unref). **Sizes** in GTK's logical pixels = points; `want` round-trips fractional sizes (`shellkit.FromPx` at scale 1); the drawable size is the GGSurface's allocation (`sizeAllocate` → `Resized` + invalidate, none while creating). `SetSize` clamps, unmaximizes, sets the default size (plus the window-vs-GGSurface CSS delta once both are allocated: solid-csd without a compositor), queues a resize of the GGSurface, and reports the clamped size at once (a different allocation corrects it). `mappedResize` = `resizeDefaultSize` (default) or `resizeSizeRequest` (also raises the size request while growing past the last allocation, lowered by a Post once an allocation reaches it), open until the Linux log. GTK 4 has no maximum-size hint: the maximum only clamps `SetSize`/`SetMaxSize`. `Center` and `SurfaceConfig.Center` do nothing (GTK 4 cannot place toplevels). **Layout reentrancy:** `Shell.inLayout` is raised around a `Resized` from `size_allocate`; then the native part of `SetSize`/`SetMinSize`/`SetMaxSize`, `Close` and `Shell.Quit` are posted. **Scale:** `gdk_surface_get_scale` (required since S4.2a; 1 without a `GdkSurface`); a change reports `Resized`. **Lifecycle:** `Show` = `gtk_window_present`, then the surface paces the clock (`tickWidget` = the GGSurface while shown and not minimized or suspended per `gdk_toplevel_get_state`; never reported on Wayland, where the clock's watchdog covers it); `Minimize`, `Zoom` (resizable and shown only) = maximize/unmaximize, `Zoomed` = `gtk_window_is_maximized`; `close-request` asks `CloseRequested` and closes the surface itself, always returning TRUE; `Close`/`closeNow`: dead, out of `Shell.surfaces`, `clock.detach`, `destroy`, then `Closed` (not when silent). `KeyChanged` on `notify::is-active` changes. **Painting:** `Invalidate` marks and requests a frame; the paint pass (`Shell.paintInvalid`) queues a draw of every invalidated, shown surface, which GTK snapshots in the same frame; each snapshot calls `Paint` on the canvas (below) over the vfunc's `GtkSnapshot` at the surface's scale, finished in a defer so the snapshot is balanced even when `Paint` panics (only a returned paint counts in `paints`; with `GOGUI_DEBUG=1` the recorder's errors are logged and kept in `paintErr`), with the Paint guard (`Shell.painting`, as on Win32). `SetCursor` = `gtk_widget_set_cursor_from_name` on the GGSurface (CSS names; GTK's borders keep theirs); `SetChromeRegions` copies the regions for the caption gestures (below).
* **Chrome regions** (`chrome.go`, untagged; `window_linux.go`; S4.1h): the `RegionCaption` parts of the drawable area act as GTK's own title bar (`GtkWindowHandle`), through two primary-button gestures that `addCaptionGestures` adds to the GGSurface (the widget owns them; their handlers are kept in `conns` and disconnected in `destroy`): a `GtkGestureDrag` (`drag-begin` → `kindCaptionDragBegin`, `drag-update` → `kindCaptionDragUpdate`, `sigDoubleDouble`) and a `GtkGestureClick` (`pressed` → `kindCaptionPress`, `sigIntDoubleDouble`). A press that begins on the caption (`shellkit.HitRegion` over the regions, last to first, at the press position: GTK's widget coordinates are the drawable area's points) starts the compositor's interactive move once its offset passes GTK's drag threshold (`gtk_drag_check_threshold` from 0, 0, as `GtkWindowHandle`), from the press position; `beginMove` claims the press, converts the point to `GdkSurface` coordinates (`gtk_widget_compute_point` to the window plus `gtk_native_get_surface_transform`, the CSD shadow) and calls `gdk_toplevel_begin_move` with the gesture's device, button and event time, then resets both caption gestures and (since S4.1i) the pointer gesture. A press that does not move does nothing, so a double-click can follow. The second press (`n_press` 2, GTK's double-click time and distance) on the caption is `Zoom` (shown and resizable only) and starts no move; the two gestures' handlers for the same press come in an undocumented order, so they are matched by the press's event time (0, no current event, matches nothing). A press already on the caption keeps going when the regions change. The traffic lights and every other region are ordinary pointer events (S4.1i); the resize borders are GTK's, in the CSD shadow outside the GGSurface.
* **Pointer input** (`input.go`, untagged; `window_linux.go`; S4.1i): two controllers on the GGSurface (`addPointerControllers`, owned by the widget, handlers in `conns`): a `GtkEventControllerMotion` (`enter`/`motion` → `kindPointerEnter`/`kindPointerMotion`, `sigDoubleDouble`; `leave` → `kindPointerLeave`, `sigVoid`) and a `GtkGestureClick` for every button (button 0; `pressed`/`released` → `kindPointerPressed`/`kindPointerReleased`, `sigIntDoubleDouble`; `cancel` → `kindPointerCancel`, `sigPointer`). `enter` is a `PointerEnter`; `motion` a `PointerMove` (after a `PointerEnter` if outside; a repeated position is dropped); `leave` a `PointerLeave`. A press of the gesture's current button (`gtk_gesture_single_get_current_button`; GDK 1/2/3/8/9 → primary/middle/secondary/back/forward, others ignored) is a `PointerDown`, its release a `PointerUp` (a release whose button GTK no longer names ends the one held button); `cancel` ends every held button with a `PointerUp` at the last position. **Capture** is GTK's implicit grab; a `leave` while a button is held, a move outside, or a last release or `cancel` outside the drawable area sends the `PointerLeave` after the last `PointerUp` (`pointerState.left`; an `enter` or move inside undoes it). **Chords:** a `GtkGestureSingle` resets on a second button, so the held button gets its `PointerUp` (cancel) and the second press is not reported. **Caption:** a primary press on `RegionCaption` (`captionAt`) is not delivered, nor its release or cancel, and breaks a click series; hover there is delivered. The caption drag's claim denies the press to this gesture without a `cancel`, so `beginMove` resets the pointer gesture too, and a new press clears a stale caption press. **Clicks** are the shell's `shellkit.ClickCounter` over the press position in whole logical pixels, with `gtk-double-click-time` and `gtk-double-click-distance` read from the default `GtkSettings` at each press (`g_object_get_property`; 400 ms and 5 px when a setting reads 0 or less). **Modifiers** from `gtk_event_controller_get_current_event_state`: Shift, Control, Alt and Meta → Option, Super and Hyper → Command. **Times:** `Shell.eventTime` maps the event's ms time (`gtk_event_controller_get_current_event_time`; CLOCK_MONOTONIC on Wayland and Xorg) against `g_get_monotonic_time`/1000 with `shellkit.EventTimeAt` (older than 5 s, from another timeline, or 0 → now), never backwards (`Shell.events`, a `shellkit.Monotonic`). Nothing is delivered while the surface is being created or after it closed.
* **Scroll input** (`scroll.go`, untagged; `window_linux.go`; S4.1j): a `GtkEventControllerScroll` on the GGSurface for both axes, `KINETIC` (`addScrollController`, owned by the widget): `scroll` (`sigBoolDoubleDouble`, `kindScroll`, always TRUE), `scroll-begin`/`scroll-end` (`sigVoid`), `decelerate` (`sigDoubleDouble`). A `scroll` is a `ScrollEvent` at the pointer's last position (`pointerState.lastPos`), both axes negated (GTK's positive deltas show later content; natural scrolling is applied below GTK); `gtk_event_controller_scroll_get_unit` `SURFACE` is precise (points 1:1), `WHEEL` is notches, carried as lines at `wheelLines` = 3 per notch (GTK has no such setting), and Shift with a vertical wheel scrolls horizontally, as macOS does. Inside `scroll-begin`…`scroll-end` the first precise event is `PhaseBegan`, the others `PhaseChanged`, and `scroll-end` sends `PhaseEnded` with a zero delta; a precise event outside them, and every wheel event, has no phase. **Momentum:** `decelerate` (right after `scroll-end`, the release velocity in the deltas' units per second, `scroll_history_finish`) after a gesture that began starts the shell's own `momentum` (GTK leaves kinetic motion to the widget): `v0·e^(−k·t)` with k = 4/s (GtkScrolledWindow's deceleration friction), stopping at 20 pt/s, each axis capped at 15000 pt/s; `Shell.stepMomentum` runs it in the paint pass of each frame (before the draws are queued), sending `Momentum` `PhaseBegan`, `PhaseChanged`… and `PhaseEnded` with the rest (Phase `PhaseNone`, precise, at the frame times through `Shell.events`; one that stops within its first frame sends `PhaseBegan` with all of it, then `PhaseEnded`), and requests the next frame while it runs. A `scroll-begin`, a `scroll` or a pointer press stops it first with a zero-delta `Momentum` `PhaseEnded`.
* **Keyboard input** (`keyboard.go`, untagged; `window_linux.go`; S4.1k): a `GtkEventControllerKey` on the **GtkWindow** in the CAPTURE phase (`addKeyboard`; it sees every key before GTK's own window bindings and focus handling) and a `GtkIMContextSimple` with the GGSurface as its client widget (the `gtkWindow` holds the reference; its client widget is cleared before the window is destroyed). `key-pressed` (keyval, keycode, state) is a `KeyEvent{Down: true}` whose result is the handler's: a consumed key returns TRUE (GTK's defaults do not run) and resets the input method, so it produces no text; an unconsumed one goes to `gtk_im_context_filter_keypress` with the current event, whose `commit` (synchronous, after the `KeyEvent`) is a `TextEvent` with control characters dropped and invalid UTF-8 replaced (`commitText`), at the key's time (now outside a key event); the return value is whether the input method took the key. * **Canvas** (`canvas.go`, untagged; `canvas_linux.go`; S4.1g, real gradient strokes since S4.2b, paths since S4.2c, shadows since S4.2d, images since S4.2e, backdrop blurs since S4.2f, text drawn since S4.2i): `render.Canvas` over the unexported `snapshotter` interface (the GtkSnapshot calls in logical pixels: `save`, `restore`, `translate`, `scale`, `matrix`, `pushRoundedClip`, `pushOpacity`, `pop`, `appendColor`, `appendBorder`, `appendLinearGradient`, since S4.2c `appendFill`, `pushFill`, `appendStroke`, `pushPathStroke`, since S4.2d `appendShadow`, since S4.2e `newTexture` and `appendTexture`, since S4.2f the segment calls `begin`, `cut`, `end`, `appendNode` and `pushBlur`, since S4.2i `appendLayout`, and since S4.2b `pushStroke` (a rounded rect's `GskPath` built with `gsk_path_builder_add_rounded_rect` (`add_rect` when every corner is sharp, so its corners are miter joins) and a `gsk_stroke_new` of the width, pushed with `gtk_snapshot_push_stroke`, which keeps its own path reference and stroke copy, so both are dropped at once; ended by `pop`)); `gtkSnapshot` (linux; since S4.2f a struct of the paint's GtkSnapshot and the current segment, `newGtkSnapshot`) is the one over GTK, the host tests use a recording fake that also checks GtkSnapshot's nesting and, since S4.2f, that every segment is cut or ended balanced, the last one ended and every node released once. the surface rect is the base frame's first clip; `PushOpacity` = `push_opacity` (clamped) then a save; `Pop` pops the frame's clips, restores, and pops the opacity. `finish` closes every frame left open, the base included, and returns the recorder's errors when it has one (`GOGUI_DEBUG=1`). **Drawing:** a fill is a color node or a linear-gradient node (stops normalized; one stop or a zero-length line is the last stop's color, CSS), inside a rounded clip when the clamped radii are nonzero; a solid stroke is a border node whose outline is the rect grown by half the width (rounded corners grown by as much, sharp ones stay sharp), so it is centered; a gradient stroke (S4.2b) is `pushStroke` of the rect with its clamped radii, the linear-gradient node over that grown rect, and `pop` (so it nests in any open state); a degenerate gradient (one stop, a zero-length line) strokes as a border in its one color, and a rect without area as a border in the gradient's color at offset 0.5 (GSK would stroke its path without the border's square ends). **Paths** (S4.2c): `pathCmds` (pure) turns a `render.Path` into `pathCmd`s (move, line, quad, cubic, close, points narrowed to float32): a subpath with nothing but its move (and a close) is dropped, a fill closes every open subpath (nonzero rule), a stroke keeps them open, and a point that is not finite as a float32 drops the whole path (as Win32). `strokeArgs` makes the `pathStroke` (width, `GskLineCap`, `GskLineJoin`, miter limit, dashes and offset, from `StrokeStyle.Normalized`; The snapshotter's path calls build a `GskPath` (`gsk_path_builder_move_to/line_to/quad_to/cubic_to/close`) and a `GskStroke` (`gsk_stroke_set_*`) per call and drop them after it (GTK keeps a reference and a copy): a solid fill is `gtk_snapshot_append_fill` (`GSK_FILL_RULE_WINDING`), a solid stroke `append_stroke`; a gradient is `push_fill`/`push_stroke` around the linear-gradient node over the path's bounds (`render.Path.Bounds`, tight for curves), for strokes grown by `strokeReach` (w/2 × the largest of 1, √2 for square caps, the miter limit for miter joins), and by one device pixel more for the antialiased edge, its coordinates clamped to ±1e30 (`gradientCover`), then `pop`. A fill whose bounds have no area draws nothing. **Shadows** (S4.2d): `shadowArgs` (pure) makes a `shadowCall` from the rect, its clamped radii and `Shadow.Normalized`, whose offset, spread and blur pass through unchanged (GSK's shadow nodes have CSS box-shadow semantics, as `render.Shadow`: outset outside the outline only, inset inside it only, the spread growing each rounded radius with sharp corners kept sharp, the blur radius the CSS one, σ = blur/2); `appendShadow` is `gtk_snapshot_append_outset_shadow` or `append_inset_shadow`, a single node that nests in any open state. A texture that can't be made draws nothing and isn't retried until the release. `DrawImage` is `appendTexture`: `gtk_snapshot_append_scaled_texture` into `dst` with `GSK_SCALING_FILTER_LINEAR`, under the current transform, clips and opacity (the node holds its own texture reference); images of another set, other `render.Image`s, nil (typed too), an empty, negative or non-finite `dst` (also after narrowing) and a canvas without a set draw nothing. **Backdrop blur** (S4.2f, `blur.go`, as Win32's S2.4e_3; GSK has no backdrop filter): the canvas draws by segments, `gtk_snapshot_new` children of the paint's snapshot (`begin` in `newCanvas`; `end` in `finish` appends the last one's node to the paint's snapshot). `PushBackdropBlur` unwinds every open frame, innermost first, `cut`s the segment (`gtk_snapshot_free_to_node`, the node appended to the paint's snapshot with `gtk_snapshot_append_node` and kept in the canvas's `nodes`; an empty segment has no node), starts the next and rewinds the frames, so the state is the one before (an opacity group's content before the blur is composed as a group of its own, as on Win32). * **Trampolines** (`trampolines.go`): a fixed set of `numTrampolines` = 16 native callbacks, created once per process by `registerTrampolines` (`sync.OnceFunc` over `ffi.RegisterCallback`) into the `tramp` struct: the GGSurface `class_init` and its `size_allocate`, `measure` and `snapshot` vfuncs, one shared `GClosureNotify`, one `GSourceFunc`, and the signal handlers **by C signature**, not by signal: `gboolean (gpointer, gpointer)` (`sigBool`, e.g. `close-request`) and `void (gpointer, gint, gdouble, gdouble, gpointer)` (`sigIntDoubleDouble`, e.g. `pressed`/`released`), and since S4.1e the frame clock's `GtkTickCallback` (`tickCallback`, `gboolean (GtkWidget *, GdkFrameClock *, gpointer)`) with a shared `GDestroyNotify` (`destroyNotify`; it tells a `tickGonePeer`, then frees the handle) for a tick callback's handle when GTK drops it (returned `G_SOURCE_REMOVE`, removed, or its widget destroyed), since S4.1f `void (gpointer, gpointer, gpointer)` (`sigPointer`, `GObject::notify`), since S4.1h `void (gpointer, gdouble, gdouble, gpointer)` (`sigDoubleDouble`, `GtkGestureDrag::drag-begin`/`drag-update`, since S4.1i also `GtkEventControllerMotion::enter`/`motion`), since S4.1i `void (gpointer, gpointer)` (`sigVoid`, `GtkEventControllerMotion::leave`, since S4.1j also `scroll-begin`/`scroll-end`), since S4.1j `gboolean (gpointer, gdouble, gdouble, gpointer)` (`sigBoolDoubleDouble`, `GtkEventControllerScroll::scroll`), and since S4.1k `gboolean (gpointer, guint, guint, guint, gpointer)` (`sigBoolUintUintUint`, `GtkEventControllerKey::key-pressed`) and `void (gpointer, guint, guint, guint, gpointer)` (`sigUintUintUint`, `key-released`); `GtkIMContext::commit` uses `sigPointer`. Names start with `gtk4.`. Later steps add signatures; a test pins `ffi.Callbacks()` to the set.
* **Dispatch** (`dispatch.go`): one process-wide `ffi.Handles[entry]`, `entry{peer any, kind}`. A signal handler's `user_data` and a GGSurface's handle word are handles into it; the `kind` tells one peer's callbacks of the same signature apart. Each signature has a peer interface (`boolSignalPeer`, `intDoubleDoublePeer`, `pointerSignalPeer`, `sourcePeer`, `surfacePeer`, `tickPeer`) that the trampoline asserts; a stale, zero or foreign handle reaches no peer and returns the zero result (FALSE, `G_SOURCE_REMOVE`). A panic in a peer returns the zero result too, except `sigBool` for `kindCloseRequest`, which returns TRUE (preset named result), so GTK never destroys a surface's window itself. `connect(instance, signal, tramp, peer, kind)` connects with `g_signal_connect_data` and `closureNotify` as `destroy_data`, which frees the handle when GLib drops the handler (disconnect or finalization); a signal the instance's type lacks is refused with `g_signal_lookup` first (returns 0, no handle, no `g_critical`). `addIdle(peer, kind)` adds an idle source; `sourceFunc` frees the handle when the source goes (the peer returns false or panics), and whoever calls `g_source_remove` frees it.
* **Panics** (`panic.go`): every trampoline defers `trap(name)`, which recovers a panic and keeps it in `pendingPanic` (UI thread; the first wins, a re-raised `*PanicError` from a nested callback is kept as it is) and runs the `onPanic` hook (the main loop's quit, S4.1d; a panic of the hook is dropped). Go code calls `rethrow()` after the native call that ran the callback has returned. `PanicError{Value, Callback, Stack}` unwraps to an error value. No panic unwinds through a GTK frame.
* **GGSurface** (`class.go`, `class_linux.go`; from spike B): `registerSurfaceClass()` (`sync.OnceValue`, after `gtk.Load` and `gtk_init_check`) queries `GtkWidget` and refuses a `sizeof(GtkWidgetClass)` other than 408 (LP64, GTK 4.0–4.18; `checkWidgetType`, host-tested), puts the handle word after the `GtkWidget` instance rounded up to a word, binds `GtkWidget`'s own snapshot slot for the chain-up, refuses a taken type name, registers `GGSurface` with `g_type_register_static_simple`, forces `class_init` with `g_type_class_ref` and reads the slots back. `class_init` writes the three slots at 200 (`size_allocate`), 232 (`measure`) and 320 (`snapshot`) and sets the CSS name `ggsurface` (no theme margins or padding). `measure` passes `for_size` to the peer (GTK passes -1 while the widget keeps `GtkWidget`'s CONSTANT_SIZE request mode) and always writes its outputs, 32 bits each, NULL pointers skipped, baselines -1, zeros without a peer or after a panic. `snapshot` lets the peer draw, then chains to `GtkWidget`'s snapshot (the children), also after a panic. An instance without a live `kindSurface` handle has no peer. `newSurfaceWidget(peer)` creates a sunk instance with a new handle (0 and no handle before registration or for a NULL from GLib); `releaseSurfaceWidget` frees the handle and drops the reference (0 is ignored). For now `for_size` is only plumbed through: a height-for-width surface needs a `get_request_mode` override (slot 224, one more trampoline).

## 9. `internal/aqua`: the drawn driver

The element core of the drawn driver for Windows and Linux (PLAN.md §5.1). No build tags; depends only on `driver`, `driver/stub`, `layout`, `mainthread`, `render`, `shell`, `aqua/a11y`, `aqua/anim`, `aqua/scroll` and `aqua/theme`.

* **`Element`**: `layout.Item` (`FittingSize`, `SetFrame`) + `Paint(render.Canvas)` + `HitSelf(p) bool` + `HandleEvent(aqua.Event) bool` + `Activate() bool` (the primary action, as a click: the a11y press and Return/Escape on a default/cancel button; S3.2f) + `AccessibleNode() a11y.Node`, sealed by an unexported method to types that embed **`Base`**. An element type embeds `Base` by value and calls `Init(self)` once; tree operations, `PaintTree` and `HitTest` panic on an element without `Init`. `Base` defaults: `FittingSize` zero, `Paint` nothing, `HitSelf` = `Bounds().Contains`, no event handling, no primary action (`Activate` false), a `RoleNone` node. Elements never measure or arrange themselves: the public layer runs `internal/layout` over the peers and calls `SetFrame`.
* **Tree:** ordered children (paint order), one parent each. `AddChild`, `InsertChild` (an existing child's index counts without itself), `SetChildren` (detaches children not in the list, steals the others from their old parents; the same list is a no-op), `RemoveChild`, `RemoveFromParent` (the subtree stays with the element), `Parent`, `Root`, `Children` (a copy), `ChildCount`, `Child`, `IndexOf`. Nil, uninitialised, repeated, self and ancestor children panic before anything changes.
* **State:** `Frame` (in the parent's coordinates; a root's in the coordinates `PaintTree`/`HitTest` use), `Bounds` (origin 0), `SetHidden`, `SetEnabled`, `SetClipsChildren`, `VisibleInTree`, `EnabledInTree`.
* **Invalidation:** every setter invalidates only on a change, and tree changes invalidate the old and the new parent. `Invalidate` marks the element and its ancestors dirty and runs the root's `SetInvalidateFunc` callback on the root's clean→dirty transition only, so a frame gets one callback. Invariant: a dirty element's ancestors are dirty. New elements start dirty. v1 repaints the whole window; the marks only coalesce.
* **`PaintTree(c, root)`:** for each visible element `Save`, `Translate(frame origin)`, `Paint` inside its own `Save`/`Restore`, then (if it has children) the clip to `Bounds` when `ClipsChildren` (the element itself is never clipped by its own flag), the children in order (read once, so a `Paint` that edits the tree is safe), `Restore`. Hidden subtrees are skipped. **Culling** (S3.5d): the clip of the clipping ancestors (their `Bounds` intersected, carried down the recursion; none for an unclipped tree, which is never culled) skips an element whose frame, grown by `paintOverflow()` (the focus ring's outer edge or the widest outer shadow from the tokens, plus 1 pt, 10 pt with Sequoia), misses it: a clipping or childless element with its subtree, a non-clipping one only its own `Paint` (its children may lie outside it); an empty clip (a zero-size clipping ancestor) culls everything below it. Culled elements are cleaned like hidden ones (a repaint repaints the whole window). Every element ends clean; the flag is cleared before `Paint`, so invalidating during `Paint` calls back again (animations). The canvas is balanced afterwards.
* **`HitTest(root, p)`** returns the topmost visible element under `p` and `p` in its coordinates: children last-first before the parent, `HitSelf` decides, hidden subtrees skipped, overflowing children hit unless an ancestor clips, disabled elements hit (the `Router` skips them). `ToRoot`/`FromRoot` convert between an element's coordinates and its root's parent's.
* **Events** (`event.go`): `PointerEvent` (kinds `PointerEnter`, `PointerLeave`, `PointerDown`, `PointerMove`, `PointerUp`, `PointerCancel`; `Pos` in the element's coordinates, `Over`, and `Button`/`Buttons`/`Clicks`/`Mods`/`Time` passed through), `ScrollEvent`, `KeyEvent`, `TextEvent` (the shell events, position converted), `FocusEvent{Focused}` and (not routed; sent by the window, `state.go`, S3.2c) `WindowStateEvent{Key, Appearance}`.
* **Window context and state (`state.go`, S3.2c):** `Base.Window()` walks to the root and returns its aqua `Window` (nil when detached or under a root made with `NewRouter` directly; a closed window keeps answering with its last state); through it an element reads `IsKey`, `Appearance`, `Theme` (the driver's `tokens`), `Timeline` and `Router`. When the window's key state or effective appearance changes, the window invalidates every element and then sends `WindowStateEvent` (the state at delivery) to every element in pre-order, hidden and disabled ones included, no bubbling, result ignored; elements a handler moved out of the window are skipped, and a handler that closes the window stops the rest. The key change reaches `WindowHandler.KeyChanged` after the elements (not at all if a handler closed the window). Elements that join a window later get no event and read the state from `Base.Window`. The focus survives an inactive window: `Router.SetActive` (the window keeps it equal to `IsKey`; a plain router starts active, a window's router inactive until the shell makes it key, and it turns inactive on `Closed`) changes only `FocusState`: `Base.FocusState()`/`Router.FocusState(e)` report `Unfocused`, `FocusedInactive` or `FocusedActive`. In the a11y tree the window node carries `StateFocused` while the window is key, and the focused element keeps its `StateFocused` while it is inactive.
* **Focus ring (`focusring.go`, S3.2d):** `FocusRing` is an embeddable helper (zero value ready): the element calls `Track(self, ev)` from `HandleEvent` (it reacts to `FocusEvent` and `WindowStateEvent`, never handles them) and `Paint(c, self, shape)` last in its `Paint`. The ring is on while the element is `FocusedActive`; turning on starts at progress 0 and animates to 1 over `Animation.Duration(FocusRingDuration, a)` (200 ms) with `EaseOut` on the window's timeline (one `anim.Value` per ring, made on first use), so it runs again each time the element gains the focus or the window becomes key; turning off (blur, hidden, removed, window inactive) drops it to 0 at once. An appearance change while on does not restart it. Without a timeline (a window from `aqua.NewWindow`, a plain router) and with Reduce Motion it appears at once. `Progress`, `Visible`. `FocusShape` is a rounded rect (`RectFocusShape`) or a path (`PathFocusShape`). `FocusRingBand(p)` gives the band: the inner edge `FocusRingOffset + (1−p)·FocusRingWidth` outside the shape, `FocusRingWidth·(2−p)` wide, so the ring starts one width further out and twice as wide and settles on its final band. `PaintFocusRing(c, shape, p, a)` (the step text named `(c, shape, progress)`; the appearance is needed for the color) strokes that band, centred, in `Theme.FocusRing(a)` with its alpha × p: a rounded rect outset exactly (rounded corners grow by the outset, sharp ones stay sharp), a path scaled about its bounds' centre so they grow by the outset (exact for rects and ellipses, close for convex shapes, a flat direction not scaled). Nothing for p ≤ 0 or NaN; p > 1 is the full ring. The ring lies outside the shape, so the element's own `Paint` is not clipped by it; a clipping ancestor (the content area, a scroll viewport) may cut it.
* **`Router`** (`NewRouter(root)`, one per window; the root can't have a parent or become a child afterwards). `Event(shell.Event) bool` routes:
  * hover: the chain is the enabled part of the path from the root to `HitTest`'s element. On a change, leavers get `PointerLeave` deepest first, joiners `PointerEnter` root side first, stayers nothing; an element joins only as it gets its Enter, and a handler that changes the chain stops the rest. `RefreshHover` recomputes it after layout or tree moves (not during a capture or while outside);
  * press: `PointerDown` goes to the deepest hovered element and bubbles up; the first handler (if still usable) captures. Captured moves, presses and releases go only to it, with `Over` saying whether the pointer is over it or a descendant; the hover is frozen. The last release ends the capture and recomputes the hover; a shell `PointerLeave` (capture lost) sends `PointerCancel`;
  * moves outside a capture bubble from the deepest hovered element; scroll bubbles from the topmost element under the pointer through the enabled ancestors, except that a precise gesture is **latched** (S3.5d): the element that handled its `PhaseBegan` gets the rest of it (`PhaseChanged`, `PhaseEnded`) and the OS momentum after it, alone, wherever the pointer is, with its result returned unbubbled, until the momentum's `PhaseEnded` or any other scroll event (a new `PhaseBegan`, a wheel event, a stray phase after the end), which routes normally; `Router.Latched()` reports it. An unhandled `PhaseBegan` latches nothing; a latched element removed, hidden or disabled (also by its own handler, `PhaseBegan` included) drops the latch, and the rest of that gesture reaches nobody; key and text events bubble from the focused element (or the root) through enabled ones. An unhandled Tab key-down with no modifier other than Shift calls `FocusNext` (not handled when the Tab order is empty); an unhandled Space key-down without modifiers presses the focused element with `Activate` (S3.3a, see the control state below). **Focus hook** (S3.5g): whenever the focus moves to an element (`SetFocus`, `Focus`, `FocusNext`), after its `FocusEvent{true}`, every ancestor implementing `focusRevealer` (the `ScrollView`'s `scrollArea`), innermost first, brings it into view (`revealFocus`); it stops when the element loses the focus or stops being usable (removed, hidden, disabled) on the way; clearing the focus and `SetActive` scroll nothing. The result goes back to the shell;
  * disabled elements (or ones in a disabled subtree) get no input.
* **Focus:** `SetFocusable`/`Focusable`, `Focus()`/`HasFocus()` on `Base` (false without a router), `Router.SetFocus` (nil clears; fails for elements that are not focusable, visible, enabled and in the tree), `Focused`, `FocusOrder` (the Tab order: pre-order, hidden and disabled subtrees skipped, filtered by the keyboard-access mode), `FocusNext(backward)` (wraps; without a focus starts at the first or the last; from a focus outside the Tab order, a control clicked without full keyboard access, goes to the first Tab stop after it in tree order, or the last one before it). **Keyboard access (S3.2e):** `Base.SetFocusKind`/`FocusKind`: `FocusControl` (the zero value) or `FocusText`. `Router.SetFullKeyboardAccess`/`FullKeyboardAccess`: on (the default, macOS with "Keyboard navigation" on and the Windows/Linux convention) Tab reaches every focusable element; off (the macOS default) only `FocusText` ones. The mode and the kind change only the Tab order: `SetFocus` focuses any focusable element in both modes, and a focused element keeps the focus when either changes. No public API sets the mode yet. The old element gets `FocusEvent{false}` before the new one gets `FocusEvent{true}`; a handler that moves the focus wins.
* **Default and cancel buttons (`buttons.go`, S3.2f):** `Base.SetDefaultButton`/`IsDefaultButton` and `SetCancelButton`/`IsCancelButton` mark an element; the mark stays on the element (so marking works before or after it joins a window) and carries a serial from a package-wide atomic counter. `Window.DefaultButton()`/`CancelButton()` return the element of the window's tree marked last (pre-order walk at each call): a second mark replaces the first, marking again makes an element the latest, and unmarking or removing the latest makes the previous one still marked in the tree the button again; one element can be both. The surface handler passes a key-down no element handled (after the `Router`, so the focused element and its ancestors, and Tab, come first) to the window: Return without modifiers presses the default button (the shells report keypad Enter as Return), Escape without modifiers and `ModPrimary.Resolve(false)`+`.` (Ctrl+.; ⌘. on macOS) the cancel button, with `Activate`, only when the button is in the tree, visible and enabled (no fall-back to another marked one); the key is consumed when `Activate` returns true. A repeat presses nothing but is consumed when the button could be pressed. Other modifiers, other keys, key-ups and a missing, hidden or disabled button leave the key unhandled for the shell. The step text's `Window.SetDefaultButton`/`SetCancelButton` became the element marks.
* **Control state and press tracking (`control.go`, S3.3a):** `ControlState{Interaction, Focus, Disabled, Key, Appearance}` is what a control's look depends on besides its own value, computed fresh (never cached) by `Base.ControlState()` or, for a pressable control, `pressTracker.State(e)`: `Interaction` is `InteractionPressed` while the control holds a primary press with the pointer over it, `InteractionNormal` while that press is dragged off (the hover chain is frozen during a capture, so it is not read then), otherwise `InteractionHover` when the element is in its router's hover chain; a control disabled in the tree is always normal. `Focus` is `Base.FocusState`; `Key` and `Appearance` are the window's (outside a window `Key` is the router's `Active`, true without a router, and the appearance is the zero value). `String()` gives e.g. `"pressed focused key light"` for test logs. `pressTracker` (unexported, zero value idle) is embedded in a control and fed from its `HandleEvent` with `Track(self, ev) (handled, act)`: a primary `PointerDown` starts the press (handled, so the router captures), captured moves set pressed from `Over`, the primary release ends it and reports `act` when over the control, `PointerCancel` (and `Reset`) drop it without acting; other buttons are not handled when idle and swallowed during a press; every pressed-look change invalidates the element. The traffic lights use it (`trafficLight.press`). **Space:** the `Router` passes a Space key-down that no element handled (the focused element and its ancestors first) to `spaceActivates`: without modifiers, with a focused, usable element of `FocusKind` `FocusControl` in an active router, it calls `Activate` and consumes the key when that returns true; an auto-repeat presses nothing but is consumed; a `FocusText` element keeps Space (it is typed), and an inactive window, a missing focus or modifiers leave it unhandled. Space acts on key-down (AppKit highlights on key-down and acts on key-up; the pressed highlight for Space comes with the real buttons if needed).
* **State follows the tree:** removing (`RemoveFromParent`, `RemoveChild`, `SetChildren`, moving to another tree), hiding or disabling an element or an ancestor sends `PointerCancel` to the capturer, `PointerLeave` to the dropped hovered elements and `FocusEvent{false}` to the focused one at once; so does making the focused element unfocusable. Moves inside the same tree keep the state. Frame changes and newly shown elements affect the hover only at the next pointer event or `RefreshHover`.
* **`AccessibilityTree(root) *a11y.Node`:** a snapshot with one node per visible exposed element: the element's `AccessibleNode`, plus `Frame` in root-parent coordinates, `StateDisabled` (in a disabled subtree), `StateFocusable` and `ActionFocus` (focusable and enabled), `StateFocused` (the router's focus). `RoleNone` elements are left out and their children hoisted; hidden subtrees are left out; the root's node is always returned.
* **`aqua/a11y`:** `Role` (none, window, group, text, button, checkbox, radio, textfield, textarea, slider, progress, popup, separator, scrollarea, titlebar), `States` (disabled, focusable, focused, checked, mixed, selected, readonly, expanded), `Actions` (press, focus, increment, decrement, showmenu), `Node` (`Role`, `Label`, `Value`, `States`, `Actions`, `Frame`, `Children`), `Walk`, `Find`, `Count`, `String` and `Dump` (one line per node, two-space indent). No bridge to an OS accessibility API (D4).
* **`Window` (`window.go`):** `NewWindow(sh, cfg, h) (*Window, error)` on a running shell (panics for a nil handler). The surface is the content size plus `TitleBarHeight()` (the `Chrome.TitleBarHeight` token, 28 pt) for `StyleTitled` windows, 0 otherwise; zero limits stay "no limit", but a titled surface's minimum height is at least the bar. The tree: a root (the surface; a11y `window` labelled with the title, `focused` while key), a content area at `y = 28` that paints `ColorWindowBackground` and clips the content element, and the title bar after it (on top). `driver.Window` works in content coordinates: `ContentSize`, `SetContentSize` (clamped by the surface; `ContentResized` exactly once, even for the same size), `SetMinSize`/`SetMaxSize` (content limits), `SetTitle` (native and drawn), `Center`, `Show` (initial focus, S3.2e: when nothing is focused it first focuses the first element of the Tab order, before the surface shows and the window becomes key, so a `Focus` after `SetContent` and before `Show` wins and a second `Show` keeps the focus), `Close` (no `ShouldClose`). `SetContent` makes an aqua `Element` the content area's only child and refreshes the hover; any other widget shows nothing, nil removes it. A focus in the old content is dropped (`FocusEvent{false}`), nothing new is focused until the next `Show` or Tab. The focus survives key changes (S3.2c). Extra API for the driver and tests: `Root`, `Content`, `Router`, `Surface`, `Title`, `IsKey`, `Closed`, `Shown` (S3.4f: after `Show`, until closed; a minimized window counts as shown), `Theme`, `Timeline`, `Appearance`/`SetAppearance` (on a change repaints every element and sends `WindowStateEvent`), `TitleFrame`. The `shell.SurfaceHandler` is an unexported adapter: `Paint` = `PaintTree(root)`; `Resized` re-lays out the chrome, sets the chrome regions, refreshes the hover and reports `ContentResized` when the content size changed; `CloseRequested` asks `ShouldClose` only with `StyleClosable`; `KeyChanged` updates the router's active state, repaints every element, sends `WindowStateEvent` and then reports; `Event` goes to the `Router`. After `Closed` every method and handler call does nothing.
* **Chrome (`chrome.go`):** the title bar paints its key or inactive fill, a 1 pt bottom hairline (`ColorSeparator`, black in dark mode) and the title in `titleFont()` (the regular `Typography.FontSize` in `WindowTitleWeight`: 13 pt semibold, `ColorLabel`, `ColorTertiaryLabel` when inactive), laid out with the shell's `TextSystem`, centered and truncated to keep 68 pt (the lights plus 8 pt) from both edges: the longest rune prefix, trailing spaces dropped, plus "…", or nothing when not even "…" fits; newlines show as spaces. All metrics come from `Theme.Chrome` (S3.1c): the traffic lights (a11y buttons "Close", "Minimize", "Zoom" with `press`) are `LightSize` circles (12 pt) `LightStep` apart from `LightInset`, vertically centred (x = 8, 28, 48, y = 8), with a `LightBorderWidth` border stroked just inside the circle and glyphs drawn on a 12 pt grid scaled to `LightSize` with `LightGlyphStroke`; the title keeps `LightInset` + the group + `TitleGap` from both edges. They sit inside a group element whose hover (gaps included) shows the ×/−/+ stroked paths on all three; they are grey while the window is inactive unless hovered, 18 % darker while pressed, and disabled (half-transparent grey, no glyphs) when their style flag (`StyleClosable`, `StyleMiniaturizable`, `StyleResizable`) is missing. Clicks go through a `pressTracker` (S3.3a): a primary press captures; dragging off un-presses; a release over the light acts: `Surface.Minimize`, `Surface.Zoom`, or `ShouldClose` then `Surface.Close`. Chrome regions: the bar as `RegionCaption`, then each enabled light as `RegionClose`/`RegionMinimize`/`RegionMaximize` (disabled ones stay caption).
* **`Driver` (`driver.go`):** `New(sh shell.Shell) *Driver` implements `driver.Driver` (`Name` "aqua"). `Run` binds the calling goroutine to a fresh `mainthread.Queue`, runs the shell (its error, such as a missing GTK, is returned) and, on `shell.Handler.Ready`, reads the OS appearance, installs the queue's wake (one `Shell.Post(drain)` per wake-up, coalesced by the queue) and calls `AppHandler.Ready`; the queue is closed when `Run` returns; a second `Run` returns `ErrRunTwice`. `Queue()` (nil before `Run`) lets `gogui`'s `uiDriver` accept it. `Quit` closes the queue (later `Post`/`Do`/`DoSync` from other goroutines are dropped) and quits the shell, which closes every window; work queued before `Quit` still runs once. `Quit` before `Run` makes `Run` return without `Ready`. Appearance: the forced mode (`Mode`) is merged over the shell's appearance (only `Dark` is overridden); a change repaints every open window and calls `AppearanceChanged`, never before `Ready`. **Timeline** (S3.2b): at `Ready`, before `AppHandler.Ready`, the driver creates one `anim.Timeline` on `Shell.Clock()` and installs its `Tick` as the clock's only frame function (`Timeline()`, nil before `Ready`); the timeline's Reduce Motion follows the effective appearance (at `Ready` and on each change, before the windows repaint, so running animations finish first). `NewWindow` creates an aqua `Window` with the effective appearance and the driver's timeline (`Window.Timeline()`; nil for a window made with `aqua.NewWindow` directly) and tracks it until `Closed` (`Windows`). `SetMenuBar` records a copy (nil = `driver.DefaultMenuBar`, `MenuBar`) and `RunAlert` records the alert (`Alerts`, `Alert.Dismiss` calls `done`); neither draws yet. `NewContainer` returns an aqua `Container`, `NewLabel`, `NewSeparator`, `NewBox`, `NewButton`, `NewCheckbox` and `NewRadio` real controls; every other factory returns a placeholder peer. `Post` and `Queue` are safe from any goroutine; the rest is UI-thread only.
* **`Container` (`container.go`):** a real element that paints nothing. `SetChildren(widgets)` re-parents the widgets' elements (`ElementOf`), in order, stealing them from old parents and detaching the dropped ones; widgets without an element are kept in `Widgets` but invisible. Invalid lists (repeated element, self or ancestor) panic before anything changes. `SetControlSize` and `SetTooltip` only record, `Focus` does nothing, `Destroy` leaves the parent and keeps the children (`Destroyed`).
* **Label (`label.go`, S3.3c):** the first real control. `Label` embeds its `driver/stub` label (the state) and a `peerBase` bound with `initElement` to its own `label` element (no placeholder: `Caption` reports false). The font is the peer's `Font` with a zero size replaced by `Typography.FontSize` for the control size (`TextFont`). `FittingSize` is the `TextSystem` layout, wrapped at `max.W` when `Wraps` (real line widths, not the stub's area estimate), clamped to `max`; a stub `Fixed` size still wins. Paint: nothing for an empty frame or text; the text from the frame's top, clipped to the frame only when it does not fit; `AlignLeading` (and `AlignJustified`, the `TextSystem` has no justification) draws the layout once at x = 0; centre and trailing draw a single line once, offset by the free width (at least 0), and several lines one layout per visual line (`lines`: a line starts where the caret moves down; line breaks and wrap spaces trimmed, empty lines skipped). The color is `TextColor` (`ColorLabel` when zero) in the window's appearance (`appearanceIn`), `ColorDisabledControlText` when disabled in the tree. One layout is cached per label (text, font, wrap width). The setters (text, font, color, alignment, wraps, control size) repaint; `SetSelectable` is recorded only; the theme's line height and tracking are not applied. Not focusable; a11y `text` with the label's text.
* **Separator and Box (`group.go`, S3.3d):** real elements, built like the `Label` (stub state, `peerBase` with `initElement`, not placeholders, not focusable). Pixel helpers: `scaleIn` (the window surface's `Scale`, 1 outside a live window), `pixelWidth` (a width rounded to whole device pixels, at least one) and `pixelAlign` (a rect's edges snapped to device pixels in root coordinates, so it holds at any position). `Separator`: a `ColorSeparator` hairline `SeparatorThickness` thick (`pixelWidth`), along the frame's longer side and centred across it, pixel-aligned; a square frame follows `SetVertical` (which repaints); `FittingSize` is the thickness on both axes (1 × 1, as the stub), `Fixed` winning; a11y `separator`. `Box` (NSBox primary): with a non-blank title, the title in `BoxTitleSize`/`BoxTitleWeight` (one line, truncated to the frame width with "…", `ColorLabel`, `ColorDisabledControlText` when disabled in the tree) at the frame's top left, and the group `BoxTitleGap` below the title's line height rounded up to whole points (the band); the group is a `BoxCornerRadius` rounded rect (clamped to half its size) in `BoxFill` with a `BoxBorder` stroke `BoxBorderWidth` wide (`pixelWidth`; none for 0 or no room), its edges pixel-aligned. `ContentInsets` = `Controls.BoxContentInsets()` plus the band at the top (with the fake text metrics 26/10/8/10 titled, 8/10/8/10 untitled); the stub's insets stay for headless. `FittingSize` is the insets, `Fixed` winning. The content host is framed at those insets on `SetFrame` and `SetTitle`; the title layout is cached per title. The tokens do not depend on the control size. a11y `group` with the title.
* **Button (`button.go`, S3.3e):** a real push button, built like the `Label` (stub state, `peerBase` with `initElement`, not a placeholder), focusable with `FocusKind` `FocusControl`. `FittingSize`: `Metrics.Control(cs)`'s `Height` high and the title's width plus `PaddingX` on each side, rounded up to whole points, at least `ButtonMinWidth` wide (70 × 20 for a short regular title), clamped, `Fixed` winning; the title layout (one line, the system font size of the control size with `ButtonTitleWeight`) is cached per title and font. Paint: the bezel is the frame's width and `Height` high (at most the frame's), centred vertically and pixel-aligned (`pixelAlign`), with `CornerRadius`; then the `BezelShadow` (`DrawShadow`, the per-size offset, blur and spread), the fill `Theme.ButtonFill(a, isDefault, pressed, key)`, the 1 pt `BezelBorder` (whole device pixels; not on the accent fill, nor without room), the title centred in the bezel in `Theme.ButtonText`, truncated with "…" to the bezel minus the padding (nothing when no room), and the focus ring around the bezel last. The state is the `pressTracker`'s `ControlState` (`pushButton.State`): pressed while a primary press is over it; a default button is accent-filled with `AccentText` only in a key window and while enabled (inactive or disabled it is drawn plain); disabled: the disabled text color. `HandleEvent` tracks the ring and the press (a release over the button calls `UserClick`); a disabled button drops a press and handles nothing. `Activate` is `UserClick`, false when disabled in the tree. `SetTitle`, `SetDefault` and `SetControlSize` repaint; `SetDefault`/`SetCancel` also set the element's marks (S3.2f). a11y `button` with the title and `press`.
* **Checkbox (`checkbox.go`, S3.3f):** a real checkbox, built like the `Button` (stub state and toggle rule, `peerBase` with `initElement`, not a placeholder), focusable with `FocusKind` `FocusControl`. `FittingSize`: the box (`CheckboxSize`, 14 regular), then `CheckboxGap` and the title's width, rounded up to whole points, as high as the box or the title's line (rounded up), whichever is higher (48 × 16 for "Wrap" on the fake text system; the box alone without a title), clamped, `Fixed` winning; the title layout (one line, `Typography.FontSize` of the control size, regular) is cached per title and font. Paint: the box at the leading edge, its side the token (at most the frame's width and height), centred vertically and pixel-aligned, `CheckboxRadius` rounded; filled with `Theme.ToggleFill(a, on, pressed, key)` (mixed counts as on); off: the 1 pt `BezelBorder` in whole device pixels (none without room); on: a check, mixed: a dash, stroked `CheckboxMarkStroke` wide with round caps and joins in `AccentText` on a 14-unit grid of the box (no border); while disabled in the tree the box and its mark are drawn in a `PushOpacity(ToggleDisabledAlpha)` layer. Then the title at x = box + gap, centred vertically, in `ColorControlText` (`ColorDisabledControlText` when disabled), truncated with "…" to the frame (nothing when no room or lower than its line), and the focus ring around the box last. The whole frame is the hit area: `HandleEvent` tracks the ring and the `pressTracker` (a release over it calls `UserClick`, the stub's toggle: off → on, on → off, mixed → on, with the handler's `StateChanged`); a disabled checkbox drops a press and handles nothing. `Activate` (Space, the a11y press) is `UserClick`, false when disabled in the tree. `SetTitle`, `SetState`, `SetControlSize` and `UserClick` repaint. a11y `checkbox` with the title, `checked` or `mixed`, and `press`.
* **Radio (`radio.go`, S3.3g) and the toggle helpers (`toggle.go`):** a real radio button, built like the `Checkbox` (stub state and click rule, `peerBase` with `initElement`, not a placeholder), focusable with `FocusKind` `FocusControl`. `toggle.go` holds what both share: the title font (`toggleFont`), the cached one-line title layout (`toggleTitle`), the fitting size of mark + gap + title (`toggleSize`) and the title paint (`paintToggleTitle`). `FittingSize`: the circle (`RadioSize`, 14 regular), then `RadioGap` and the title's width, rounded up, as high as the circle or the title's line (48 × 16 for "Wrap" on the fake text system; the circle alone without a title), clamped, `Fixed` winning. Paint: the circle at the leading edge, its diameter the token (at most the frame's width and height), centred vertically and pixel-aligned, filled with `Theme.ToggleFill(a, on, pressed, key)` (the accent when on, `AccentInactive` grey in an inactive window, `BezelPressedFill`/`AccentPressed` while pressed); off: the 1 pt `BezelBorder` in whole device pixels (none without room); on: a centred dot of `RadioDotSize` (scaled with the circle) in `AccentText`, no border; disabled in the tree: circle and dot in a `PushOpacity(ToggleDisabledAlpha)` layer. The title and the focus ring (around the circle, last) as the checkbox's. The whole frame is the hit area through a `pressTracker`; a release over it calls `UserClick` (the stub's rule: on, and `StateChanged(StateOn)` even when it was on already, like AppKit); a disabled radio drops a press and handles nothing; `Activate` (Space, the a11y press) is `UserClick`, false when disabled in the tree. Exclusivity is not the radio's: the public `RadioGroup` turns the others off through `SetOn` when one reports `StateOn`, and reports `OnChange` only for a new index (no peer API change). **The arrow keys do not move the selection inside a group (not in v0.1)**; each radio is its own Tab stop with full keyboard access. `SetTitle`, `SetOn`, `SetControlSize` and `UserClick` repaint. a11y `radio` with the title, `checked` when on, and `press`.
* **Slider (`slider.go`, S3.4c–S3.4d):** a real slider, built like the `Checkbox` (stub state, `peerBase` with `initElement`, not a placeholder), focusable with `FocusKind` `FocusControl`. `FittingSize`: the stub's default length (96) along, across it the knob (`SliderKnobSize`, 20 regular) plus, with tick marks, `SliderTickGap` and `SliderTickLength`, rounded up (96 × 20, 96 × 28 with marks; a vertical slider turned), clamped, `Fixed` winning. Layout (`sliderGeometry`): the knob and the marks form a band centred across the frame, the marks below the knob (vertical: after it); the track runs the frame's whole length, `SliderTrackThickness` thick, centred on the knob's line; the knob (at most the frame's depth and length) travels from half a knob in at one end to half a knob in at the other, the minimum at the left (vertical: the bottom); an empty range puts it at the minimum; n marks spread evenly over the travel (one in the middle), not drawn when they would leave the frame. Paint: the track in `SliderTrack`, its part from the minimum to the knob's centre in `Theme.ValueFill` (grey in an inactive window), the marks in `SliderTickMark` (round ends), the knob's shadow, its fill (`SliderKnobFill`, `BezelPressedFill` while dragged) and its inner `SliderKnobBorder`; rects pixel-aligned; disabled in the tree, every color at `ValueDisabledAlpha` (no layer); the focus ring around the knob, last. Pointer: a primary press captures; on the knob it grabs it where hit and the value stays until the pointer moves along the slider (no float round trip); on the track the knob jumps there first (a handler that disables or hides the slider ends the press). While held the value follows the pointer (clamped, also off the frame; `valueAt` gives the exact minimum and maximum at the ends), snapping to the nearest mark with `SnapToTick` (the last mark exactly the maximum); `ValueChanged` on every change, never for an unchanged value (`userSet`). Release or `PointerCancel` ends the drag; other buttons are swallowed during it; disabled drops it. Keys while focused, no modifiers: Right/Up and Left/Down by `Step` (a twentieth of the range, or one mark when snapping to ≥ 2 marks), Page Up/Down by `PageStep` (a fifth, at least `Step`), Home/End the ends; consumed even at an end. `constrain` clamps, snaps, maps a value within 1e-9 of the range of an end to that end (repeated steps reach it exactly) and NaN to the minimum. `Increment`/`Decrement` on the element (the a11y actions) step by `Step`, refused while disabled. `UserDrag` goes through the same `userSet` (ignored when disabled in the tree). `SetRange`, `SetValue`, `SetTickMarks`, `SetVertical`, `SetControlSize` repaint. a11y `slider` with the value and `increment`/`decrement`. `testdata/slider.states` pins the states (normal, pressed, disabled, focused, marks, vertical) in light/dark × key/inactive.
* **Progress (`progress.go`, S3.4e–S3.4f):** one real peer for `ProgressBar` and `Spinner` (`driver.ProgressSpinner`), built like the `Slider` (stub state, `peerBase` with `initElement`, not a placeholder); not focusable, no input. `FittingSize`: a bar is the stub's default length (96) wide and `ProgressThickness` high (96 × 6 regular), a spinner `SpinnerSize` square (32 regular), rounded up, clamped, `Fixed` winning. Bar: the track the frame's whole width, `ProgressThickness` high (at most the frame's) with `ProgressRadius`, centred vertically, in `ProgressTrack`; a determinate bar fills from the left to the value's fraction in `Theme.ValueFill` (grey in an inactive window; nothing for an empty range or NaN), the fill's radius at most half its width; rects pixel-aligned. Spinner: `SpinnerSpokes` round-capped spokes, the first at twelve o'clock and clockwise, `SpinnerSpokeLength` from the outer edge inwards, `SpinnerSpokeWidth` wide, `SpinnerSize` across and centred (a smaller frame scales it down); determinate: the first ⌊fraction × spokes⌋ in `SpinnerSpoke`, the others at `SpinnerTailAlpha`; coordinates rounded to 1e-6. Disabled in the tree: every color at `ValueDisabledAlpha`, no layer. **Indeterminate (S3.4f):** the phase is an `anim.Value.Loop` on the window's timeline (`ProgressBandPeriod` for the bar, `SpinnerPeriod` for the spinner, retimed on a style change): the bar's band (`ProgressBandFraction` of the track) at x = −band + phase × (track + band), clipped to the track; the spinner's leading spoke at ⌊phase × spokes⌋, the spokes behind fading linearly to `SpinnerTailAlpha`. The loop runs only while *live*: indeterminate, visible in the tree, in a `Window.Shown` window with a timeline. `SetIndeterminate(false)` and the peer's `SetHidden(true)` stop it at once; an ancestor hidden, leaving the window (`SetContent`, `Destroy`) or the window closing stop it at the next frame (the change func checks `live`); it starts again from `SetIndeterminate(true)`, `SetStyle`, `SetHidden(false)` and from any `Paint` that finds it live (a returning subtree or a shown window repaints). Reduce Motion stops it (the timeline) and draws a static look: the bar's whole track in `ValueFill` at `ValueDisabledAlpha`, the spinner's fade with the lead at twelve o'clock; turning it off repaints every window and the paint restarts the loop. An app with no live indicator requests no frames. a11y `progress` with the value, none while indeterminate. `testdata/progress.states` pins the determinate bar and spinner (enabled, disabled) in light/dark × key/inactive; `progress_anim_test.go` runs the loop on the fake clock.
* **ScrollView (`scrollview.go`, S3.5d–S3.5g):** a real peer (stub state, `peerBase` with `initElement`, not a placeholder, not focusable). Its `scrollArea` element (a11y `RoleScrollArea`; it paints only the corner between two legacy tracks, in `LegacyScrollerTrack`) holds the clipping viewport host at the frame minus `ViewportInset`, which holds the document host at minus the *shown* offset (overscroll included) with the document size. Two `scroll.Axis` (`ThemeParams(tokens)`) on the driver's timeline drive it (without one, a driver not yet running, a still timeline with Reduce Motion: everything jumps, and an overlay scroller once shown never fades); the stub's `Off` is the clamped offset, `Scrolled` fires once per change of it from input or momentum. A `ScrollEvent` drives only the axes with a scroller; a wheel or phase-less precise event is taken when such an axis can move by it, else it bubbles; a `PhaseBegan` is declined only when no axis can move by it and an enclosing scroll view can (which then takes the whole gesture), else taken (rubber band at the edge). `SetOffset`, `ScrollRectToVisible` and `UserScroll` stop any gesture or animation at the stub's offset; `SetFrame`, `SetDocumentSize` and `UserResizeViewport` update the axes' viewport and range (an overscrolled or decaying axis springs back to a new edge); none of them fires `Scrolled` (`UserScroll` through the stub). Since S3.5e a taken scroll event and every offset change from input or momentum (not from `sync`, i.e. not `SetOffset`, `ScrollRectToVisible`, layout) show the overlay scrollers; `UserScroll` shows them too. **Legacy scrollers** (S3.5f): `Appearance.LegacyScrollers` of the window (the driver's outside one) sets `ViewportInset` to `LegacyScrollerThickness` on the right (vertical scroller) and the bottom (horizontal) — from the appearance and the scroller flags only, never the document, so it cannot oscillate. Read at creation, on every `SetFrame` (silently: the layout reads `ViewportSize` right after), and on `SetHas…Scroller` and `WindowStateEvent` (then `ViewportResized` fires once, through the stub's `UserResizeViewport`, and the public layer re-lays out). `Legacy()` reports the kind; a change of kind drops the scrollers' hover and press. Pointer moves bubbling to `scrollArea` (it handles none) drive the scrollers' hover, only while it is enabled in the tree and only over the strip of an overlay scroller whose axis can scroll; `PointerLeave` ends it. **Keys** (S3.5g) bubbling to `scrollArea` (key-down and repeat, not while a scroller is pressed): Page Up/Down by the viewport − `PageOverlap` (the whole viewport when not longer), Home/End to the ends, Space/Shift-Space as Page Down/Up only when the focused element is not a `FocusControl` (other than the scroll view itself, so Space still presses a focused button or checkbox), the arrows by `WheelLineHeight` only when the scroll view itself has the focus (it is not focusable by default). Paging, Home and End move the vertical axis if it has a scroller, else the horizontal one; arrows only their own axis with a scroller. A step starts from a running key or wheel step's target (`Axis.Stepping`, so repeats add up), animates like a wheel step (`WheelStepDuration`, a jump under Reduce Motion), fires `Scrolled` and shows the overlay scrollers; any modifier except Shift on Space leaves the key alone; a key that cannot move the offset is not taken and bubbles on (an enclosing scroll view). **Scroll-to-focused** (S3.5g, the router's focus hook): the element's frame in document coordinates grown by the full focus ring (`FocusRingBand(1)`: outset + width) is brought into the viewport by the least scroll (far edge first, then near, so a rect longer than the viewport shows its top-left), on the axes with a scroller, at once (no animation, so an enclosing scroll view, called next, sees the final offset), from a running step's target; it fires `Scrolled` and shows the scrollers when it moved.
* **Scrollers (`scroller.go`, S3.5e–S3.5f):** one `scroller` element per axis, children of `scrollArea` after the viewport (drawn on top), not exposed to a11y. Overlay: a strip `ScrollerHoverThickness + 2·ScrollerInset` wide inside the viewport's trailing edge (the vertical and horizontal strips cut the corner when both axes are active); the knob `ScrollerInset` from the edge, `ScrollerThickness` thick, widening to `ScrollerHoverThickness` over `ScrollerHoverDuration` (EaseOut) while hovered, in `ScrollerKnob` × opacity. Legacy: a `LegacyScrollerThickness` strip outside the viewport, `LegacyScrollerTrack` fill, a one-device-pixel `LegacyScrollerBorder` on the content side, the knob `ScrollerHoverThickness` centred and opaque; always shown while the axis has a scroller. Knob along the track (`ScrollerInset` from both ends): length track × viewport/document, at least `ScrollerMinKnobLength`, at most the track; position by the clamped offset; overscroll shortens it by |overscroll| × track/viewport down to its thickness, pinned to the pushed edge; no knob without range or on a track shorter than the knob's thickness; rects pixel-aligned, the knob's corners half its thickness. Opacity is an `anim.Value`: `Set(1)` on user scrolling and while hovered or pressed, then `AnimateAfter(0, ScrollerFadeDelay, ScrollerFadeDuration, EaseInOut)`, re-armed by each change (so it counts from the end of the motion); at 0 the element is hidden (not painted, not hit-tested; the content gets the pointer). An overlay scroller shows only while its axis can scroll; one that loses its range while shown hides. Under Reduce Motion the delay runs and it is hidden at once, and the hover widening jumps. Input (S3.5f): a primary press on the knob's span (anywhere across the strip) captures, stops the axis and drags the offset 1:1 from where the knob was grabbed (clamped, also off the strip; `Axis.ScrollTo` without animation; `Scrolled` per change); on the track before/after the knob it pages by max(viewport − `PageOverlap`, viewport/2), animated like a wheel step (from a running page's target, so clicks accumulate); release or `PointerCancel` ends it and arms the fade; other buttons are swallowed during a press; while a scroller is pressed the scroll view swallows scroll events (latched OS momentum or a wheel would move the offset under the pointer); a track click accumulates only from a running page or wheel step (`Axis.Stepping`), not from a momentum's rest; disabled (the scroll view or an ancestor): no input, still drawn.
* **Placeholder peers (`placeholder.go`, `controls.go`):** `TextField` (secure too), `PopUpButton` and `TextView`. Each embeds its `driver/stub` peer (state, getters, `User…` simulations, fake `FittingSize`, so the example layouts equal the headless ones; `StubPeer`, `Stub`) and owns a placeholder element (`AquaElement`); the peer itself is not an element. `ElementOf(w)` returns a widget's element (an element itself, a placeholder's, or nil); `Container` and `Window.SetContent` use it. The `driver.Widget` methods reach both sides (frame, enabled, hidden, `Focus` counted and moved to the element, `Destroy` leaves both parents); setters that change what is shown repaint, and so do the placeholders' `User…` methods. The element paints a 4 pt rounded rectangle (`ColorControl` fill, `ColorTertiaryLabel` 1 pt border, in the window's appearance) and its caption in 11 pt (`PlaceholderFont`) at x = 4, vertically centred: "Kind: text" (`Caption`) when it fits, else the text alone (or the kind) truncated with "…", nothing when that doesn't fit; `ColorDisabledControlText` when disabled in the tree. Text: the field's text (bullets when secure) or placeholder, the pop-up's item, a text view's first line. Text fields, text views and pop-up buttons are focusable (S3.2d); text fields and text views have `FocusKind` `FocusText`, the others `FocusControl` (S3.2e); the placeholders have no primary action (`Activate` false), and the element tracks a `FocusRing` (`Track` in `HandleEvent`, which handles nothing) and paints it last around its rounded rect; an empty frame paints nothing, ring included. Each has an a11y node with its role and label, value and states (read-only) and actions; secure fields expose no value. These are the placeholders left: the `Slider` became real in S3.4c–S3.4d (`slider.go`), `Progress` in S3.4e–S3.4f (`progress.go`), `ScrollView` in S3.5d (`scrollview.go`), `TextField`, `TextView` and `PopUpButton` in phase 5.
* **Colors (`colors.go`):** the driver draws with `tokens = &theme.Sequoia`. `resolveColor`/`semantic` go through `Theme.Resolve` (accent rules, unknown colors magenta); the title bar and traffic lights read `Theme.Chrome` (key/inactive fill, the bottom hairline, per-light fill/border/glyph, the grey inactive light, `LightPressedShade` and `LightDisabledAlpha`); the chrome metrics and the title font come from `Theme.Chrome` and `Theme.Typography` (S3.1c). No color value or chrome metric is written in the package any more; the placeholders keep the `driver/stub` layout metrics until S3.3.

### 9.1 `internal/aqua/theme`: design tokens

The tokens of the drawn controls (PLAN.md §5.2). Imports only `driver` (besides the standard library's `math` and `time`); no build tags. Used by `aqua` (every color it draws) and `shell/win32` (the clear color).

* **`Theme`** (hand-written, `theme.go`): `Name` and `Colors`, an array of `ColorToken` indexed by `driver.SemanticColor` (index 0, `SemanticNone`, unused and zero). `ColorToken` has `Light`, `Dark` and, when `HasContrast`, `ContrastLight`/`ContrastDark`; all concrete. `ColorToken.Value(a)` picks dark or light, the contrast variant only with `a.IncreaseContrast` and `HasContrast`; `Theme.Color(s, a)` does the same by semantic color and reports false for `SemanticNone` and unknown colors; neither applies the accent rules. `Theme.Resolve(c, a)` is what the driver uses: a concrete `c` unchanged, `ColorControlAccent`, `ColorSelectedContentBackground` and `ColorSystemBlue` to `a.Accent`, `ColorKeyboardFocusIndicator` to `FocusRing(a)`, `ColorSelectedTextBackground` and `ColorSelectedControl` to `Selection(a)`, other semantic colors to their token (its contrast variant with `IncreaseContrast`), unknown ones to `Unknown` (opaque magenta). **Accent rules** (`accent.go`, S3.1d; D10: the accent follows the OS): accent-derived colors are computed, never stored, from `a.Accent` and the `Theme.Accent` tokens: `FocusRing` (alpha × `FocusRingAlpha`, 0.5; with `IncreaseContrast` the accent itself, S3.2d), `Selection` (the accent at `SelectionAlpha` 0.3 over the opaque `Base`, white / 89 grey), `AccentPressed` (channels × `PressedShade`, 0.85), `AccentInactive` (the accent's Rec. 709 luma as a grey at `InactiveAlpha` 0.35 over `Base`, for accent fills in an inactive window) and `AccentText` (`DefaultButtonText`). The semantic tokens of the accent colors keep their default-accent values as references only. **Contrast** (S3.1d): 13 colors have a pair (the four labels, placeholder text, separator, grid, link, control text and disabled control text; `TitleBarSeparator`, `LightInactiveBorder`, `BezelShadow`). `Theme.Animation` (S3.1d): `DurationFast`/`Normal`/`Slow` (100/250/400 ms), `FocusRingDuration`, `ScrollerFadeDelay`/`Duration`, the cubic-bezier `Curve`s `EaseIn`, `EaseOut`, `EaseInOut`, `EaseDefault` (Core Animation's), the `Spring`s `ControlSpring` and `RubberBandSpring` (mass, stiffness, damping; `DampingRatio`), and `Duration(d, a)`, zero with Reduce Motion. Nothing uses the accent helpers beyond `Resolve`, or the animation tokens, before S3.2/S3.3. `Theme.Chrome` holds the window-chrome tokens that are not semantic colors: `TitleBar`, `TitleBarInactive`, `TitleBarSeparator`, `Close`/`Minimize`/`Zoom` `Fill`/`Border`/`Glyph`, `LightInactiveFill`/`Border` (all `ColorToken`) and the numbers `LightPressedShade` (0.82) and `LightDisabledAlpha` (0.5), plus (S3.1c) the chrome metrics `TitleBarHeight` (28), `LightSize` (12), `LightStep` (20), `LightInset` (8), `TitleGap` (8), `LightBorderWidth` (0.5) and `LightGlyphStroke` (1.2). `Theme.Metrics` (S3.1c): `SizeTable`s (`[NumControlSizes]float64` indexed by `driver.ControlSize`; `At(cs)` maps an unknown size to regular) `ControlHeight`, `ControlPaddingX`, `ControlCornerRadius`, `BezelShadowOffsetY`/`Blur`/`Spread`, the `BezelShadow` color and `FocusRingWidth`/`FocusRingOffset`; `Metrics.Control(cs)` collects one size into a `ControlMetrics`. Nothing draws with them before S3.2/S3.3, and the placeholders keep the `driver/stub` layout metrics. `Theme.Typography` (S3.1c): `FontSize` per control size (13, 11, 9, 13, equal to `driver.Font.EffectiveSize`), `LineHeight` (a factor of the font size, 1.23), `WindowTitleWeight` (600) and `EmphasizedWeight` (700), and the SF-like `Tracking` table (`TrackingStep{Size, Tracking}` in 1/1000 em, the HIG's SF Pro values from 6 to 80 pt applied to Inter); `TrackingAt(size)` interpolates linearly and clamps to the end rows, `TrackingPoints(size)` gives points, `LineHeightFor(size)` points. The win32 text system does not apply tracking or line height yet (S3.3 and S5 use them). `Theme.Controls` (S3.3b): the bezel colors `BezelFill`, `BezelPressedFill`, `BezelBorder` (off-state push button, checkbox box, radio circle) and `BoxFill`, `BoxBorder`; the numbers `BoxCornerRadius` (6), `BoxBorderWidth` (1), `BoxTitleSize` (11), `BoxTitleGap` (4), `BoxContentInsetX`/`Y` (10, 8) , `SeparatorThickness` (1) and `ToggleDisabledAlpha` (0.5, S3.3f: the opacity of a disabled checkbox's box or radio's circle); the per-size rows `ButtonMinWidth` (70, 60, 50, 80), `CheckboxSize`, `CheckboxRadius`, `CheckboxMarkStroke`, `CheckboxGap`, `RadioSize`, `RadioDotSize`, `RadioGap`; the weights `ButtonTitleWeight` and `BoxTitleWeight` (400). `Controls.BoxContentInsets()` gives the content insets from the group's edges. The accent-colored fills are computed (`controls.go`): `ButtonFill(a, isDefault, pressed, key)` (a default button in a key window: the accent, `AccentPressed` while pressed; otherwise, inactive default buttons included, `BezelFill`/`BezelPressedFill`; a disabled default button is passed as plain), `ButtonText(a, isDefault, key, disabled)` (`AccentText` on the accent fill, else `ColorControlText`, `ColorDisabledControlText` when disabled) and `ToggleFill(a, on, pressed, key)` (on or mixed: the accent, `AccentPressed`, `AccentInactive` in an inactive window; off: the bezel fills). The `Button` draws with `ButtonFill` and `ButtonText` (S3.3e); the `Checkbox` with `ToggleFill` and `AccentText` (S3.3f). **Value controls (S3.4a):** the colors `SliderTrack` (the empty part), `SliderKnobFill`, `SliderKnobBorder`, `SliderKnobShadow`, `SliderTickMark`, `ProgressTrack`, `SpinnerSpoke` (contrast pairs except the knob fill); the numbers `SliderKnobBorderWidth` (0.5), `ProgressBandFraction` (0.25, the indeterminate band as a fraction of the track), `SpinnerSpokes` (12, a whole number as a float), `SpinnerTailAlpha` (0.25, the faintest spoke, fading linearly) and `ValueDisabledAlpha` (0.5); the per-size rows `SliderTrackThickness`, `SliderTrackRadius`, `SliderKnobSize` (20, 14, 11, 24), `SliderKnobShadowOffsetY`/`Blur`, `SliderTickLength`/`Width`/`Gap`, `ProgressThickness` (6, 4, 3, 8), `ProgressRadius`, `SpinnerSize` (32, 16, 10, 32), `SpinnerSpokeLength`/`Width`; the durations `ProgressBandPeriod` (1.2 s) and `SpinnerPeriod` (1 s). The filled track is computed: `ValueFill(a, key, disabled)` (the filled part of a slider's track, of a progress bar and the indeterminate band: the accent in a key window, `AccentInactive` in an inactive one, alpha × `ValueDisabledAlpha` when disabled; no pressed shade). The `Slider` draws with them since S3.4c; the `Progress` (bar and spinner) since S3.4e. `Theme.Scroll` (S3.5a, the last field; the fade timing and `RubberBandSpring` stay in `Animation`): the colors `ScrollerKnob` (translucent, overlay and legacy knob), `LegacyScrollerTrack` (opaque) and `LegacyScrollerBorder` (contrast pairs except the track); the numbers `ScrollerThickness` (6, an idle overlay knob), `ScrollerHoverThickness` (9, hovered and legacy), `ScrollerInset` (2), `ScrollerMinKnobLength` (18), `LegacyScrollerThickness` (15, taken from the viewport), `WheelLineHeight` (16 pt per line), `MomentumDecayRate` (2 per second, v = v0·e^(−k·t)), `MomentumStopVelocity` (20 pt/s), `RubberBandFraction` (0.55, the constant c of §5.6 as a fraction of the viewport) and `PageOverlap` (10); the durations `ScrollerHoverDuration` (150 ms), `WheelStepDuration` (150 ms) and `VelocityWindow` (80 ms, shorter than the Win32 ~100 ms gap before the late `PhaseEnded`). Nothing reads them before S3.5c.
* **`tokens.go`** (generated, committed): `var Sequoia = Theme{…}`, one line per token, `// provisional` on values from memory. All 39 colors (the 12 of the former `provisional.go` unchanged, the other 27 from memory), the 23 chrome tokens (the former `provisional.go`/`chrome.go`/`window.go` values, unchanged), 9 metrics tokens, 5 typography tokens, 6 accent tokens, 12 animation tokens (S3.3b) 23 basic-control tokens, (S3.4a) 27 value-control tokens and (S3.5a) 16 scroll tokens: 160, all provisional (a size row, a curve, a spring and the tracking table count as one each).
* **Spec** (`spec/sequoia.json`): `name` (exported Go identifier), optional one-line `comment`, and `colors`: per `driver` constant name `light` and `dark` as `[r, g, b]` or `[r, g, b, a]` (integers 0..255, missing alpha 255), optional `contrastLight` + `contrastDark` (both or neither), required `source` (`"memory"` = from memory, to be measured in S3.1t; `"measured"`), optional one-line `note`; and the groups `chrome`, `metrics`, `typography`, `accent`, `animation`, `controls` and `scroll` (one per `Theme` struct field), each with `colors` (same form), `numbers` (`value`, a finite float32), `sizes` (`regular`, `small`, `mini`, `large`, each a finite float32), `weights` (`value`, an integer in 1..1000), `durations` (`ms`, an integer in 0..60000), `curves` (`value`: x1, y1, x2, y2, finite, x1 and x2 in 0..1), `springs` (`mass`, `stiffness`, `damping`, each finite and positive) and, for `typography` only, `tracking` (`steps`: `[size, tracking]` pairs by strictly ascending positive size), every entry with `source` and an optional `note`. Unknown fields, unknown or missing groups or tokens and trailing data are errors.
* **Generator** (`gen`): `Parse(data) (*Spec, error)` validates; `Generate(spec, specPath) (goSrc, doc, err)` returns the gofmt-formatted Go file and `docs/tokens.md` (a colors table and a section per group, one row per token, a table per control size, the tracking table, hex values, contrast columns, source with `memory` in bold, notes; a count of provisional tokens in both headers). `ColorNames` lists the driver constants in declaration order; `Groups` is the schema: per group its `Theme` field, JSON key, heading and field names by kind (colors, numbers, sizes, weights, durations, curves, springs, tracking); the Go file imports `time` when a group has durations. `gen/gentokens` is the command behind `//go:generate` in `theme.go` (`go generate ./internal/aqua/theme`, paths relative to the package); stdlib only.

### 9.2 `internal/aqua/anim`: animation math and timeline

The animations of the drawn driver (PLAN.md §5.5): the pure math since S3.2a, animated values on the frame clock since S3.2b, repeating loops since S3.4b, momentum and released springs since S3.5c, delayed tweens since S3.5e. Imports only `aqua/theme`, `driver` (value types) and the standard library; no build tags. The aqua `Driver` owns the one `Timeline` (§9); since S3.2d the focus ring (`aqua.FocusRing`) animates on it.

* **`Curve`** (`= theme.Curve`, so a token converts with `anim.Curve(th.Animation.EaseOut)`): a cubic bezier from (0, 0) to (1, 1); `Linear`. `At(t)` clamps t to 0..1 (NaN → 0; `At(0)` = 0 and `At(1)` = 1 exactly) and returns y at x = t: Newton from s = t, converging on s (step < 1e-14), with a bisection fallback down to 1e-15 when the slope is below 1e-3 or a step leaves 0..1. X1/X2 must be in 0..1; Y1/Y2 may overshoot. Where x is flat and y steep, the result is limited by float64 conditioning (a few 1e-6 at a flat middle), not by the solver.
* **`Spring`** (`= theme.Spring`): `Motion(from, to, v0)` panics unless mass, stiffness and damping are positive and finite. **`Motion`** has `From`, `To`, `V0`, `Spring()`, `DampingRatio()` and `At(t time.Duration) (x, v)` in closed form for every regime (`basis`: under-damped e^(−at)·cos/sin, critical e^(−at)·(1, t), over-damped written with e^(−(a−ω)t) and `Expm1`, so neither near-critical cancellation nor overflow at any t); t ≤ 0 gives `From`, `V0`. A late frame lands exactly where a punctual one would.
* **Settling:** `Settled(t, eps)` bounds the reachable displacement √(x² + v²/ω₀²) and speed √(ω₀²x² + v²) from the spring's energy, which never grows, so once true it stays true. `SettleTime(eps)` is the first settled time to the microsecond (rounded up) by doubling and bisection: 0 at rest, `MaxSettleTime` (1 h) if never; it panics for eps ≤ 0. The control spring settles to 1e-3 in 100 ms–1 s.
* **`Curve.Slope(t)`** (S3.2b): dy/dx at the time fraction t (clamped like `At`), so a tween moves at (b − a)·Slope/d; 0 where x is flat in the curve parameter (an unbounded slope at an end with X1 = 0 or X2 = 1).
* **`Timeline`** (`NewTimeline(c anim.Clock)`; `Clock` is `Now` + `RequestFrame`, which `shell.FrameClock` has; panics on nil). `Tick(frameTime)` is the frame function: every running value is sampled at the frame time (closed form, so a late frame lands where a punctual one would and values step by whole frames); a finished value takes its exact target and stops; change funcs run in start order and may start, retarget or stop any value (a value started during `Tick` starts at the frame time; stopped values are unlisted after the loop, so a stop-and-restart stays listed once). `Tick` requests the next frame only while a value still runs, so an idle app requests none; a `Tick` inside a `Tick` panics, and a panicking change func leaves the timeline usable. `Running()` counts the running values. `SetReduceMotion(on)`/`ReduceMotion()`: with it on, `AnimateTo`, `SpringTo` and `SpringFrom` jump like `Set`, `Decay` jumps to its rest, `Loop` stays at 0, and turning it on finishes every running value at once (a loop stops at 0); turning it off restarts nothing.
* **`Value`** (`Timeline.NewValue(x, onChange)`; `onChange` may be nil and is called with the new value whenever it changes: in `Tick` and from the jumps). `Value()` is what the last frame (or jump) set, `Velocity()` its units per second (0 at rest), `Target()` the running end value (else the value), `Running()`. `Set(x)` jumps and stops; `Stop()` stays where the last frame left it, with no velocity. `AnimateTo(x, d, c)` runs `Lerp(from, x, c.At((t − start)/d))` and ends exactly at x; `SpringTo(x, s)` runs `s.Motion(from, x, v0)` and ends at x once `Settled` within `SettleEpsilon` (1e-3). Both start at the clock's `Now` (the frame time inside a `Tick`) and retarget from where the running animation is at that moment (sampled there, not the last frame's value), a spring with that velocity, which for a tween comes from its curve's `Slope`; animating to the running target, or to the value of a value at rest, does nothing (repeated calls do not restart); `d ≤ 0` jumps. Non-finite values panic, and an invalid spring panics even when Reduce Motion makes it jump.
* **`Value.SpringFrom(x, v0, s)`** (S3.5c): `SpringTo` released with the explicit velocity v0 from the position at the start; it always (re)starts, except for a value at rest at exactly x with v0 = 0. **`Value.Decay(v0, rate, vs)`** (S3.5c): momentum from the position at the start, x = from + v0/rate·(1 − e^(−rate·t)), v = v0·e^(−rate·t) in closed form, ending exactly at the rest from + sign(v0)·(|v0| − vs)/rate when the speed reaches vs (the same motion as `scroll.Decay`; `anim` does not import `scroll`); `Target` is the rest; |v0| ≤ vs stops where the value is, with no velocity; it always restarts; retargets from it start at its position and velocity. Panics for a non-finite v0, a rate that is not positive and finite, vs ≤ 0 or NaN, a non-finite rest.
* **`Value.AnimateAfter(x, delay, d, c)`** (S3.5e): a tween marked delayed whose start is `delay` after the call: the value stops where the running animation is and holds there with no velocity (no change calls) until then, then tweens to x; `Target` is x at once; it always restarts (re-arming the delay), except for a value at rest at exactly x; `delay ≤ 0` is `AnimateTo`. The delay is not motion: under Reduce Motion it still runs and the value jumps at its end, and `SetReduceMotion(true)` during the delay keeps it (a running non-delayed tween jumps at once, as before). The timeline requests frames during the delay (no timers). The overlay scrollers' fade-out uses it.
* **`Value.Loop(period)`** (S3.4b): a repeating phase in [0, 1), frac((t − start)/period) at the frame time from the exact nanosecond remainder, so late frames and long runs do not drift (clamped below 1). It starts at 0 (a jump at the clock's `Now`, the frame time inside a `Tick`), never finishes, and keeps the timeline requesting frames until `Stop` (keeps the phase), `Set`, `AnimateTo`/`SpringTo` or Reduce Motion ends it. `Loop` with the running period does nothing; another period retimes it from the current phase without a jump. `Velocity` is 1/period seconds, `Target` the current value. A retarget from a loop always starts, from its phase (a spring with velocity 1/period). Under Reduce Motion `Loop` is `Set(0)`; owners re-call `Loop` when it is turned off (the `Progress` does it from its next paint, S3.4f). Panics on period ≤ 0.
* **Interpolation:** `Lerp(a, b, t)` = (1−t)·a + t·b (exact end points, t not clamped); `LerpColor` per sRGB channel and straight alpha, each clamped to 0..1, panics on a semantic color; `LerpPoint`; `LerpSize` and `LerpRect` clamp negative sizes to 0.

### 9.3 `internal/aqua/scroll`: scroll physics

The physics of the ScrollView (PLAN.md §5.6), since S3.5b as pure one-dimensional math (one instance per axis), since S3.5c the offset model `Axis` on the frame clock, which the aqua `ScrollView` (S3.5d) runs one of per scrolling axis. Imports `aqua/anim`, `aqua/theme` and `shell`; no build tags. Lengths in points, velocities in points per second, times `time.Duration` on the frame clock; the token values (`Theme.Scroll`) are passed in by the caller.

* **`RubberBand(d, c)`**: the overscroll shown for a drag d past an edge, d·c/(d+c): 0 at the edge with slope 1, strictly increasing, below c (+Inf gives c); odd in d. `RubberBandInverse(x, c)` = x·c/(c−x) maps it back (±Inf for |x| ≥ c), so a drag caught during the spring-back continues 1:1. c is in points (the caller multiplies `RubberBandFraction` by the viewport length); c ≤ 0 or NaN means no overscroll (both return 0); NaN in, NaN out.
* **`Decay`** (`NewDecay(v0, k, vs)`; panics unless k is positive and finite): v(t) = v0·e^(−k·t), x(t) = v0/k·(1 − e^(−k·t)) from the release point. It stops when the speed falls to vs: `Duration()` = ln(|v0|/vs)/k (0 when |v0| ≤ vs: no momentum, `Rest` 0), `Rest()` the position there, (|v0| − vs)/k with v0's sign, i.e. vs/k short of `Asymptote()` = v0/k, so the motion ends exactly at `Rest` with no creep. `At(t)` gives (x, v): (0, v0) for t ≤ 0 ((0, 0) without momentum), closed form (`Expm1`) before the stop, (`Rest`, 0) from it on; `Done(t)`. vs ≤ 0 or NaN: no stop, `Duration` the largest `time.Duration`, `Rest` the asymptote; a stop beyond `time.Duration` is capped with `Rest` still exact.
* **`VelocityTracker`** (`Window`, `EndGap`; zero value reports 0; UI thread only): `Add(t, d)` records a moving event (`PhaseBegan`/`PhaseChanged`, zero deltas allowed: held still), `Reset` for a new gesture. `Velocity()` is the deltas of the samples within `Window` of the latest one, over the time they span; the oldest sample in the window anchors the span and its delta is not counted, so a steady stream d every Δt gives exactly d/Δt and a gesture that speeds up or slows down gives its last window. A sample at or before the latest one's time merges into it; fewer than two samples or a zero span give 0. **End rule:** `End(t)` ignores the end event's delta and returns `Velocity()` when t is at most `EndGap` after the latest sample (Win32's zero-delta `PhaseEnded` 100 ms after the last precise event), 0 when longer (fingers at rest before the lift) or with no samples; fingers that stopped while still reporting show as zero deltas in the window. `DefaultEndGap` is 150 ms (Win32's `gestureTimeout` plus timer slack).
* **`Axis`** (S3.5c; `NewAxis(tl, Params, onChange)`, panics on a nil timeline; `ThemeParams(th)` reads `WheelLineHeight`, `WheelStepDuration` with `EaseOut`, `MomentumDecayRate`, `MomentumStopVelocity`, `VelocityWindow`, `DefaultEndGap`, `RubberBandFraction` and `RubberBandSpring`; UI thread only). One `anim.Value` holds the *shown* offset (`Offset`, overscroll included); `Clamped` is it clamped to [0, `Max`], `Overscroll` the difference, `Target`, `Moving`, `Dragging`, `Stepping` (S3.5f: an animated `ScrollTo` or wheel step is running, not a gesture, momentum or spring back). `Event(ev, d)` takes the event's delta on the axis in `shell.ScrollEvent` direction (the offset moves by −d) and reports whether it was taken:
  * a precise gesture (phases) is always taken: the fingers' raw offset moves 1:1 and is shown through `RubberBand` past the edges (c = `RubberBand` × `SetViewport`'s length), so dragging back maps 1:1; a gesture that begins (or continues without a `PhaseBegan`) catches the content where it is through `RubberBandInverse`, and a lone `PhaseEnded` releases at once with no velocity;
  * the release takes the tracker's `End` velocity times the rubber band's slope: past an edge, outwards or no faster than `StopVelocity`, `SpringFrom` the edge; else `Decay` (also back into the range from an overscroll); the change func watches the decay: reaching an edge with speed left springs back from it with that speed, coming to rest past one springs back from rest. Spring-back speeds are capped at 0.9·c·ω₀·e so a critically damped overshoot stays below c;
  * OS momentum (GTK) stops the axis's own decay (started at `PhaseEnded`) and moves the offset by its deltas; at an edge it springs back from there with the tracked speed and ignores the rest of the momentum (also when the release was already springing back);
  * a wheel event scrolls `Delta × LineHeight` with `AnimateTo` over `WheelStep` (stopping a gesture, momentum or spring-back first), notches during a step extend its target, clamped to the range (no overscroll) and not taken when it cannot move; a phase-less precise event scrolls 1:1, clamped.
  * `ScrollTo(x, animated)` (clamped, ends any gesture or momentum), `Stop` (where it is, an overscroll at its edge), `CanScroll(d)` (in the offset's direction), `SetViewport` (re-shows a drag), `SetMax` (negative → 0; a drag is re-shown against the new edge, a spring retargets when its edge moved, a decay or OS momentum left past the new edge springs back, a wheel step's target is clamped, an offset at rest beyond it is clamped at once). Reduce Motion (the timeline's): no rubber band (drags clamp), no momentum, wheel steps and animated `ScrollTo` jump, a running spring-back finishes at the edge. Without a rubber band (c ≤ 0) drags clamp and spring-backs jump.

**`aqua/gallery/golden`: PNGs and the image comparison** (since S3.6b; pure Go, standard library only, no build tags, no thread rule):

* `ReadPNG(path) (*image.NRGBA, error)` and `WritePNG(path, img)` (creates the directory; straight alpha at 8 bits per channel, RGB when every pixel is opaque; the same pixels always give the same bytes). `NRGBA(img)` returns a compact straight-alpha image at the origin (stride 4 × width): the image itself when it already is one, otherwise a converted copy (premultiplied images are un-premultiplied by the color model).
* `Compare(want, got image.Image, opt Options) (Result, *image.NRGBA)`, after pixelmatch (ISC): the squared YIQ distance per pixel against `maxYIQ` (35215) × `Threshold`²; translucent pixels are blended over white and over black and the larger distance counts (pixelmatch blends over white only, which hides a change of alpha alone). A differing pixel on an anti-aliased edge in either image (pixelmatch's `antialiased`/`hasManySiblings`: at most two equal neighbours, a darker and a brighter neighbour, the darkest or brightest of them in a flat area of both images; the image border counts as one equal neighbour) counts `AAWeight`, any other differing pixel 1; the images pass when the weighted count is at most `MaxDiff` (with a 1e-9 margin for float rounding). `DefaultOptions` is `{Threshold: 0.1, AAWeight: 0.1, MaxDiff: 0}`: no differing pixel at all. The goldens use it unchanged: on the host a fresh render matches them exactly (max delta 0); `native.sh` on windows/arm64 shows whether another WARP build needs a larger `MaxDiff`.
* `Result`: `WantSize`, `GotSize`, `SizeMismatch` (a mismatch fails and returns no diff image), `Diff`, `AA`, `Weighted`, `MaxDelta` (the largest distance, on the `Threshold` scale), `Bounds` (of every pixel over the threshold) and `Pass`; `String` is a one-line report. The diff image has want's size: unchanged pixels as a faded grey of want, differing pixels red, differing anti-aliased pixels yellow.

**`aqua/gallery/goldentest`: the shared golden-test flow** (since S4.3e; untagged, imported only by tests, on `golden` and the standard library). What the win32 gallery test and (from S4.3g) the gtk4 one share:

* `Variant{Dark, Scale}` with `Name()` (`gallery-{light,dark}-x{1,2}`), `Variants` (light 1×, dark 1×, light 2×, dark 2×) and `DirFromShell` (`../../aqua/gallery/testdata/golden`, the goldens from a shell package's test directory). Win32 sets the DPI to `96 × Scale`.
* `FromBGRA(w, h, stride, bgra) *image.NRGBA`: premultiplied BGRA rows `stride` bytes apart (D3D11 staging, `gdk_texture_download`) to straight-alpha RGBA, rounded to the nearest value, transparent pixels as transparent black, colour over the alpha clamped; panics on a short buffer.
* `Check{Dir, Options, Update, Out, LogOnly}.Run(t, v, got) golden.Result`: with `Update` it rewrites `<Dir>/<name>.png` and compares nothing (the caller owns the flag: win32 passes its `-update`, the package registers none, so Linux cannot rewrite the goldens through it). Otherwise it logs the `Result`; on a failure it writes `<name>.actual.png` and, when the sizes match, `<name>.diff.png` to `Out`, else `$GOGUI_GOLDEN_OUT`, else `t.TempDir` (remembered in `Out` for the next variant), and reports both paths through `t.Errorf`, or `t.Logf` with `LogOnly` (an uncalibrated tolerance, S4.3g). A missing golden or an unwritable image always fails.
